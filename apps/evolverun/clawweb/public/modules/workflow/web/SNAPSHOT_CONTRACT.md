# Editor / AutoHeal 保存与部署

- 仍使用原来的保存、部署按钮；文件视图默认选择草稿。修改文件或画布不会自动保存。
- 保存同步数据库文档与完整 Pack（工作流 YAML、脚本、资源及文件模式）到 `wf/<id>`。
  保存不会移动当前生效 tag。保存请求发出之后的新本地改动继续保留，需要再次显式保存。
- 部署审阅比较**当前生效 tag**与**已保存的草稿(wf)**，发布 tag 并更新 history/active，
  不改写草稿分支。仅当已保存 DB 与待部署 Git 工作流一致且通过服务端校验时，画布存在未保存改动仍可部署已保存快照；审阅须提示这些改动不会随部署发布，且审阅与确认期间草稿、位置、DB 和 Git 基线必须保持不变。

## DB / Git 差异与可选对比

- Git 工作流 YAML 与数据库草稿不同不妨碍使用当前候选保存，但**目前不得直接部署**：服务端在不一致或无法安全比较时 fail-closed，返回 HTTP 409 `SNAPSHOT_DB_MISMATCH`。TaskGuard 当前优先使用 DB 草稿，若发布不同的 Git 快照会导致运行和发布内容不一致。默认继续使用数据库载入的工作流及当前编辑器候选（包括尚未保存的编辑），不自动以 Git 替换。警告应让用户知道可以查看差异，而非要求先完成合并审阅。
- 对比展示数据库工作流及当前编辑器候选、Git 原始 YAML。用户可显式选择可安全解析、可无损表示且身份匹配的 Git 工作流；在它加载到编辑器并覆盖当前候选**之前**，须提示覆盖后果并取得确认。取消、关闭或失败均保留原候选；选择本身不写 DB 或 Git，后续仍须显式保存。
- Git YAML 无法安全解码、解析、无损转换或验证工作流身份时，不得选择或加载 Git，须说明原因；仍可保留并使用可信 DB / 当前编辑器候选。不可比较也不得被报告为内容一致。其他完整 Pack 资源不能因不能展示而被默认为已审阅或丢弃。
- 普通保存使用当前候选，仍通过统一保存、原始 DB token 和 wf head 租约保护完整 Pack；部署仍需显式审阅并发布**已保存的 wf commit**，不会把未保存编辑或 DB 文档覆盖到发布树。若 DB 与 Git 不一致，先确认并显式保存当前候选使两者一致，再重新审阅部署；保存可能立即影响读取 DB 草稿的运行端。此流程不解除权限、身份、有效性、Pack 完整性、CAS、失败及未知结果保护，也不自动覆盖、降级或重试。
- 对比/覆盖确认须绑定工作流、会话、DB/Git 基线和本地编辑；期间任一相关内容变化、切换会话、过期或超时后旧结果不可应用。保存或部署期间的并发变化仍按现有 CAS、审阅和未知结果协议处理；错误与迟到响应不得清空本地更改、伪造成功或自动重试。

## 现有读取与回执字段

| 场景 | `baseRef` | commit / head 语义 |
| --- | --- | --- |
| 正常草稿 | `origin/wf/<id>` | `baseCommit === draftHead` |
| 生产 current | `refs/tags/deploy/<id>/#N` | 数据库 active tag 的 peeled commit；没有 active history 返回 404 |

`current` 不能用 wf 或旧草稿冒充；生产 tag 丢失不是首次部署的证明。

写请求继续使用 `sourceVersion`、`sourceCommit`、`expectedSavedHead`：
`sourceCommit` 指读取来源，`expectedSavedHead` 指 wf 写入目标 tip。
已有不同 wf 草稿时，禁止以 current 覆盖它。服务器负责 CAS、完整 Pack 保存与授权。
包含分支身份的保存回执必须指向 `wf/<id>`；后置读取也必须确认 wf，而不是旧草稿。

部署保留 `savedCommit`、`snapshotProtocol: saved-tree-v2` 等 wire 字段/协议，
其 saved 语义仍为已保存快照，不是分支名。前端内部 `activeRef` 仅供展示，不加入请求。
失败、未知结果、审阅超时或过期响应不清空本地草稿，不自动重试、恢复、授予权限或降级写入。

ClawWeb 不读取、比较、回退或写入 saved/。草稿只取 wf；没有 wf 时返回未保存/快照不存在，不自动采用其他分支。
