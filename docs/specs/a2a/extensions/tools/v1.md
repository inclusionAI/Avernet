# BCS A2A tool observation extension v1

URI: `https://github.com/inclusionAI/Avernet/blob/dev/docs/specs/a2a/extensions/tools/v1.md`

This Plugin API is implemented by the Harness encoder and consumed by the BCS
outbound A2A adapter. It observes tool execution; it never grants approval.
Declare the URI in AgentCard capabilities.extensions and negotiate through
A2A-Extensions before emitting these records. Unsupported clients can still
receive ordinary Artifact answers when this observation extension is optional.

Carry one record in a structured DataPart of statusUpdate.status.message.
Message metadata at the URI key contains `{"version":"1"}`. Preserve the actual
Task state. Do not set a new Task state just to publish tool progress.

Start record: phase `start`, nonempty toolCallId, nonempty name, args object.
End record: phase `result`, nonempty toolCallId, nonempty name, isError boolean,
and result object with content (an ordered array of typed result parts).
The text result part has type `text` and text string, including empty text.
ToolCallId is stable within a Task. BCS associates it with the authenticated
remote Task and local Bot/Session/Run; IDs do not grant routing authority.
Duplicate equal records are no-ops; conflicting records of one phase are errors.
A result-only recovered record does not fabricate an observed start.

Tool failure does not imply Task failure. Tool approval uses Structured Input
and is never encoded as a successful start or automatically accepted here.
Internal run IDs, routing directives, credentials and database fields must not
be embedded. Breaking field/meaning changes require a new URI version.
