1. 概述与目标

1.1 目标

将 ClawMind（通用 YAML DAG 工作流引擎）和 ClawWeb（工作流 Web 管理平台）拆分为开源版本和内部版本：

  • 开源版本放在 Avernet 仓库的 src/evolverun/taskguard/ 和 src/evolverun/evolvetrace/ 目录下，发布到 GitHub
  • 内部版本放在 OCB 仓库的 src/taskguard-corp/ 和 src/evolvetrace-corp/ 目录下，引用开源版本并添加内部扩展
  • 遵循 Avernet 已有的 community/corp 分离模式，与 engine/backend/bcs 的架构保持一致

1.2 核心原则

  1. 单驻留原则：每份代码只存在于一个位置。共享代码在开源版本中，内部版本通过 import 复用。
  2. 依赖方向：corp → community，community ↛ corp。开源版本不能依赖内部代码。
  3. Profile 切换：通过 DEPLOY_PROFILE=community|corp 环境变量在运行时选择实现。
  4. 渐进迁移：分阶段实施，每个阶段保持可构建、可测试。
关键决策：ClawMind 采用「全部开源 + 内部扩展」策略；ClawWeb 采用「核心功能开源 + 内部特性保留」策略。内部版本通过 Git Submodule 引用开源代码，配置通过 DEPLOY_PROFILE 环境变量区分。

2. 背景分析

2.1 Avernet 现有 community/corp 分离模式

Avernet 的 engine 模块已经建立了一套成熟的 community/corp 分离架构，核心要素如下：

机制说明TaskGuard 映射
命名空间分离 engine.community (开源) + engine.corp (内部) taskguard (开源) + taskguard-corp (内部)
Profile 切换 ENGINE_PROFILE=community|corp|test DEPLOY_PROFILE=community|corp
DI 注入 profile_modules 根据 profile 绑定不同实现 Corp 扩展通过 registerCorpExtensions() 注册
边界测试 AST 级架构测试确保 community 不 import corp ESLint no-restricted-imports 规则 + 架构测试
Git Submodule OCB 通过 ocb-public/ 子模块引入 Avernet 同样通过 ocb-public/ 子模块引用
Docker 合并 Dockerfile 中 COPY community + corp 代码 同样策略，合并两套代码部署

2.2 ClawMind 现状

ClawMind 已经具备良好的模块化基础：

  • PlatformAdapter 抽象层：已有 4 个平台适配器（OpenClaw、MCP、Hermes、TeClaw），通过统一接口屏蔽平台差异
  • openclaw SDK 依赖隔离：全项目仅 1 个文件有运行时 import（openclaw-entry.ts），1 个文件有类型 import（openclaw-types.ts）
  • 大量纯通用逻辑：executors、actions、validation、synthesis、input、context、retry、llm、knowledge、packs 等模块完全不依赖平台特定代码
  • 多入口设计：已有 3 个独立入口（openclaw-entry、mcp-entry、hermes-entry），天然支持多平台

2.3 ClawWeb 现状

ClawWeb 是 React 19 + Express 5 全栈应用：

  • 前端：30+ 页面、60+ 组件，使用 React Router + React Query + zustand
  • 后端：30+ 路由模块、40+ Repository、15+ 服务
  • 不依赖 openclaw SDK：通过共享数据库与 openclaw 交互
  • 页面分类：核心页面（Dashboard、工作流管理、编辑器、知识库、审批）vs 内部页面（DevPlatform、Evolve、InsightCenter、ClawDiagnosis 等）

4.6 扩展注册机制

参考 Avernet engine 的 profile_modules 模式，内部版本通过注册函数注入扩展：

// taskguard-corp/src/index.ts
import { registerTaskguardPlugin } from '@avernet/taskguard';
import { createZdasAdapter } from './db/zdas-adapter.js';
import { createEnterpriseDingtalkNotifier } from './alerts/dingtalk-enterprise.js';
import { createInternalApprovalProvider } from './approval/internal-approval.js';

export interface TaskguardCorpExtensions {
  dbAdapter: ReturnType<typeof createZdasAdapter>;
  notifier: ReturnType<typeof createEnterpriseDingtalkNotifier>;
  approvalProvider: ReturnType<typeof createInternalApprovalProvider>;
}

export function registerTaskguardCorpExtensions(
  api: Parameters<typeof registerTaskguardPlugin>[0]
): TaskguardCorpExtensions {
  // 1. 先注册开源核心
  registerTaskguardPlugin(api);

  // 2. 注入内部扩展
  const dbAdapter = createZdasAdapter();
  const notifier = createEnterpriseDingtalkNotifier();
  const approvalProvider = createInternalApprovalProvider();

  // 3. 覆盖默认实现
  api.registerDbAdapter(dbAdapter);
  api.registerNotifier(notifier);
  api.registerApprovalProvider(approvalProvider);

  return { dbAdapter, notifier, approvalProvider };
}

5.5 后端扩展注入机制

// evolvetrace/server/index.ts (开源版本)
import express from 'express';
import { registerCoreRoutes } from './routes/index.js';

export function createEvolvetraceApp(options?: { extensions?: EvolvetraceExtensions }) {
  const app = express();

  // 注册核心路由
  registerCoreRoutes(app);

  // 注册扩展路由（内部版本提供）
  if (options?.extensions?.registerRoutes) {
    options.extensions.registerRoutes(app);

  return app;
}

export interface EvolvetraceExtensions {
  registerRoutes?: (app: express.Express) => void;

export function registerCorpRoutes(app: Express): void {
  registerDevWorkflowRoutes(app);
  registerEvolveRoutes(app);
  registerDimaRoutes(app);
  // ...
}

7.3 配置加载逻辑

// taskguard/src/config/loader.ts
import { readFileSync } from 'fs';
import { parse as parseYaml } from 'yaml';
import { resolve, dirname } from 'path';

export type DeployProfile = 'community' | 'corp';

export function detectProfile(): DeployProfile {
  const raw = process.env.DEPLOY_PROFILE || process.env.ENGINE_PROFILE || 'community';
  return raw.toLowerCase() === 'corp' ? 'corp' : 'community';
}

export function loadConfig(profile: DeployProfile): AppConfig {
  // 1. 加载开源基础配置
  const baseConfig = parseYaml(
    readFileSync(resolve(__dirname, '../../configs/application.community.yaml'), 'utf8')
  );

  if (profile === 'community') {
    return baseConfig;
  }

  // 2. corp 模式：尝试加载内部覆盖配置
  try {
    const corpConfig = parseYaml(
      readFileSync(resolve(__dirname, '../../configs/application.corp.yaml'), 'utf8')
    );
    return deepMerge(baseConfig, corpConfig);
  } catch {
    console.warn('Corp config not found, using community defaults');
    return baseConfig;
  }
}

9. 迁移计划

9.1 总体阶段

Phase 0: 准备与验证 (1-2 天)

  • 在 Avernet 创建 src/evolverun/taskguard/ 和 src/evolverun/evolvetrace/ 目录结构
  • 在 OCB 创建 src/taskguard-corp/ 和 src/evolvetrace-corp/ 目录结构
  • 编写架构边界测试（ESLint no-restricted-imports 规则）
  • 确保现有 ClawMind/ClawWeb 构建和测试全部通过

Phase 1: TaskGuard 开源迁移 (3-5 天)

  1. 将 ClawMind 全部代码复制到 Avernet/src/evolverun/taskguard/
  2. 重命名包名为 @avernet/taskguard
  3. 移除内部依赖（企业钉钉、ZDAS、内部审批）到 taskguard-corp
  4. 创建 community/ 目录，放置开源默认实现
  5. 创建 taskguard-corp 包，实现内部扩展
  6. 配置 TypeScript path mapping 引用开源代码
  7. 编写 Profile 检测和配置加载逻辑
  8. 确保 DEPLOY_PROFILE=community 可独立构建和运行
  9. 确保 DEPLOY_PROFILE=corp 可加载内部扩展

Phase 2: EvolveTrace 开源迁移 (5-7 天)

  1. 将 ClawWeb 核心代码复制到 Avernet/src/evolverun/evolvetrace/
  2. 重命名包名为 @avernet/evolvetrace
  3. 拆分页面：核心页面保留，内部页面移到 evolvetrace-corp
  4. 实现前端 @evolvetrace-ext 别名机制
  5. 实现后端 EvolvetraceExtensions 扩展接口
  6. 拆分后端路由：核心路由保留，内部路由移到 evolvetrace-corp
  7. 创建 evolvetrace-corp 包，实现内部页面和路由
  8. 确保开源版本可独立构建和运行

Phase 3: 集成验证 (2-3 天)

  1. 端到端测试：开源版本独立部署验证
  2. 端到端测试：内部版本加载开源 + 内部扩展验证
  3. Docker 构建验证
  4. CI/CD 流水线验证
  5. 架构边界测试通过

Phase 4: 清理与文档 (1-2 天)

  1. 移除 ClawMind/ClawWeb 原始仓库中的冗余代码
  2. 更新 README 和贡献指南
  3. 编写开源版本快速开始文档
  4. 编写内部版本部署文档
  5. 添加 GitHub Actions CI 配置

10. 风险与缓解

风险影响缓解措施
代码复制导致维护负担 中 遵循单驻留原则，共享代码只在开源版本中维护。内部版本通过 import 复用，不复制代码。
内部依赖遗漏 高 ESLint no-restricted-imports 规则 + 架构测试 + CI 检查，确保开源版本不引入内部依赖。
ClawWeb 页面拆分不完整 中 逐页面审查依赖，确保拆分后的页面不引用内部 API。使用 Vite alias 在构建时隔离。
构建流程复杂度增加 低 保持与现有 ClawMind 构建流程一致（tshy + esbuild），内部版本仅额外编译扩展代码。
Git Submodule 同步问题 低 与 OCB 现有 submodule 管理方式一致，使用 justfile 命令管理。
配置合并冲突 低 使用 deepMerge 策略，内部配置仅覆盖需要变更的字段。提供配置校验工具。

11.4 架构测试示例

// taskguard/tests/architecture/community-no-corp.test.ts
import { describe, it } from 'node:test';
import assert from 'node:assert';
import { readFileSync } from 'node:fs';
import { globSync } from 'glob';

describe('community does not import corp', () => {
  const communityFiles = globSync('src/**/*.ts', {
    ignore: ['src/**/*.test.ts', 'src/**/__tests__/**']
  });

  for (const file of communityFiles) {
    it(`${file} has no corp imports`, () => {
      const content = readFileSync(file, 'utf8');
      const hasCorpImport = /from\s+['"]@ocb\//.test(content) ||
                            /from\s+['"]@alipay\//.test(content) ||
                            /require\(['"]@ocb\//.test(content) ||
                            /require\(['"]@alipay\//.test(content);
      assert.equal(hasCorpImport, false,
        `${file} should not import internal packages`);
    });
  }
});
