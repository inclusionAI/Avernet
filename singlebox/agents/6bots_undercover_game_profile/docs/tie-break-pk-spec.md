## 已确认的规则

1. 常规投票结束后，两名或多名玩家并列最高正票数时进入平票 PK，不立即淘汰。零有效票不触发 PK，本轮无人出局。
2. 仅 PK 玩家按本轮原有发言顺序各额外发言一次，仍限 25 字，沿用当前轮次的描述约束，可基于公开发言和已公布票面补充描述或回应质疑，禁止直接说出词语或暴露私有信息。PK 指令需要明确允许辩解，避免普通发言“不得点评他人”的规则覆盖 PK 行为。
3. 所有存活玩家参与 PK 投票，包括 PK 玩家；候选出局者仅限本次 PK 玩家，禁止自投和主动弃权。
4. PK 投票只进行一次。唯一最高票玩家出局；再次平票则无人出局，不再追加 PK，未达轮数上限时进入下一轮。
5. 副屏明确显示“PK 发言”“PK 投票”，标记 PK 玩家，分别保留常规投票和 PK 投票结果。
6. PK 属于当前轮，不额外消耗轮数。最后一轮也先完成 PK，再按现有胜负优先级结算：卧底全部出局则平民胜；否则存活人数不超过 2 或达到轮数上限时卧底胜，不开超出上限的新轮。
7. PK 违规票作废，不补投。主动弃权、自投、投给非 PK 玩家或无法识别的票均无效；最终零有效票时无人出局、结束本轮，沿用下一轮或轮数上限结算。常规投票继续允许弃权。

## 原实现与变更边界

## 实施设计

以下描述本次实现的流程与合同。

### 流程与事实状态

- 普通发言 → 常规投票 → 常规计票。仅最高正票数并列时进入 PK 发言 → PK 投票 → PK 计票。
- 每轮最多一次 PK。PK 发言只包含本次 PK 玩家；PK 投票包含所有存活玩家，并单独限制合法投票目标。
- 普通发言、常规票面、PK 发言、PK 票面分别保存。下一轮和终局回顾可读取两组公开发言及两次已公布的投票结果。
- PK 子阶段与运行重试分别标识；不复用 `attempt` 表达 PK，不将进入 PK 呈现为“旧票作废”。阶段内重试仍沿用已有恢复纪律。
- 首次计票进入 PK 时不淘汰、不派遗言、不递增主轮数、不提前结算轮数上限。
- 所有收集/计票末节点只记录事实、输出主持稿并结束；通过既有回灌启动下一运行。PK 不增加人工确认推进步骤。
- PK 唯一最高票导致出局后，沿用当前终局、Bot 遗言、Human 出局及下一轮分支。

### 游戏与副屏契约

- 游戏脚本是规则与结果的权威来源，副屏只消费公开投影并提交玩家动作。候选限制在脚本校验，不能仅依靠隐藏按钮。
- 游戏公开投影需要区分常规与 PK 子阶段，携带 PK 玩家名单，以及分别标识的公开发言历史和已公布票面。
- PK 投票的进度分母是所有存活玩家，PK 发言的分母仅为 PK 玩家。非 PK 的 Human 在 PK 发言阶段观看，进入 PK 投票后可以正常操作。
- PK Human 操作不提供弃权入口；私有投票上下文声明禁止弃权，玩家 Bot 指令同步要求选取合法 PK 候选。事实层仍独立拒绝弃权票。
- 两次投票各自保持收齐后开票；PK 开始可展示已公布的常规票面，不能提前展示其他人的 PK 投票目标。
- PK 玩家保留原座位。副屏显示主轮号与 PK 阶段，不将 PK 显示为下一轮，也不覆盖普通发言历史。
- 公开历史的标识需区分同一轮的普通与 PK 发言。终局结果文件及匹配校验需区分同轮的两次投票，避免串用常规与 PK 的结果。
- 投影新增字段在旧数据缺省时按常规阶段读取；保留既有私有词语上下文和脱敏边界。正在运行的旧协作不作为可热升级的已验证场景。
- 对外变更仅为游戏自有脚本/投影/副屏契约；不修改 BCS Rust Service API、Plugin API 或通用协作协议。

## 验收边界

- 两人、三人及全体存活玩家最高正票数并列均触发一次 PK；零有效票不触发。
- 仅 PK 玩家按原顺序发言；常规发言不被覆盖；非 PK Human 正确处于观看状态。
- 所有存活玩家重新投票，只允许 PK 候选；覆盖主动弃权、自投、非 PK 目标、已出局目标与结构化票面。验证违规票不补投、全票无效无人出局，常规投票仍可弃权。
- PK 唯一最高票淘汰正确玩家；再次平票无人出局且不再追加 PK；下一轮全体存活玩家恢复常规发言和投票范围。
- 最后一轮先完成 PK；抓完卧底优先判平民胜；否则按原上限判卧底胜。
- 覆盖 PK 后 Bot 遗言、Human 出局、终局公布、阶段重试与重复唤醒，不重复开 PK 或重复淘汰。
- 副屏区分两次票面及两组发言，阶段和进度正确，私有词语不进入公开投影，未开票结果不提前展示。
- 运行 profile 的 Python 单元测试及副屏 `npm run verify`；真实会话验证自动回灌、PK Human 操作和最终结算。不能执行的验证必须明确记录。
