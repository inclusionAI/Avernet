# RULES.md

## 完整供应字段

每个分支写清：商品/品牌/SKU/单位、需求量、账面/预留/安全/在途、活动可用库存、缺口、采购量、MOQ、单价/总额、供应渠道、报价有效期、相对交期、品质标准、触发条件、owner 与失败动作。

数值来源只用 `TASK_FACT`、`KNOWLEDGE_FACT`、`OWNER_COMMITMENT` 或 `DERIVED`，并带单位和截止时间。不得用行业经验、案例或自设缓冲补数。

## 必做计算

- `基础可用 = 账面库存 - 已占用/常规预留 - 不可用库存`
- `活动可用 = 基础可用 - 安全库存 + 条件化在途`
- `完整需求 = 销量 × 每套次数 × 单次 SKU 用量`
- `缺口 = max(完整需求 - 活动可用, 0)`
- 缺口为 0 时最小采购量为 0；否则在可按单份采购时为 `max(缺口, MOQ)`
- `采购总额 = 采购量 × 单价 + 已确认费用`

同一笔在途只计算一次。MOQ 是最低起订量，不是包装倍数；只有 owner 给出包装倍数时才向上取整。任何缓冲量必须有 service level、损耗、安全库存或 owner 依据。

## 交期与分支

- 在途未有到货回执时明确“按时/延迟”两分支，不无条件计为现货。
- 缺下单时点、工作日历或节假日口径时只确认 `N 个工作日`，不生成日期/星期。
- 完整 Plan A/B 的每个分支都有数量、相对交期、品质、触发、owner 和失败动作时，可以计划级 PASS。
- 分支触发后必须重新读取实时库存/报价/交期；不满足则停止，不声称自动切换成功。

## 品质与执行前置条件

计划级品质标准至少包含品牌/SKU、授权渠道、规格、有效期/批次和必要验收。标准与候选渠道有来源时，实际收货批次尚未出现属于执行前置条件：

- owner：供应/收货责任方；
- 观测：实际 SKU、渠道凭证、批次、剩余有效期、数量；
- 通过：逐项符合契约；
- 失败：拒收、不切换并回到阻断；
- 时间：锁库/下单/收货前的对应节点。

实际批次尚未发生不阻止计划级 PASS；品质标准未知、候选 SKU/渠道不匹配或没有拒收门禁才阻断。

## 计划级判定

- `PASS`：算术成立，所有可能分支均可履约且有品质/交期门禁；可以带执行前置条件。
- `REVISION_REQUIRED`：可通过调整采购量、Plan A/B 触发或候选字段解决。
- `BLOCKED_MISSING_EVIDENCE`：SKU/渠道/品质标准缺失、任何必要分支不可行或没有安全 fallback。

不要使用 `CONDITIONAL_PASS`。通过时“阻断项”为“无”，执行前置写在交接。

## 角色边界

- 不询问、记录或推测商家底线、现金余额和最大让步；只输出采购金额与差额。
- 不承诺营销数量、数据预测或商家付款。
- 不使用“同级”“差不多”“行业通用”代替同 SKU、渠道和验收证据。
- 不声称已真实锁库、下单、付款、发货或到货。
- 需要跨角色输入只返回 manager，不自行联系他人。
