# 威胁模型：谁是卧底的跨局和跨玩家隔离

适用于 [#2609](https://github.com/inclusionAI/Avernet/issues/2609) 的多人设计。方案见 [RFC](rfc.md)，实测边界见 [基线验证](validation.md)。

## 参与者及其信任边界

以目标席位 X 的词、阵营和未公布动作作为保护对象，分开检查以下参与者，并遍历全部席位。复用同一认证 actor 开下一局时，按局重新判定 X。

| 角色 | 权限和约束 |
| --- | --- |
| Human X | 能操作自己的浏览器、直接调用自己有权用的 API、修改公开参数或保留旧副屏。只能取得自己当局的词和待提交动作 |
| 其他 Human | 包括同局玩家、已出局玩家、同群但本局未参赛的人和旧局玩家。可知公开席位及规则。成员身份或上一局座位不授予目标词条或操作权限 |
| Bot X、其他玩家 Bot | 以 worker 身份收各自私有投递和任务。可通过 SDK、工具或内容尝试读取数据。其他 Bot 的词及主持人状态不在权限内 |
| 主持人 | 可信的裁判执行者，持有完整词表、角色和当前局比分。词条编排、计票、失效和揭晓均由它控制 |
| 服务端和宿主 | 认证身份、ACL、状态目录及隔离边界的信任根。验收使用真实认证的普通参与者，管理员访问、宿主失陷、玩家主动串通或自行转发已获知信息不在承诺内 |

秘密包括各席位的完整词语、胜负未决时的阵营和主持人内部状态。对局正式揭晓发布的词和阵营变为**该局**公开数据。已公布的发言、合法候选、规则、投票完成状态及最终计票结果可公开。未公布的票面在参与者视图中受保护。默认 Full 和现有授权节点详情 API 对票面的限制见下表，词语不得借这些渠道暴露。

## 可见性矩阵

下表写的是多人模式的目标可见性。对于目标 Human 的数据，Human X 列适用，Bot X 列记为不适用。目标 Bot 的数据反过来。对每条访问路径分别比较所有者、同局其他角色和本局未参赛成员，失败响应和元数据也要检查。

| 信道 | Human X | 其他 Human | Bot X | 其他 Bot | 主持人 | 基线暴露点与多人约束 |
| --- | --- | --- | --- | --- | --- | --- |
| 群聊、会话消息和主消息流 | 公开 | 公开 | 仅已有投影 | 仅已有投影 | 可发公开内容 | 旧流程把 Human 当唯一收件人，群员增多即失去私密性。群广播只承载规则、合法发言和已经授权发布的结果 |
| 公开 panel 参数、URL 和渲染事件 | 公开 | 公开 | 无参与者副屏 | 无参与者副屏 | 生成公开投影 | 旧 viewer 字段是公开提示。篡改它或座位映射不能改变身份。参数、交互回调、URL 和浏览器持久存储不携带秘密 |
| 私有 Group Context，以及 get/list | 自己当局的词条 | 拒绝，列表不枚举 X | 不适用 | 拒绝 | 写入按既有 ACL 授权 | 明确 session scope 及单一读取 actor。即使知道词条名也要校验。旧局的历史授权不传到新局 |
| Bot 私有投递 | 无 | 无 | 仅自己的词 | 无 | 按席位派发 | 逐 Bot 验证投递、事件与 SDK 访问。不得用群广播或可被其他方读取的通用节点字段补发 |
| 工作流定义、节点 instruction、运行 graph/detail | 公开数据和本人动作元数据 | 公开数据和自己的动作 | 公开任务元数据和自己私有投递 | 公开任务元数据和各自私有投递 | 生成工作流并处理内部状态 | 旧 panel 契约允许把词放在 HumanInput 区块。多人定义和可查询节点字段不保存明文词，避免通过并行节点或运行详情绕过 ACL |
| pending HumanInput、respond 和重试 | 列出和提交本人待处理节点 | 不列出 X，拒绝提交 X | 无 Human 接口权限 | 无 Human 接口权限 | 观察进度并推进 | 现有前端节点无绑定，同会话在场者都能提交。多人节点必须核验会话、绑定、待处理状态及正确运行，旧操作不能改写新局 |

| 未公布票面与参与者视图 | 确认自己动作 | X 仅显示「已投票」 | 自己提交值 | 自己提交值 | 收取计票所需的票 | 当前运行的指定 `tally` 完成且发布结果后才展示。默认 Full 和有权读取节点详情的直接 API 仍可能显示未公布票面，记录为已知限制 |
| 工具调用、事件转发、推理及调试日志 | 无 X 明文词 | 无 X 明文词 | 自己的私有输入 | 各自私有输入 | 按受限渠道操作 | Group Context 写参、私有读词返回和主持人状态可能通过事件转发泄露。检查参数、返回值、错误信息及工具回执，公开事件仅记录非秘密标识 |
| 主持人状态文件、工作区、备份 | 无 | 无 | 不可读取主持人文件 | 不可读取主持人文件 | 读写当局状态 | 按会话隔离路径和访问权限，状态文件不得挂入玩家工作区、公用附件或复盘包。关闭失败不改变私密级别 |

## 可复现的判定

1. 为每局、每个座位生成唯一的合成标记，词语、未公布角色、票和无害的公开发言各自使用不同标记。对矩阵逐角色调用原始接口并检查响应，再检查浏览器网络面板、DOM、交互事件和缓存。对子字段、错误响应、派生回放及工作区同样断言，不只检查 UI 是否隐藏。
2. 在同一协作群依次跑 J1（A 座 1、B 座 2）和 J2（C 座 1、A 座 2）。用同名或等价座位定位测试权限判断，核对现任、本局缺席和历史拥有者。故意延迟 J1 的结果到 J2 加载后返回，再分别验证保留旧标签页和切换浏览器认证身份。
3. 用 B 或未绑定玩家身份请求 A 的待提交动作，并在当局与跨局分别尝试提交。验证拒绝或空结果符合契约，并确认真正所有者仍可以提交且计数只增加一次。对已结束、重复和旧轮请求检查服务端状态，避免只靠 HTTP 状态判断。
4. 在合成测试夹具中向公开 panel 参数注入一个本应私有的标记，要求测试定位到对应信道、身份和局。移除注入后同一测试应通过。未公布票面按参与者视图断言，Full 与直接详情 API 的现有边界单独记录。
