# 多人谁是卧底：威胁模型

> 关联：issue #2609；RFC 见同目录 `rfc.md`。
> 基线：`oss-camp2026` @ `86252c1e9`。证据类型统一标注：〔基线实测〕旧代码 singlebox 实测；〔集成实测〕本 RFC 集成分支 singlebox 实测（2 人类 + 3 Bot 对局）；〔单测〕自动化测试；〔源码〕读代码推断、未实测。复现见 RFC 附录 A 与 `research.md`。

## 1. 要保护什么

| 资产 | 谁可以知道 | 何时公开 |
| --- | --- | --- |
| 某个人类的词 | 本人；同阵营的人碰巧同词不算泄露 | 终局复盘 |
| 某个人类的身份（是否卧底） | 无人（本局不告知身份） | 终局复盘 |
| Bot 玩家的词 | 该 Bot | 终局复盘 |
| 某人本轮的票面 | 本人 | 该轮 `tally` 完成后 |
| 发言、遗言（遮蔽后） | 全体 | 产生即公开 |

主持人 Bot 的状态文件和 GC owner 权限天然能读到所有词。本设计不把主持人当作攻击者，但把**主持人模型的输出**当作不可信信道：模型会复述、会在 thinking 里推理，这些内容会被投递出去。

## 2. 攻击者

- **A1 诚实但好奇的玩家**：只看浏览器里能看到的东西——页面、DevTools 网络面板、WebSocket 帧、会话历史。
- **A2 主动的已认证玩家**：会自己构造带认证的请求（GET/POST），会 rerun 失败的运行，会在聊天里诱导 Bot 或主持人泄词。
- **A3 同一会话里的非玩家人类**：知道 session_id 的已认证用户（见 T9）。

不考虑：部署方/运维、能读服务器磁盘或数据库的人、浏览器扩展、拿到别人登录态的人。

## 4. 威胁清单

| 编号 | 威胁 | 攻击者 | 处置 | 状态 |
| --- | --- | --- | --- | --- |
| T1 | 主持人命令输出（`init` 的 `human_word`、`my-word`）经 tool_result 外发给其他人类 | A1 | 多人模式下发词在脚本子进程内完成，命令只输出公开字段；`my-word` 返回错误码 | 已处置〔单测〕〔集成实测〕 |
| T2 | 主持人在群聊时间线里"把词念给人类"（单人类局的现行做法） | A1 | 多人模式删除这一步，词只经 GC | 已处置 |
| T3 | 词写进 HumanInput instruction / 私有 UI 上下文，经运行定义或节点详情被他人读到 | A2 | 多人模式 instruction 不含词；副屏凭 `wordRefs` 自取 | 已处置〔单测〕 |
| T4 | GC 条目 `visible_to` 写错或留空（**空 = 所有人可见**，bcs-cli 默认值就是空） | — | 先以 owner-only 建全，全部成功后再逐条授权；测试断言每条 `visible_to` 恰为本人 | 已处置〔单测〕 |
| T5 | 抢注：别人抢先用你的条目名建条目，诱导你读到假词 | A2 | 条目名用密码学随机数生成，建好并授权之后才公开名字 | 已处置 |
| T6 | 冒用他人的 HumanInput：提交别人的节点，或让普通聊天被路由进别人的节点 | A2 | BCS 按 assignee 校验提交者；聊天只路由进本人或未绑定节点 | 已处置（BCS PR） |
| T7 | 副屏身份被公开参数欺骗（旧参数 `currentViewerActorId`） | A2 | 多人模式删除该参数；身份来自认证接口，并与座位表交叉校验。UI 身份只决定显示，不作为授权依据 | 已处置〔单测〕 |
| T8 | rerun 旧快照：任何在场人类都可重跑失败运行，旧结果被当成当前结果写回 | A2 | 脚本登记真实 run_id，给出旧 run_id 时返回 `STALE_RUN`〔单测〕。节点拿不到真实 run_id，所以 collect/tally 不带它；多人局改为强制 round/stage/attempt，并要求本阶段已登记 run〔单测，用实际下发的指令〕。`--retry` 后旧 attempt 的迟到提交会被拒；在 BCS 侧直接 rerun 同一快照得到的 run 与已登记 run 范围相同，脚本无法区分 | **部分处置**，待 RFC Q6 |
| T9 | 非玩家人类凭 session_id 自助加入会话，默认拿到 Full 视图 | A3 | 会话时间线会出现"用户 X 已加入"，可察觉；session_id 不可猜测。副屏对未入座身份不取词、不给操作 | 假设 + 待维护者确认（RFC 开放问题 Q4） |
| T10 | 有人加入/离开会话时，系统消息灌入主持人和所有 Bot 的会话文件，打断进行中的激活；打断玩家 Bot 时整轮运行失败〔基线实测〕 | A2（可重复制造） | 游戏座位表在开局时冻结；BCS 会话成员仍可变化，中断风险保留。文档提示"先全员加入再说开始" | 未处置，可用性风险，RFC Q5 |
| T11 | 错误路径把外部命令原文（含词）带进命令输出 | — | 错误一律输出稳定错误码，原文只落盘 | 已处置〔单测〕 |
| T12 | 遗言链路：主持人用 `mask --text '<原话>'` 处理遗言，原话作为 tool args 持久化进主持人的 Full 历史（`tool_result.metadata.arguments`），被二次外发 | A1 | 恢复基线的 mask 流程，二次外发限制保留：原话确实多出一份可长期读取的主持人工具历史。`eulogy` 子进程方案已实现，但取不到真实回执，未接入。多人局 Bot 非终局遗言已实测：另一名人类的 Full 历史里，主持人 `mask` 调用的 `metadata.arguments` 含遗言原文〔集成实测，第 3 局〕；单人局未实测 | **未处置**，待 RFC Q7 |
| T13 | 存在性探测：他人条目 `get` 返回 403，不存在的条目返回 `200+[]` | A2 | 条目名本来就公开，不构成新信息 | 接受 |
| T14 | 投票阶段的"已投票"进度泄露投票先后 | A1 | 只显示是否已投，不显示目标 | 接受（与单人类一致） |
| T15 | 遮蔽反馈侧信道：玩家在自己的发言里塞一串候选词（如「牛奶、豆浆、可乐」），汇总稿里被遮蔽的位置即是对家词 | A2 | 遮蔽机制与公开词库是既有行为，单人类局同样存在；只能确认对家词，不能单凭此确定任意玩家身份 | 接受，记录为已知限制 L8 |

## 5. 已知限制（不得写成"服务端隔离"）

- **L1 票面**：`tally` 完成前，直接调节点详情或运行视图可以读到他人票面；**默认 Full 视图下，宿主聊天时间线与会话历史也会在计票前显示 Bot 的票和人类的结构化票面**〔集成实测〕。副屏只能管自己的展示，宿主时间线不在本 issue 可改范围；按维护者口径，计票前保密依赖参与者切到 Participant 视图。目前只有局后一次 Participant 历史查询（research R11）：其中没有他人的独立原始投票消息；计票前的实时消息、视图切换时机、节点详情都未验证，不能据此认定计票前保密成立。维护者已确认本阶段不引入 `sealed_output`，副屏只做展示门控：`tally` 完成前不请求、不展示他人投票节点详情。
- **L2 原始发言**：Bot 或人类的原始发言在主持人遮蔽之前，已经进入下游 `[Upstream Outputs]`、pending 的 `upstream_artifacts`、节点详情和 Full 历史。单人类局里就存在，属于玩家自己泄词或被诱导泄词，profile 层无法事前拦截。
- **L3 遗言激活**：出局 Bot 的遗言激活以 task 事件投递，directed 受众在 Full 视图下放行，原文和 thinking 会先到前端。profile 层只能用措辞约束降低概率。
- **L4 主持人权限**：主持人仍有 GC owner 权限和状态文件读权限。"词盲"只指正常流程不把词交给模型，不是权限隔离。
- **L5 GC 读权限不随离场撤销**：离场的人类仍能读自己的词（本来就该知道）。
- **L6 视图切换**：Full → Participant 切换后，已准入的 WebSocket 操作不会立即截断。
- **L7 Bot 自己的词在 Bot 节点 instruction 中**：节点详情不返回 instruction，但原始 transcript 回退、控制该 Bot 的视角能否读到未验证。机制早于本 RFC，单人类局同样存在。
- **L8 遮蔽反馈侧信道**：见 T15。
