# Draft 之后的编辑、review 与群应用 Roadmap

当前协议见 [spec](./spec.md)。Draft、公开固定版读取、逻辑预览已实现；本文件只规划未完成部分，不再使用 readToken、签名密钥或消息内完整 YAML 作为新能力基础。

## 1. 已实现与仍待完成的边界

| 能力 | 当前状态 |
| --- | --- |
| Draft 存储、CAS、固定版本校验、下载和撤销 | 已实现；管理仍要求 owner Bot，固定版公开读取 |
| 副屏只读图/源码/复制 | 已实现；schema 1 兼容，新卡片用 schema 2 三字段 |
| 副屏“发起协作” | 已接 frontend 主屏既有建群浮层，用户选择自己的 Bot 和协作者 |
| 建群时修改 YAML | 已支持主屏本地副本编辑，提交当前已校验文本；不回写 Draft |
| 专用助手显式 preview 交付 | 本地 Skill 已修改，独立提交/刷新与真实模型验证待完成 |
| 副屏编辑并保存新 revision / Bot review | 未实现；需要明确用户和跨 Bot 写入边界 |
| 修改已有群并 apply | 未实现，独立设计群基线和提交契约 |
| frontend-nextgen 接入 / 聊天建群 | 见 [建群 roadmap](../2026-10-22-collaboration-draft-group-launch/roadmap.md)，不计为本轮已完成 |

## 2. CLI 展示输出分离（待决定与实现）

先发布专用 Skill：create/update 只消费保存与校验结果，显式 preview 获取卡片。当前 CLI 仍在 create/update 返回 reference/message，不改默认行为、不新增 --panel。

后续若调整 CLI，可让 create/update 停止取引用及生成展示字段，preview 继续承担显式卡片生成。实施前检查实际消费者和发布顺序；旧 CLI 额外输出的 message 由新 Skill 忽略，新 CLI 也应能服务同一套 Skill。未升级且依赖 create/update.message 的专用流程要先迁移，不能把默认输出变更当作无兼容影响。

这是 CLI 输出职责调整，不需要改变 Draft 存储、公开读取或旧 CLI 所需的 HTTP reference 兼容字段。是否移除该 HTTP 占位字段由实际旧 CLI 消费者退场决定，不以此 roadmap 自动授权移除。

## 3. 副屏编辑与 Bot review

```text
打开固定版本 A
  → 用户建立本地编辑副本并修改 YAML
  → 以明确 expectedRevision 保存版本 B
  → 发送固定 B 与 review 诉求给目标 Bot
  → Bot 下载 B、返回意见；获准修改时保存新版 C
  → 用户主动查看或采用新版本
```

### R2-01：编辑与保存

保留原文、注释和空白，以 YAML 为权威，不由图反写。记录基线 revision、本地文本身份和保存状态；旧消息及旧 revision 不变。CAS 冲突时保留编辑内容，不能自动提高基线或最后写入胜出。保存期间新增输入不能被旧响应清除。

目前浏览器用户没有通用 Draft 写接口；公开读取不赋予保存权限。先基于实际用户需求定义 BCS 内的写入归属，不能默认给共享助手其他用户的凭据或增加未经要求的跨服务委托。

### R2-02：实时校验

未保存文本走现有文本校验，已保存内容走固定版校验；共享同一服务端规则。编辑立即使旧结论失效，防抖和请求取消之外还核对文本身份。可保留上一有效图但明确标识；网络失败不等于 YAML 无效，不丢弃文本。

### R2-03：明确发送 review

发送已持久化的 `{schemaVersion, draftId, revision}` 和诉求，不带读取凭据或完整 YAML。目标 Bot 可下载公开固定版本；读取不授予修改原 Draft 的权限。需要跨 Bot 修改时另行定义写授权或明确复制为目标 Bot 自有 Draft。

来源聊天和目标 Bot 必须明确；切换会话不误投。消息请求、持久化确认、Bot 排队和完成 review 分开呈现。保存成功但发送失败时复用同版，不为重发追加 revision。现有 onAction 不能代替持久化/幂等确认契约。

### R2-04：并发与采用新版本

保留未提交文本；Bot 和用户同时保存用 CAS 拒绝过期基线。新版本仅提示，不覆盖脏副本或自动换基线。固定 n+1 核对只证明内容已保存，不修改作者或归因。分支树、CRDT、自动合并不作为默认需求。

### R2-05：关闭与恢复

未保存改动需要关闭/导航保护，保存失败或结果未知时保留。已保存未 review 与未保存分别提示；不要将已持久化内容误报为丢失。现有只读 Tab 随卡片卸载关闭，不能直接套用到编辑器；宿主关闭拦截和状态托管须先定义。浏览器崩溃恢复、跨设备未保存文本不默认承诺。

验收覆盖 R2-AC-01～09：旧版不变、CAS、乱序校验、无效版本诊断、目标/来源隔离、保存与发送分别失败、并发和迟到响应、关闭保护、新版主动采用。普通 Bot 不被注入专用 review 工作流。

## 4. 现有协作群编辑与 apply

沿用 RG-01～04：

1. 从 BCS 权威群定义和群基线建立编辑副本；来源只作追溯，不授予群写权。当前 Draft 没有 origin/group_revision 字段，不预先新增占位。
2. Draft CAS 与群配置 CAS 分开；应用指定固定 Draft revision 和预期群基线，不能把 Draft revision 当群版本。
3. 应用时复核群权限、当前 YAML、绑定与运行能力，原子保存群配置和来源记录；不产生半更新。
4. 已运行 Run 保持原 snapshot，后续 Run 使用生效定义；应用不等于启动。结果未知/重试的幂等与查询契约独立设计。

此能力与“用 Draft 初始文本新建群”不同，不能因为已有主屏建群浮层就标记完成。覆盖无权/冲突/绑定不兼容/无效定义/未知结果/运行中 snapshot 不变等场景后再交付。

## 5. 按需求评估的增强

- 自动保存、本机未保存内容恢复：定义频率、生命周期和隔离，不默认发送 review 或应用到群。
- Diff/合并、列表/搜索、模板复用：有真实需求再定义入口和可见性；公开固定版读取不自动开放枚举、写入或群操作。
- 更多帮助 Bot 和主题转交：每个角色使用自己的专用 Skill，沿用现有分发，不把帮助流程扩散给所有 Bot。
- 私聊真实验收和各宿主部署接入：按用户恢复验收安排推进，不添加资源加载检查。

本 roadmap 不预建通用文档、授权或任务操作平台，不改变现有读取无需凭据的契约。
