# ClawInsight 监控自愈访问权限

状态：已实现，待双仓库合入及部署验收。更新：2026-09-16。

## 范围与用户操作

仅限制效果中心内的 **Agent 监控自愈**，不限制整个 ClawInsight、Agent 治理或改变其他模块的既有权限。

已有超级管理员进入 ClawWeb「其他功能 → 权限管理」，选择新增角色 **ClawInsight 管理员**，填写目标用户工号或账号并保存；撤销时删除该角色成员。复用现有权限页面、`/api/admin-users` API 和 `clawweb_admin_users` 表，角色值为 `claw_insight_admin`。无需直接填写数据库、创建表或新增管理接口。获得此角色不等于获得权限管理权限。

角色独立判断：普通管理员、超级管理员、ClawEvolve 管理员及 Dev Local 均不自动获得监控权限；需要显式加入新角色。可选配置 `auth.claw_insight_admins` 沿用已有角色的启动初始化与配置回退机制，日常增删使用页面。数据库正常时以动态角色列表为准；数据库不可用时沿用现有配置回退语义。

## 两仓库修改与接口契约

### OCB

- access-admin 的角色类型、数据库读取集合、配置初始化、API 角色标签和管理页面增加新角色。
- archive 的 admin-auth 在每次请求读取角色后设置 `req.isClawInsightAdmin`，不继承其他管理员角色。
- `/api/auth/me` 所有成功路径返回布尔字段 `isClawInsightAdmin`，缺省为 false。
- 新字段始终来自当前请求，不进入身份缓存；IAM、Buservice、ASF 缓存命中和 Dev Local 路径行为一致。数据库增删角色后，下一次请求反映新权限，不等待身份缓存过期。

### Avernet

- shared 的配置、公共角色仓库、中间件、Express/Web 类型补齐同一角色；公共宿主 `/api/auth/me` 返回同一字段。
- 客户端 `useClientUser` 缺省为 false，不从其他管理员字段推导。
- 无权限不渲染「Agent 监控自愈」导航；直接打开 `?module=monitoring` 时展示 Agent 治理，不挂载监控组件。效果中心其余入口保持原逻辑。
- 监控 runtime 装配后，`/api/insight/v1/monitoring/*` 浏览器读取接口对字段 false 或缺失均返回 403，包含 Bot 列表、状态和诊断列表；有角色按原业务逻辑响应。
- `/api/insight/v1/internal/monitoring/*` 保持原内部上报协议，不受本次用户角色限制，不新增 token 校验；依赖既有部署侧网络隔离。

本改动沿用已有宿主身份识别和可信网关边界，不引入新的身份认证方式。已打开页面不主动推送撤权通知：后续服务端请求按当前权限拒绝，界面在刷新或重新获取身份后隐藏。

## 兼容性与交付

保留 dev 上最新的监控异步接口、自动发现、无 Bot 配置启动与 schema 初始化逻辑；不重放旧监控分支历史。新增响应字段为增量契约，旧服务不返回字段时新前端默认不展示监控。

两仓库应作为配套变更交付：先将 Avernet 合入 dev，等待内部 Avernet Mirror 的 dev 同步，再提交或重新验证 OCB（其现有 CI 固定使用 Mirror dev 作为编译依赖），重新构建 shared、clawinsight、access-admin 和应用，避免旧 dist。OCB 公共源码具体版本沿用既有同步/构建流程，本功能不改子模块指针。无需数据库迁移。

不要单独部署任意一侧并视为完整权限上线；回滚也须两侧协调，旧版监控接口无本次角色保护。

## 验收

1. 超级管理员可在原权限页面新增和删除该角色；普通用户不能管理角色列表。
2. 仅此角色的用户可见并访问监控，且不会因此获得其他管理员权限。
3. 无此角色保留效果中心和 Agent 治理，隐藏监控入口；监控深链接不挂载组件，三个浏览器读取 API 均拒绝。
4. 同一身份缓存下授权和撤权，下次 `/me` 与读取 API 一致；覆盖 IAM、Buservice、ASF 和 Dev Local。
5. 公共宿主与 OCB 识别同一角色；既有监控内部上报与无配置启动不受影响。

仓库内测试覆盖登录响应/缓存、公共中间件、监控 HTTP 和界面导航；跨仓库联合验证额外覆盖现有权限 API 与共享数据库角色。真实 SSO、生产数据库驱动及部署侧网关隔离仍需部署环境验收。
