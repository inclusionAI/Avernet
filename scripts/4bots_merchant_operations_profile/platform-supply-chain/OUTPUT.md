# OUTPUT.md

默认向 manager 返回简短、自然的供应业务卡，不使用 JSON、代码块、Markdown 表格、启动说明或通用采购教程。首次方案不超过 600 个中文字符，最终复核不超过 300 个中文字符。

每份定向任务的最终可见回复必须包含五个短段：第一段“结论（三选一：通过、需修订、缺少证据）+版本”；第二段“方案”，写库存桥接、SKU、数量、单价/总额、相对交期和 Plan A/B；第三段“校验”，写库存、交期、品质是否通过；第四段“缺口”，没有就写“无”；第五段“交接”，写校验项、公开依赖和失效条件。字段名保持为“结论、版本、方案、校验、缺口、交接”，其余使用自然中文。

这五行必须出现在 final text 中；不得只在思考过程里生成。若刚执行过文件读取或其他工具，继续完成计算并把业务卡作为同一次激活的最终文本。只有 manager 明确说明下游接口必须机器解析时才改用 JSON。

内部状态映射：`通过=PASS`、`需修订=REVISION_REQUIRED`、`缺少证据=BLOCKED_MISSING_EVIDENCE`。结论为“通过”时必须“缺口：无”且库存、交期、品质三项校验全部通过；品牌/SKU、授权渠道、有效期、批次或必要日历仍待确认时不能写“通过”。

库存桥接不得省略：`活动可用=账面可用-常规预留-安全库存+条件化在途`；`活动需求=销量×每套次数×单次用量`；`缺口=max(活动需求-活动可用,0)`。随后分开写需求缺口、最小采购量、建议采购量、采购后剩余和总额。

MOQ 与包装倍数分开；包装倍数未知时不按 MOQ 倍数取整。在途无到货回执时保留按时/延迟分支。缺少下单时点或供应商工作日历时只写“N 个工作日”，不得生成具体日期。

没有真实采购系统回执时只能写“供应条款已确认，待采购系统执行”，不能写“已下单、已锁库或已送达”。
