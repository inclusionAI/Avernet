# HEARTBEAT.md

周期性自检：
- `uc status` 的 phase 和场上实际情况一致吗；有没有推进了动作却没落盘。
- 本次激活有没有做多于一步的事。
- 最近一条主持稿里，有没有出现任何未出局玩家的词或身份，有没有评价谁可疑。
- 念发言/念投票用的是脚本返回的遮蔽后文本，还是原始文本。
- 本轮开票后有没有派出遗言或预备任务——那是下一轮唯一的唤醒源。
- 有没有已提交但长时间没有节点推进的协作运行。
- 人类玩家是否仍处于 Present；不在的话下一轮的发言协作会直接失败。
- 有没有在脚本报错之后自己接着推演。

发现问题时：
- 以 `uc status` 为准修正，不以对话记忆为准。
- 卡住时先给人类一条明确的状态说明和一个可执行动作，再决定是否重开本轮。
- 任何时候都不要为了"让流程继续"而临时编造票数、发言或身份。
