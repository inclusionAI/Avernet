# OUTPUT.md

默认向 manager 返回简短、自然的业务卡，不使用 JSON、代码块、Markdown 表格或启动说明。首次方案不超过 600 个中文字符，最终确认不超过 300 个中文字符；默认只给一个候选，manager 明确要求比较时最多两个。

每份定向任务的最终可见回复必须包含五个短段：第一段“结论（三选一：通过、需修订、缺少证据）+版本”；第二段“方案”，写券种、对象、价格与分担、最大核销量、有效期和结算；第三段“校验”，写算术与授权是否通过；第四段“缺口”，没有就写“无”；第五段“交接”，写校验项、公开依赖和失效条件。字段名保持为“结论、版本、方案、校验、缺口、交接”，其余使用自然中文。

这五行必须出现在 final text 中；不得只在思考过程里生成。若刚执行过文件读取或其他工具，继续完成计算并把业务卡作为同一次激活的最终文本。只有 manager 明确说明下游接口必须机器解析时才改用 JSON。

内部状态映射：`通过=PASS`、`需修订=REVISION_REQUIRED`、`缺少证据=BLOCKED_MISSING_EVIDENCE`。结论为“通过”时必须同时满足“缺口：无”“算术通过”“授权通过”，且不存在待数据/供应依赖或待 owner 字段。

每个券种至少写清：门市价、用户实付、优惠额、单次平台补贴、单次商家承担、单次商家结算、最大核销量、平台补贴总额、有效期、叠加与核销结算规则。数字后用括号短注来源，例如“平台政策”“manager 任务”“本轮推导”；不展开来源表。

最终授权卡必须给出“授权包络”：平台已确认的最大核销量、单次优惠和补贴、总补贴上限、适用对象、有效期与失效条件。manager 在该包络内下调核销量或释放节奏，不改变单价、补贴、对象、规则和总上限时，属于商家侧选择，不要求营销再次确认；提高数量或改变任一授权条件才使本结论失效。

不得输出“符合商家毛利/现金底线”或计算其余量。不得声称平台已经配置或上线；使用“营销条款已确认，待执行系统落地”。
