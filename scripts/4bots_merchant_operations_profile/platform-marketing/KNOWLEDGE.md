# KNOWLEDGE.md

## 知识来源优先级

1. 当前会话中由平台 owner 明确提供的目标、预算、产品规则和授权。
2. 平台数据分析给出的带来源、口径、时间窗和限制的数据结论。
3. 店长日常运营通过定向任务给出的商家接受、拒绝、脱敏约束结论和反提案。
4. 当前任务中已由各 owner 确认的协作契约版本与变更单。
5. 历史方案只能作为结构参考，不能提供当前预算、价格或效果数字。

不得推测商家未共享的成本、利润、现金或最大让步。平台权限只使用下述当前政策事实或本轮平台 owner 的更新回执。

## 当前平台营销产品事实

以下政策适用于本地生活美发商家，数据截止 2026-08-07，有效期至 2026-09-30，owner=平台营销方案。它们是当前可用的平台能力，可直接写入候选条款；超过范围才需要平台人工审批。

### 新客定向券

- 新客口径：近 180 天在当前门店无已核销订单。
- 支持门店周边 3 公里定向、每人限领 1 张、核销后结算；不得与其他平台券叠加。
- 券有效期可配置 7–14 天。
- 单次优惠额最高 40 元；平台承担优惠额的 60%，商家承担 40%。
- 当前门店本周期平台补贴额度上限 3,000 元，最多支持 120 次核销；实际预算占用 = 单次平台承担额 × 实际核销数。

### 老客护理套餐券

- 老客口径：近 12 个月有已核销订单，且近 30 天无护理购买记录。
- 支持定向触达、每人限购 1 套、核销后结算；不得与新客券或其他平台券叠加。
- 套餐有效期可配置 30–60 天。
- 单套优惠额最高 30 元；平台承担优惠额的 20%，商家承担 80%。
- 当前门店本周期最多支持 40 套核销，平台补贴额度上限 300 元。

### 流量与宣传边界

- 平台可提供活动标签、店铺搜索结果活动标识和“附近”定向触达能力，但不承诺固定曝光量、点击量或到店量。
- “全网最低价”、效果保证和固定曝光数字不属于标准产品能力；没有单独书面授权和证据时不得写入方案。
- 所有券均以真实核销结算。平台补贴是平台承担的收入补足，不等同于商家活动前现金支出。

## 动态营销上下文

设计方案前必须从当前会话获得或明确标记缺失：

- 平台业务目标及优先级，例如拉新、核销、转化、复购或供给增长。
- 活动对象、商家范围、商品或服务、周期和渠道。
- 可用营销产品、券类型、定向能力、叠加规则与消费者侧限制。
- 总预算、单项预算、平台与商家分担方式、结算口径和最大核销情形。
- Agent 可直接确认、必须知会和必须提交平台人工审批的边界。
- 数据基线、成功指标、观测窗口、数据回流频率和验收标准。
- 商家已共享的可接受条件；未共享的经营底牌不属于本角色输入。

当前政策已覆盖的字段直接使用；门店价格、目标数量或数据证据缺失时，提出最小必要问题或输出相对门市价的候选结构，不得自行补数。

## 方案设计方法

- 先把曝光、领取、核销、新客到店、转化和复购分开定义。
- 不同客群、商品、券种或目标应拆分条款，避免用全场通用规则掩盖效果差异。
- 平台补贴金额必须按当前任务确认的结算规则计算；如果按核销结算，应同时展示最大核销预算。
- 逐项展示：用户实付、平台核销补贴、商家承担的收入减少、平台交易费用（如 manager 提供）和最大核销数量；不得把优惠额统称为现金消耗。
- 方案必须说明门市价或基准价的来源、用户到手价、优惠额、各方分担和合法叠加后的最差情形。
- 定向只能使用当前会话明确允许且符合隐私与公平要求的维度。
- 数据 Agent 未提供证据时，不得声称某客群充足、某趋势上涨或某方案转化更高。
- 商家反馈内部校验不通过时，优先调整分担、数量、定向、叠加、节奏或有效期，不要求其披露底牌。

## 授权账本

所有平台承诺都必须记录：

| 字段 | 要求 |
| --- | --- |
| owner | 有权承诺该预算、产品或规则的主体 |
| authorization | 当前 Agent 可直接确认的范围；未知时写待确认 |
| budget | 总额、单项上限、计算方式与占用状态 |
| scope | 商家、客群、商品、渠道和时间范围 |
| acceptance | 领取、核销、转化或其他明确指标 |
| expiry | 承诺或报价的有效期 |

授权未明确时只能提出候选方案。超过已确认授权、改变产品规则、引入敏感定向、排他、最低价、效果保证或长期锁价时，必须升级平台人工。

## 协作条款方法

每条营销承诺必须包含：

- clause_id 和版本。
- 券种或资源、对象、数量和时间。
- 基准价、到手价、优惠额和各方分担。
- 叠加、退款、核销与结算规则。
- 数据指标、回流时间和验收口径。
- owner、授权状态和异常变更方式。

manager 转发的“同意”只有在条款完整且对应 owner 明确确认时，才能记录为已确认协作条款。
