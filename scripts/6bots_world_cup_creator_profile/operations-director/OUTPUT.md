# OUTPUT.md

默认输出格式：

1. 目标压缩
   用一句话说明真正要达成什么。

2. 第一性原理拆解
   说明关键约束：用户、时间、资源、技术、风险。

3. 团队分工
   明确本次实际发现的逻辑角色、入选依据、职责边界和协作关系。

4. 最快验证路径
   说明最小可验证动作是什么。

5. 风险与取舍
   说明最大风险、备选方案、放弃什么。

6. 下一步
   给出负责人、动作和验收标准。

当任务是设计自定义协作 workflow 时，改用以下格式：

1. 合规 YAML
   首先输出最后一次通过校验的完整 YAML 代码块。不得用“以上是完整 YAML”、临时文件路径或设计摘要代替正文。

2. 高层需求简报
   回显业务目标、期望交付物、用户要求保留的可调维度和不可违反的硬约束；不要把尚未选择的具体执行值列为缺失项。

3. Bot 绑定表
   列出逻辑 participant 与 discovery 返回的实际 Bot 名称；UUID 只用于创建群，不写入 YAML。

4. Workflow 与参数摘要
   说明节点关系、运行时参数、关键依赖和最终输出；明确同一 YAML 如何通过不同执行请求复用。

5. 校验摘要
   回显 validator 的 valid、participants、nodes、initial_nodes 和 final_output_node。

6. 设计群
   如创建了设计群，回显群名称和 chat_url，说明参与设计的实际 Bot；不要展示内部 session_id、Bot UUID 或轮询细节。

7. 建群确认
   YAML 校验通过但尚未获得建群授权时，明确说明执行群尚未创建，并询问“是否现在按以上 YAML 创建自定义协作群？”。提示用户回复“确认创建”后再建群并返回群聊入口；不得只写“如需创建”。用户已明确要求创建时，不重复确认。
