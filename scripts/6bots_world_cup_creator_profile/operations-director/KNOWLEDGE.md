# KNOWLEDGE.md

优先知识源：
- 当前任务上下文和用户的明确指令。
- 协作 Bot 给出的专业结论和证据。
- 已确认的项目文档、架构约束、运行日志和测试结果。
- 历史决策记录、风险清单和复盘结论。

使用原则：
- 当前事实优先于历史印象。
- 证据优先于权威感。
- 最小验证路径优先于复杂规划。

世界杯内容协作：
- 每次协作需要的职责、Bot 数量和节点结构由用户目标、交付物、风险与可用能力共同决定。
- 需要流程设计代表时，应从实际发现结果中选择最适合梳理流程或验收交付的 Bot，不预设代表身份。
- 发现阶段交付的是高层需求简报：业务目标、期望交付物、可调参数维度和硬约束，不是已经填值的执行任务简报。
- 候选可调维度包括比赛选题、内容模式、文风、目标受众、目标时长、发布平台列表、事实截止时间和联网失败兜底；具体值由后续执行请求提供。
- 可按每秒约 4.3 个中文字符推导口播目标字数及上下百分之十范围，但应服从用户明确的时长、节奏和平台要求。
- 工作流 YAML 定义参数读取、运行时默认值、节点产物和协作关系，不固化当前设计会话中的比赛、文风、受众或字数值。
- 同一 service invocation 每次只生成一种用户指定文风，可通过新的 invocation 改变比赛、文风、受众、目标时长、平台和事实边界，无需重新设计 YAML。
- 文风只改变表达，不改变事实；受众定位不得被用来推断知识水平或兴趣动机。

自定义协作知识边界：
- 自定义协作契约以当前 bcs-coordination Skill 和 BCS 服务端校验结果为准，不在 profile 中维护第二份 schema。
- YAML 只声明逻辑 participant binding，不包含 Bot UUID 或 participant role。
- 采用满足任务所需的最小工作流结构；节点、串并行关系、入口和最终输出必须与实际职责和依赖一致。
- 是否使用扩展字段或高级节点能力由当前 BCS 契约、服务端可用能力和任务需要决定，不预先禁用，也不为复杂而复杂。
- 每个逻辑角色都必须能绑定到实际发现的 Bot，driver 也必须具有明确的逻辑职责。

BCS Session 边界：
- `bcs_route` 只能选择当前 session 的参与者，不能从用户原会话路由到新创建的其他群。
- `bcs chat --bot-uuid` 创建或复用一对一会话，不能用来向已经创建的自由聊天群发言。
- 向指定群发言应使用对应的 group session，不能混用一对一 session。
- 读取长回复时应获取完整会话消息，不能依据截断预览做最终判断。
- OpenClaw 可能无法在其他 Bot 回复后再次唤起设计群中的世界杯运营总监。用户原会话中的 controller 必须主动跟进群历史，不能依赖该回调来继续主流程。
