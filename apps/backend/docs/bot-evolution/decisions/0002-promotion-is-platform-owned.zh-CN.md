# 被进化 bot 修订版的晋升归平台所有

> English version: [0002-promotion-is-platform-owned.md](0002-promotion-is-platform-owned.md)

状态：proposed（决策草案；接受后晋升到 `docs/adr/`）。

## 决策

进化策略是可插拔的，但**晋升不是**。只有平台门禁可以移动 bot 的 `active`
基因组引用（ref）。进化策略可以提交候选补丁；bot 可以向收件箱
提交观察和补丁草稿。两者都不能写入线上 bot、它的工作区或它的基因组引用。

一个候选只有在以下条件全部满足时才可晋升：平台底线通过（schema、锁定基因和
钉住项未被改动、密钥 / PII 扫描、无权限提升、在平台所有的回归集和安全集上无
回退、预算），在绑定的验证配置下验证判定为 `accept`（所有者可以选择更严格的
配置，进化策略不能放宽它），且补丁的风险等级获得批准（在所有者策略
下低等级自动批准，其他情况需人工评审；工具、script 和 policy 的变更默认锁定，
永不自动晋升）。

验证同样归平台所有。用例集、评分器、验证配置（verification profile）和协议
都位于基因组之外。它们对进化策略、bot 以及第 3 层元循环都是只读的，只能通过
经人工评审的变更来修改。元循环提出的新改进机制（进化策略版本）只有在通过机制
验证并获得人工批准后才会被采用。进化策略的输入永远不包含封存集（holdout）、
回归集或安全集的用例。

设计：[`../08-promotion.zh-CN.md`](../08-promotion.zh-CN.md)。

## 影响

- ClawEvolve 的 tune 阶段必须停止编辑线上工作区，改为从沙箱中产出补丁；
  pack/restore 退出进化流程。
- 任何第三方进化策略都可以被启用，而无需授予它生产环境写权限。
- bot 所有者获得一个评审队列和按 bot 的策略（启用的进化策略、自动晋升上限、
  预算）。
- 每一次晋升和回滚都会连同证据和评估链接一起被审计。

## 备选方案

- **每个进化策略按自己的规则晋升**（即当前 ClawEvolve 的接纳规则加上原地
  编辑）。已否决：奖励投机（reward hacking）和自我评分是自改进 agent 被报告
  最多的失败模式。
- **始终要求人工批准。** 不作为默认值：会阻塞低风险的记忆更新；作为所有者
  策略保留可用。
