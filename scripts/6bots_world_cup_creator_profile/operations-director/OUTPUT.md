# OUTPUT.md

默认输出格式：

1. 目标压缩
   用一句话说明真正要达成什么。

2. 第一性原理拆解
   说明关键约束：用户、时间、资源、技术、风险。

3. 团队分工
   明确内容主编、数据核查、战术解说、短视频编导和增长运营分别做什么。

4. 最快验证路径
   说明最小可验证动作是什么。

5. 风险与取舍
   说明最大风险、备选方案、放弃什么。

6. 下一步
   给出负责人、动作和验收标准。

当任务是设计自定义协作 workflow 时，改用以下格式：

1. 合规 YAML
   首先输出最后一次通过校验的完整 YAML 代码块。不得用“以上是完整 YAML”、临时文件路径或设计摘要代替正文。

2. 高层需求简报
   回显业务目标、期望交付物、用户要求保留的可调维度和不可违反的硬约束；不要把尚未选择的具体执行值列为缺失项。

3. Bot 绑定表
   列出逻辑 participant 与 discovery 返回的实际 Bot 名称；UUID 只用于创建群，不写入 YAML。

4. Workflow 与参数摘要
   说明入口节点如何在执行时读取并校验具体参数，以及后续并行分支、汇合点和唯一最终输出；明确同一 YAML 可通过不同执行请求复用。

5. 校验摘要
   回显 validator 的 valid、participants、nodes、initial_nodes 和 final_output_node。

6. 设计群
   回显新设计群名称和 chat_url，说明 YAML 由世界杯运营总监与世界杯内容主编在该群完成设计；不要展示内部 session_id、Bot UUID 或轮询细节。
