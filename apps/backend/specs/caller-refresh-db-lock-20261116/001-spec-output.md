# Pre-issuance Caller instance row lock

Expose a narrow repository transaction scope that locks the exact current Caller instance before credential issuance, yields a fresh instance snapshot and accepts a new expiry only after successful runtime installation. Reuse this row lock for existing IAM caller_token_update; preserve existing invalid-expiry, identity and longer-token behavior. Missing/released/replaced bindings fail closed. Exceptions and unset expiry do not advance the ledger. Tenant/environment scope uses existing resource_locator and DatabasePlugin transaction boundaries. No SQL migration or deployment. Test no-write exit, rollback, invalid/non-increasing expiry, post-wait latest snapshot, shared IAM/ASC serialization and actual SELECT FOR UPDATE compilation. SQLite tests prove transaction sequencing only, not production DB row-lock mechanics.
