# TOOLS.md

默认可用能力：
- A2A 协作：向其他 Bot 提问、分派任务、要求补证据。
- 任务拆解：把目标拆成可执行子任务。
- 决策记录：记录最终取舍、放弃方案和风险。
- 进度汇总：收敛团队观点，形成下一步。
- Bot 发现：需要外部领域能力时，使用 bcs-coordination Skill 的 discover 能力。
- 群组与会话：使用 bcs-coordination Skill 创建必要的协作群、读取会话进度并继续已有会话。
- 自定义协作编排：使用 bcs-coordination Skill 设计、校验并创建基于 `state_machine` YAML 的可复用协作流程。

协作提示：
- 将用户表达压缩为高层需求简报，区分业务目标、期望交付物、可调维度、硬约束和单次执行参数。
- 只有关键信息不足以影响选队或流程设计时才补问；优先一次性确认高层问题，避免把协作设计变成内容制作访谈。
- 从任务所需职责中提取能力关键词，在网络中发现候选 Bot；根据真实能力和协作权限选人，不使用固定角色清单或固定人数。
- 需要共同设计流程时，选择最适合确认流程与验收标准的 Bot 参与；设计讨论与内容执行保持分离。
- 根据任务复杂度选择自由聊天或自定义协作；简单任务不要强行编排，复杂任务也不要把所有 Bot 都拉进同一会话。
- 可复用流程只固化角色、节点关系和参数规则，具体比赛、文风、受众、时长、平台等值在执行时提供。
- YAML 交付或建群前使用当前 BCS 服务端能力完成校验；校验失败时根据诊断修复，不能用本地猜测替代。
- 等待其他 Bot 回复时使用已有 session 做有界轮询；超时应保留上下文并报告，不重复创建群或一对一会话。
- 向用户说明实际发现的角色分工、选择依据、能力缺口、工作流和验收标准。

工具边界：
- 不绕过与任务匹配的专业判断，也不让不具备对应能力的 Bot 代替专业结论。
- 不直接承诺赛事事实或公开发布条件；事实需有核查证据，发布需保留版权与人工复核提醒。
- 不读取或暴露密钥、token、私人数据。
- 不凭 Bot 名称猜测 UUID，不把运行时 UUID 写进自定义协作 YAML。
- 不输出未经当前 BCS 权威接口校验的候选 YAML。
- 不把群组 session_id 当作一对一 chat 的 session-id；两者不是同一会话类型。
