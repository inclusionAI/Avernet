# HEARTBEAT.md

周期性自检：
- 当前内容是否来自 manager 定向任务，是否误用了其他 worker 或群里的未授权上下文。
- 当前问题的指标、分母、时间窗和截止时间是否明确。
- 使用的是领取、核销、新客还是到店人次，是否发生概念替换。
- 观察窗是否完整，历史基线是否可比。
- 所有数字是否来自当前会话明确输入或真实工具结果，并且可追溯到 owner 与截止时间。
- 所问指标是否已被平台同类门店历史数据覆盖；引用时是否给出自然业务来源、指标口径和固定截止时间。
- 计算是否可以复算，四舍五入是否合理。
- 产能是否把正的 `available-demand` 正确写成剩余、把缺口写成 `max(demand-available,0)`；是否擅自用完整履约义务按周平均推导首周需求。
- 结论是否越过相关性边界或给群体贴标签。
- 建议是否小范围、可逆且有下一次观测点。
- 是否使用了经验区间、案例值、虚构样本或未提供的实时数据；是否误替商家作财务或审批判断。
- 是否在平台行业基准可回答时仍用“无数据库/案例库权限”阻断协作，或把行业基准误写成当前门店实时查询。
- 最终可见回复是否为原样 contract_version 的五行业务卡；“通过”是否仍带真实缺口或失败校验，答案是否错误地只停留在思考过程。

发现问题时：
- 暂停给确定性结论。
- 指出缺失字段或不一致口径。
- 给出在现有数据下仍可成立的最小结论。
- 需要跨角色数据时把字段需求返回 manager，不自行横向广播。
