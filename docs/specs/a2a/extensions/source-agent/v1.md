# BCN A2A 来源 Agent 扩展 v1

> 历史合同，已被 [v2 来源分类扩展](v2.md) 替代。新注册/更新不再接受此 v1；平台身份改由注册字段 provider_bot_ref 提供。以下内容仅保留历史语义，不作为当前接入要求。

URI: `https://github.com/inclusionAI/Avernet/blob/dev/docs/specs/a2a/extensions/source-agent/v1.md`

这是 BCN 定义的 A2A Data-only Extension，不是 A2A 核心标准字段。
Agent 在 AgentCard 中声明来源信息，BCN 注册及 Card 管理入口消费这些数据。
扩展不增加调用方法，不改变消息、Task 或 Context 的语义。

## 声明

在 `capabilities.extensions` 数组中添加以下对象，同一 Card 只能声明一次：

```json
{
  "uri": "https://github.com/inclusionAI/Avernet/blob/dev/docs/specs/a2a/extensions/source-agent/v1.md",
  "required": false,
  "params": {
    "agentId": "order-agent-001",
    "party": "first_party"
  }
}
```

所有 Provider 和部署环境使用同一个 URI。该地址标识规范，不是 Agent
服务地址；消费方无需在运行时访问它，也不需要通过调用请求激活此数据扩展。
未知此扩展的 A2A 客户端仍可正常调用 Agent。

## 字段

| 字段 | 要求 |
| --- | --- |
| `uri` | 与上述 URI 完全一致，不根据 Provider、环境或 Agent 版本替换 |
| `required` | 显式填写 `false` |
| `params` | JSON 对象 |
| `params.agentId` | 必填字符串，1～256 个 Unicode 字符，无首尾空白或控制字符；保留大小写和前导零，不做数字转换或 Unicode 归一化 |
| `params.party` | 可选，取值为 `first_party`、`second_party` 或 `third_party`；省略表示未分类，不能以 `null` 或空字符串代替 |

来源分类以所属 BCN Provider 为参照：`first_party` 为自身提供，
`second_party` 为与其有直接合作关系的合作方提供，`third_party` 为其他外部来源。
分类由接入方声明，不表示平台认证、信任级别或访问权限。
未知附加字段随完整原始 Card 保留，不产生额外权限或路由语义。

## BCN 管理约束

- 整个扩展可省略；首次登记后也允许补充，但补充时必须满足唯一性要求。
- `agentId` 在同一环境、同一 Provider 的有效 Bot 中唯一，按原始字符串精确比较；不同 Provider 可以使用相同值。
- 一个 Bot 一旦登记 `agentId`，后续更新、手动刷新、周期刷新均不能修改或移除它，包括移除整个扩展。Agent 改名不影响此规则。
- `party` 可以更新或移除；移除后表示未分类，不影响来源 ID 或已有任务关联。
- 相同 Provider 下重复来源 ID 返回 `SOURCE_AGENT_CONFLICT`；修改或移除已登记 ID 返回 `SOURCE_AGENT_CHANGE_NOT_ALLOWED`；字段不符合规范返回 `INVALID_CARD`。被拒绝的操作不能写入部分 Card 或改名结果。
- Provider 归属来自管理凭据和 BCN 注册关联，不采信 Card 自声明。`agentId` 不代替 BCN `bot_id`、Card.name、远端服务地址或鉴权凭据。
- BCN 保存完整原始 Card，不注入 Provider 信息，不因识别本扩展而删除其他字段或重写签名内容。

这些管理约束是 BCN 的接入约定；其他 A2A 客户端忽略可选扩展仍然符合协议。
来源 ID 查询接口及派生索引不由本扩展定义。

## 版本与兼容性

不兼容的字段结构或语义变更使用新版本 URI。普通 Agent 升级或 Card 更新
不修改 URI。旧文档中的 `example.org` 占位地址不是此扩展的别名。
本文件在本地新增不代表上述仓库 URL 已发布，需随仓库变更合入。

验证应覆盖：缺省扩展、合法及非法字段、大小写和前导零、同 Provider 冲突、
跨 Provider 隔离、首次补充、ID 修改及移除拒绝、party 更新及移除、未知数据保留，
以及并发操作下的持久化一致性。纯字段校验通过不能替代仓储唯一性验证。
