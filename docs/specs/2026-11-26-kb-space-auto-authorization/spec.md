# 知识库按空间自动授权 Bot

## Summary
每个知识库提供默认关闭的“自动授权当前空间下所有 Bot”开关，适用于个人空间和团队空间。开启后覆盖当前及后续加入的 Bot，保留逐 Bot 人工取消、恢复和独立启用能力。

## Motivation
逐个授权增加维护成本，也容易遗漏新建或转入的 Bot。需要减少重复操作，同时保证人工取消、空间迁移和 Owner 转交不会造成权限意外恢复或丢失。

## User Stories
- As a 知识库创建者, I want 开启本库的空间自动授权, so that 当前及新增 Bot 无需重复人工授权。
- As a 有授权管理权限的用户, I want 取消或恢复某个 Bot 的访问, so that 例外持续生效且不影响其他关系。
- As a Bot Owner, I want 授权与启用分开、转交和迁移遵守既定规则, so that 知识访问可控且状态可解释。

## Acceptance Criteria
- [ ] AC01：两类空间的新旧库均默认 OFF；仅创建者可修改开关，服务端拒绝其他操作者修改；既有人工作用范围不扩大。
- [ ] AC02：旧库开启后，当前符合条件的 Bot 在同步收敛后进入授权列表、计数及可选知识库；仅产生一条开启汇总动态，不自动启用；数量为该轮自动操作实际新增且确认成功的去重 Bot 数，已授权、跳过、失败和待确认另列。
- [ ] AC03：ON 期间新建和转入 Bot 自动获权；新建知识库仍 OFF。两类空间分别覆盖。
- [ ] AC04：人工取消持续到本次连续入驻结束，重试、对账及 OFF→ON 不恢复；人工恢复可重新访问。两种操作均留痕、并发冲突可识别，其他关系不受影响。
- [ ] AC05：关闭只停止新增自动授权，保留此前获权和人工例外；关闭后新增 Bot 不自动获权，仍可人工调整；关闭产生一条汇总动态，数量采用相同“本次实际新增成功数”口径，正常为 0，不能显示为撤权数或当前总授权数。
- [ ] AC06：移出或删除后，旧空间授权在同步收敛后失效，历史人工授权不能绕过；停止/休眠不撤权。覆盖转交引发的空间变化。
- [ ] AC07：迁回为新入驻；ON 时重新获权，OFF 时历史授权不复活；旧取消不永久继承，重复同步不产生新入驻。
- [ ] AC08：自动授权不修改启用、发布、WRITE 或管理权限；仍检查可信调用主体的原生 READ；取消 Bot 授权不撤销人员权限。
- [ ] AC09：自动操作建立实际授权，列表、计数、候选、开启检查、配置、对话/服务 Bot 各阶段及实际内容访问复用现有授权结果；自动与人工授权均可分页、取消和恢复，活动中区分操作来源，不伪装成人工操作。
- [ ] AC10：TC 在新建、转入、移出、删除及 Owner 转交时可靠执行授权/撤权；断网、重启和结果未知可恢复，旧任务不能恢复已取消授权或撤销新状态。自动任务必须具有实际执行权限；无权、失败和未确认结果可识别，不伪报完成。
- [ ] AC11：受控环境贯通开启、当前/新增/转入获权、启用检索、取消直调拒绝、恢复、关闭、迁出迁回和删除，核对页面、授权结果及实际消费；未验证场景单列。
- [ ] AC12：同 Bot 同空间仅换 Owner 时，人工授权、自动授权、关闭后保留资格及人工取消全部承接；新主体仍独立通过原生 READ；跨空间转交按迁移处理。

## In Scope
- 每库开关、自动与人工实际授权、当前连续归属期间的人工例外、管理页面与活动反馈。
- TC 感知 Bot 生命周期并可靠发起授权/撤权；ECB 保存每库开关、实际授权并负责鉴权和更新记录；企业工作台集成及组合验证。

## Out of Scope
- 跨空间授权、永久禁止名单、通知中心、审批、语雀导入、知识库删除流程重设计。
- 自动启用、安装 MCP、发布服务 Bot、扩大人员权限；生产 DDL、初始化执行、发布和部署。
- 即时撤权、终止已鉴权在途调用或未经验证的同步时限承诺。
- ECB 保存 Bot 归属/入驻历史、计算继承资格，以及相关投影初始化。
