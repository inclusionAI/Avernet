# 副屏发起协作之后的交互 Roadmap

本文件配套 [首版 spec](./spec.md)。**本轮实现副屏预览 + frontend 现有主屏建群浮层。聊天控制不进入首版实施或验收清单。** 以下事项均未实现、未排定发布承诺；它们也不改变之前 Draft 编辑、Bot review 和已有群 apply 的独立规划。

## 1. 首版：副屏预览、主屏确认发起协作

交付用户结果：从助手给出的固定方案预览进入配置，选择自己的发起 Bot 和可协作成员，明确点击“建群并开始协作”，进入真实新群。

首版只使用当前登录用户的既有权限；助手不获得用户 Bot 凭据或持续代操作授权。是否完成以 spec 的 L-AC01–13 为准，不能用聊天按钮演示替代真实身份与建群验收。

## 2. 后续：聊天打开和调整同一份配置

用户可以说“用我的助手发起这个方案”“把审稿角色换成法律助手”。聊天产生结构化意图，宿主在可信当前用户上下文中更新同一份配置；主屏浮层展示同一份配置。

前置契约：

- 明确用户、来源会话、目标配置实例和固定 Draft revision 的可信关联；模型传入的 userId、Bot 名称或 sessionId 不构成授权。
- 定义宿主接收助手建议并回传选择结果的能力。现有 UMD props 或 `onInteraction` 的存在不等于已具备这条双向链路，需要单独验证。
- 候选检索仍按所选发起 Bot 的关系进行。同名候选由用户选择；模型只能建议，不能扩大候选范围。
- 不默认把完整 Bot 目录/好友信息注入共享协作助手。仅传递该轮操作必要且经用户选择的上下文。
- 聊天和副屏并发修改需要配置版本或等价冲突检测，不能让迟到建议覆盖最新绑定；切换用户/版本后旧建议失效。

该阶段的自然语言操作先限定为“打开配置、选择建议、修改绑定和任务说明”。最终创建继续使用主屏浮层的明确按钮，不因普通聊天文本出现“确认”自动执行。

## 3. 再后续：通过聊天确认并执行

只有用户明确需要纯聊天完成操作时再启动本阶段。必须先定义可信用户操作授权，而不是给共享协作助手配置所有用户 Bot token。

一次确认应绑定具体用户、固定方案版本、发起 Bot、完整参与者/角色绑定和任务说明。任何影响执行的参数变化都使旧确认失效。确认只能消费一次；同时设计取消、失效、跨会话重放、网络未知结果和审计规则。

可以复用已有可信宿主用户操作通道；若需要 Backend/Gateway/Runtime/frontend 扩展，单独明确范围和契约，不作为副屏首版的隐藏依赖，也不以本 roadmap 代替实现授权。

## 4. 条件性增强：建群结果恢复与幂等

首版没有跨刷新/跨设备自动重试保证。若未知结果影响使用，再设计服务端建群操作幂等契约：

- key 按可信调用用户和部署隔离，并绑定确认内容；同 key 不同内容冲突。
- 原子关联创建意图、群 ID、初始会话和启动结果；不能只缓存成功响应而忽略崩溃窗口。
- 重启、部分失败和补偿未完成时可查明状态，不重复创建群或重复启动 Run。
- 结果查询不依赖当前 Draft readToken，且不能泄露别的用户的操作。

优先落在 BCS 既有 Group 创建职责内，不预建跨业务通用操作平台，不把 Draft CAS 当成建群幂等。

## 5. 独立需求

- 自定义协作指定与发起 Bot 不同的协调 Bot：有真实使用需求后再增加；普通自由聊天与任务协作已沿用现有群主/Manager 选择。
- 配置记忆、跨设备恢复、常用角色组合：先确定用户归属和生命周期，不能写入助手共享 Draft。
- 保存编辑结果为新 Draft revision、让 Bot review、应用到已有群：继续作为独立规划，先定义用户写权和跨 Bot 修改授权。本轮已支持在建群表单内编辑本地副本，但不写回共享 Draft。现有上传 Bot 管理权和 readToken 不自动扩展为这些权限。
- 只建群不启动、任意结构化运行输入、任务系统集成：独立交互与契约评审，不用首版未实现的开关预留接口。


## frontend-nextgen 接入（未实现）

- 在 `src/services/bcs/UmdPanel.tsx` 等实际 UMD 宿主注入相同的 `onOpenCreateGroup(options?)` 通用回调（无参或可选 `{draft: reference}`），按需打开该宿主现有建群组件；不启用已移除的副屏独立表单。
- 为现有建群组件提供独立的自有 Bot 选择参数和可选初始 Draft，无 Draft 时保留群类型和模板；带 Draft 时固定自定义协作、隐藏模板切换、自动校验展开，保留重新编辑；共用群名、目标、角色绑定、逻辑 Loop 及高级设置；发起 Bot 与当前聊天身份独立。
- 读取固定 Draft 使用宿主可信 `/api/v1/collaboration` base，Human 操作使用 `/openapi/v1/collaboration`；验证真实 Gateway 认证和转发，不根据 401/404 回退到原生路由。
- 与 frontend 对齐初始原文完整性检查、当前编辑文本校验及提交前用户复核、候选视角隔离、单次提交锁、未知结果和取消语义；成功使用 nextgen 的群/Session 导航。
- 回调仅内存传递引用，避免日志、URL 和持久化存储泄露；群聊/私聊都验证，未接入时保持只读。
- 单独验收部署环境创建群、初始会话、启动 Run 和历史重开；本轮不修改 frontend-nextgen 源码。

## 候选筛选一致性（未实现）

将现有建群浮层的好友筛选和画像推荐接到 Human 候选契约；结果须保持选定发起 Bot 的权限视角。当前自有 Bot 入口提供名称搜索和分页，不使用协作助手身份查询。
