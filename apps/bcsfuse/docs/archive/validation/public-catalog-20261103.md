# 公共 Card 检索流程独立运行验证（2026-11-03）

本轮把通用运行能力和默认转换器移到 Avernet。OCB 保留支付宝业务转换、运营规则、历史资料兼容和内部平台接入；TC 不迁表、不切换现有流程。

## 实际验证

使用只安装 `search-core[http,qdrant]` wheel 的新 Python 环境，从仓库外启动 HTTP 服务。
没有添加 OCB 源码路径；启动时确认内部包不可用，并禁止导入 OCB、ZDAS、Layotto、SofaPy 和 TC app。
存储使用真实 SQLite 与 Qdrant Local，模型使用公共离线示例向量，无精排模型。

| 操作 | 结果 |
| --- | --- |
| PUT 新 Card，等待本实例索引状态完成 | 返回 202，检索返回对应 Card，状态 ok |
| PUT 修改名称和描述 | 版本推进，recommend 返回新资料 |
| 停止进程，使用相同数据目录重启 | 恢复原版本，search 返回更新后的资料 |
| DELETE Card，等待本实例应用 | 返回 202，随后搜索不再返回该 Card |
| 自定义转换器生成两条 Doc，再减少到一条 | 旧 Doc 标记删除，索引只保留当前 Doc |
| 第二实例从已发布 Doc 恢复 | 不重复调用转换器或 Embedding |

启动和调用示例见 [独立运行指南](../../../packages/search-core/docs/local-catalog.md)。

OCB 回归中包含真实的两个独立 Qdrant Server：构建新版本、前向切换、单 Card 修复和回退通过。
跳过项包括未提供专用 Server 地址的额外场景、真实 MySQL/OB 集成和 Linux 二进制安装测试；不把本地通过当成这些环境已经验证。

最终检查修正了默认 Card 可选描述为 null 时的响应错误，以及自定义转换器辅助函数与运行时计算不同 index_key 的问题；两者均先复现失败，再验证修复。支付宝显式指定的历史转换版本保持原键值。

这是功能与兼容性验证，不是吞吐压测、真实模型效果或预发部署结果。未改动数据库结构；两仓部署仍需使用匹配的公共包和内部版本。
