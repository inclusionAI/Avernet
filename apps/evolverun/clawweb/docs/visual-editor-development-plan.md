# ClawWeb 轻量可视化编辑器开发方案

状态：本轮 A–F 已完成并通过本地验收；未发布。日期：2026-10-29。

## 1. 目标与边界

将已确认的 HTML Demo 落到现有 React / React Flow 编辑器，不是另建一套只能运行演示数据的页面。

目标：用户能通过拖拽、连线与少量业务字段编辑真实工作流；同时保留复杂工作流的完整配置和既有保存、版本、部署流程。

本轮不做：生产数据写入、线上部署、提交/推送代码、BaaS鉴权改造、引擎执行行为变更、伪造技能/人员/工具服务、不新增公司内网依赖。继续使用当前工作区，不自动切换分支或处理其他未提交文件。

### 1.1 设计输入与数据依据

- 交互基线：本聊天中已确认的离线 HTML Demo；其交互不是生产API或运行器实现。
- 研究快照：375份当前保存定义、3,071顶层节点；53份active部署定义、639顶层节点。两组重叠，不相加，也不是运行流量统计。
- active中AI处理256、脚本235，合计76.8%；all_success为599/639（93.7%）；完全匹配标准单次尝试配置557/639（87.2%）。
- 这些比例只决定默认界面优先级，不决定字段是否可以删除。identity、输出契约、分支、失败处理等即便折叠也必须保留。
- 在线BaaS文档未能认证读取；此次不扩展BaaS合同，沿用原始配置保留模式。

## 3. 用户可见行为与验收编号

### U01：默认工作区

- 保留任务护航的应用导航和工作流上下文，不复制Demo的静态假导航/假用户。
- 左：常用节点库；中：画布或YAML/对照视图；右：选中节点的业务属性。
- 未选中节点时展示简短引导，不自动展开全量工作流配置。
- 工作流级设置由明确按钮进入；返回画布时保持编辑内容。
- 保留现有“保存”“版本历史”“部署”与确认流程。产品页面不把真实部署按钮标成Demo，也不在验证中触发它。

### U02：节点库

常用：AI处理、脚本执行、人工输入、审批、工具调用、完成。
更多：子代理、循环、外部动作、协作路由、Bot调用、子工作流等。生产中存在但缺专用表单的类型，显示真实类型与兼容模式，不强制变成done。

搜索匹配中文名、原始executor类型、说明。拖拽和点击均可新增节点；ID自动生成且唯一，phase自动生成合法值。不要复制Demo示例脚本、技能、人员到真实新建节点中。

### U03：画布与连接

- 节点展示：业务名称、类型、关键内容摘要、配置状态；默认保持可读比例，不自动把长流程缩成不可读缩略图。
- 提供缩放、总览/定位、节点搜索、小地图。
- 点击依赖线只选中，明确删除操作后才删除；不沿用“点线即删”。
- 拒绝自环、重复边、悬空端点、造成环的边；非法导入图仍能渲染并显示校验信息，不发生递归栈溢出。
- 连线改变真实dependsOn。并行仍由依赖结构表达，不新增parallel executor。
- 分支端口对应上游onResult.branches；连接时维护目标branchId，遇到不兼容的已有分支归属必须拒绝而非覆盖。
- 多输入节点显示有效触发规则；单输入非默认规则同样显示。
- 拖动位置只改变UI侧状态，不向执行spec新增_x/_y。导入定义已有的_x/_y作为兼容输入保留，不自动清理。当前坐标仅在编辑会话内保留，刷新页面后重新布局；不承诺服务端或跨浏览器持久化。
- 默认从上到下排列依赖层级，同层并行节点横向展开；合法旧坐标优先作为初始位置。

### U04：节点字段分层

| 类型 | 默认可见 | 高级/完整配置 |
|---|---|---|
| AI处理 | 名称、可选技能、任务指令、输出形式 | 超时、模型、上下文、工具、输出契约、进度消息等 |
| 脚本执行 | 名称、命令/脚本、可理解的参数输入、输出形式 | 完整args、env、workdir、超时等；不按空格拆命令或重新拼shell |
| 人工输入 | 名称、提示、输入与动作摘要/入口 | inputSchema、confirm/revise/reject、saveAs等保留；不退化成统一确认 |
| 审批 | 内容、审批人配置入口、规则、渠道摘要 | approvers/delivery/skillName/saveAs/卡片等，绝不伪造默认审批人 |
| MCP工具调用 | 服务、工具、参数、输出形式 | 原始参数与超时；不假装有已接入的工具目录 |
| 完成 | 名称、完成文案 | 汇合规则；说明done不取消其他分支 |
| 子代理 | 技能、任务指令 | 超时、上下文等 |
| 循环/扩展/未知类型 | 名称、真实类型、已配置摘要 | 原始完整执行器编辑；本轮不伪装成完整循环子画布 |

默认值提示不等于写入：展开面板、切换节点、查看YAML，不得自动添加retry、triggerRule、contextPolicy等。

### U05：分支与汇合

- 新式分支使用 `{ branches: [{ branchId, match, complete? }] }`，不导出不存在的branch executor。
- `complete: true` 不是“终止分支/禁止连线”：保持原值，不以此限制下游依赖；该行为已按本机 ClawMind runner 的分支选择逻辑复核。
- match按真实标量类型编辑，true与"true"不同；按数组顺序首个命中，兜底空对象应在最后。
- 既有旧式数组或if/then/else保留为兼容配置，不自动迁移/混写。
- 有显式triggerRule时以其为准；没有时join:any兼容one_success，其余按all_success提示。
- 修改、删除分支需检查下游归属；不能留下悬空branchId或静默改成另一条分支。

### U06：无损编辑与输入草稿

- 完整spec为执行文档真相；表单做明确字段patch，不按“可见字段”重建节点。
- 文本永远按字符串处理，不能因为以`{`开头便JSON.parse。
- JSON使用独立草稿；只有显式应用或合法提交才修改文档。非法/未应用内容不可在切节点、复制、删除、保存、导出或视图切换时悄悄消失。
- 所有隐藏字段、未知字段和missing/null/false/0/空字符串应被保留；原始配置编辑的删除必须是用户显式操作。
- 节点ID默认只读，改标题不改引用；兼容类型不强制转换。
- 删除节点先确认，清理已知依赖；若存在输出模板、人工反馈、分支目标等引用则阻止并列出来源，不做全局字符串替换。

### U07：历史与保存

- 增删改节点、连线、分支、原始配置、导入支持撤销/重做；单次拖动合并为一个历史步骤，历史有上限。
- 未应用文本草稿优先使用其文本撤销，不把半成品写入执行文档。
- 工作区内切页/切工作流使用明确放弃确认；浏览器刷新/关闭使用 beforeunload。顶层 SPA 导航和浏览器后退不改宿主路由架构：未应用 JSON/YAML 在同一编辑会话的内存中保留，返回时恢复正文与待应用状态；显式放弃/加载另一会话时清除。
- 这不是跨刷新自动保存：不将工作流或草稿写入 localStorage，关闭页面前仍需应用并保存。
- 本产品继续使用原有DB+Git保存，不引入把完整生产定义自动写localStorage的行为；画布坐标仅作为非敏感UI侧状态。
- 保存期间不得把后续新编辑误标为已保存；部署仍只能发布已保存定义，并保留确认。
- 保存/校验/网络失败必须显式反馈；不能用toast假装保存成功。

### U08：YAML与兼容

- 保留编辑、校验、应用、导入、导出和对照能力；不是把正式YAML编辑器降级成Demo的只读窗口。
- 只在没有待应用文本时从spec同步YAML；有草稿时保留原文并提示冲突。
- 只应用本次校验对应的文本版本；校验中再编辑、切换工作流或组件卸载时不得套用旧响应。
- 服务端normalizedSpec若会丢字段或改变值，先展示/阻止，不静默覆盖原始配置。
- 不承诺数据库JSON没有保存过的注释/锚点可以恢复；本轮保证语义字段保留，不做任意YAML源码排版保真。

## 4. 技术设计

### 4.1 组件拆分

- `editor/nodeCatalog.ts`：类型目录、中文文案、常用优先级、最小创建模板。只包含公开通用定义，无私有endpoint和示例凭据。
- `editor/graph.ts` / `editor/contracts.ts`：无环检查、布局、引用检查、真实分支读取/写入兼容适配、有效触发规则。
- `editor/store.ts`：完整spec、positions、选择、history、pendingEdits、actionError、已保存基线。
- `components/editor/*`：类型字段、JSON草稿、结果分支、节点卡片、画布工具栏等拆分组件。
- `NodePropertyPanel`：只负责选择状态和分层组合，不再把全部节点与系统配置塞进同一文件。
- `Editor`：负责与现有API及宿主集成，不承担执行器schema业务规则。

### 4.2 状态与协作接口

保持旧store入口兼容，新增明确动作：

```ts
positions: Record<string, { x: number; y: number }>
pendingEdits: Record<string, string>
actionError: string | null
canUndo: boolean
canRedo: boolean
setPendingEdit(key: string, message: string | null): void
setActionError(message: string | null): void
beginTransaction(): void
endTransaction(): void
undo(): void
redo(): void
duplicateNode(nodeId: string): void
addEdge(sourceId: string, targetId: string, branchId?: string): void
markClean(savedSpec?: WorkflowSpec): void
```

- pending key使用`node:<id>:<field>`、`workflow:<field>`或`yaml`，阻止会丢稿的操作；处理合法草稿时先解除相应key再patch。
- 单调 `sessionId` 隔离加载/新建/明确重置；同 ID 的新会话也使旧校验/保存响应失效。未应用文本另有会话内存缓存，组件因 SPA 导航卸载后可恢复；不进入执行 spec 或历史快照。
- positions与执行spec分离。旧坐标留在原始spec以保持兼容，新移动不改旧字段。
- 历史快照保存spec和positions，深拷贝JSON文档；不把React Flow内部Node/Edge对象当执行定义保存。
- 新式routing的类型适配集中在编辑器边界，避免把历史共享DTO的数组假设扩散到所有组件。
- 运行器同源全校验仍由现有后端接口负责；前端只做安全结构检查和用户可理解的提示，不宣称完整执行器校验。

### 4.3 外部边界

不增加Service API、不改变Plugin API、不触及ClawMind调度器。依赖继续使用已安装的React 19、React Flow 12、Zustand 5、YAML 2；不引入新的画布框架。

官方API参考：React Flow 12的screenToFlowPosition、受控节点、isValidConnection、onNodeDragStart/Stop、Handle id、MiniMap/Controls；实施以当前安装类型声明为最终编译依据。

### 4.4 视觉与可访问性

- 复用现有semantic theme：bg-background/bg-card/bg-primary/text-primary-foreground/text-muted-foreground/border-input。
- 不将Demo硬编码颜色、假导航、静态数据复制到正式业务页面。
- 按钮/表单有中文label与键盘焦点；添加节点提供非拖拽入口；删除需确认；状态/error可感知。
- 优先桌面工作台，窄屏使用可滚动/折叠区域，不宣称手机画布编辑已完整支持。

## 7. 风险、发布与回滚

1. **已有复杂配置损失**：以完整spec为底稿；默认字段patch；测试outputContract.required、未知嵌套字段及legacy分支。
2. **图操作改语义**：拒绝非法连接；分支归属冲突不覆盖；删除引用显式阻止；普通箭头不冒充人工反馈回跳。
3. **文字草稿丢失**：pendingEdits统一护栏；YAML持久挂载/独立草稿；异步结果用版本/请求标识核对。
4. **保存和部署耦合回归**：现有DB+Git顺序、降级错误提示、部署确认与autoRun:false全部保留并测试。
5. **旧数据字段不符合当前UI**：不自动修正或推断迁移；兼容模式给原始配置入口。前端校验不代替实际引擎合同。
6. **Node运行环境**：本机Node23与部分jsdom engines不一致；先运行验证再如实记录，避免盲目升级依赖。
7. **部署范围**：本轮只交付本地实现。人工验收后另行提交PR、预发验证及发布；本轮不跑预发流水线。
8. **回滚**：由于不引入存储迁移或新的后端schema，可回退本次前端变更；此前已保存的工作流仍使用原合同。
