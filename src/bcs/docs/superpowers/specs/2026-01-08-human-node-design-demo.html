State Machine · Design Review

HumanInput 节点

第一版只解决一次性的人工输入：Human 提供文本，后续 Judge、outcome 和 DAG progression 与 Bot 节点完全一致。

DAG-only · Workbench + IM Channel · 最后更新 2026-07-22

核心决定

产生文本

BotTask 来自 Bot final；HumanInput 来自有权限的 Human。

→

统一 Judge

都调用现有 Judge。无 Judge 时都得到 complete。

→

统一推进

通用 completion CAS、branch 选择与 DAG progression。

第一版的边界

本期实现

  • HumanInput 激活后进入 Running 等待。
  • Workbench 与 IM 都可提交自然语言。
  • Human 原文直接成为 artifact。
  • Present Human session 权限检查。
  • 持久化 deadline 与通用 timeout scanner。

本期不实现

  • YAML cyclic graph 与多次驳回循环。
  • Human-only clarification loop。
  • response claim、Judge lease 和 heartbeat。
  • Human-ready 持久化重投与 recovery scanner。
  • 跨实例 exactly-once 协调。

YAML 示例

review:
  kind: human_input
  display_name: 人工审核
  instruction: 请审核上游结果，并说明是否允许发布
  node_timeout_ms: 86400000
  judge:
    type: llm
    criteria: [是否明确允许发布]
    outcomes: [approved, rejected]
  transitions:
    approved: { targets: [publish] }
    rejected: { targets: [] }

HumanInput 不配置 Bot assignee；node_timeout_ms 必填；max_attempts 固定为 1；所有回边继续被 topology validator 拒绝。

响应路径

步骤行为
1. 输入校验非空、最多 64 KiB。
2. 权限调用者必须是 run session 中的 Present Human。
3. 状态run/node 必须仍是 Running，deadline 尚未到。
4. JudgeHuman 文本直接调用 Bot 已有的 Judge 路径。
5. 完成通用 CAS 写 outcome、原始 artifact 和 responded_by。
6. 推进复用现有 branch、dispatch 与 run completion。

并发与超时

并发响应

两个请求可能都调用 Judge，但只有一个能赢得通用 completion CAS；另一方得到 409。第一版接受这项成本。

Human timeout

使用数据库中的 timeout_deadline_ms 和现有 scanner。Human max_attempts=1，因此失败后不进入 Bot retry。

IM Channel

复用现有 binding、conversation-session mapping 和 participant mapping。Human-ready 通过 SessionChannelOutboundPort best-effort 推送；inbound 文本带着可信 Human identity 回到同一个 Runtime API。Channel 不解释 approve/reject。

数据库

ALTER TABLE bcs_state_machine_node_runs
  ADD COLUMN outcome VARCHAR(128) DEFAULT NULL,
  ADD COLUMN responded_by VARCHAR(256) DEFAULT NULL;

assignee_bot_id 在 Domain 中允许 None；数据库暂保留 NOT NULL，由 Store 使用空字符串 sentinel。Runtime 永远不能把 sentinel 当作 Bot delivery target。

为什么循环要后续统一实现

真正的 revise → review 回边需要 execution identity、artifact 版本、join 语义、最大迭代次数、timeout/cancel/recovery 和多轮 history。只重新打开 Human 节点会制造不完整的 Human-only runtime，因此本期保持 DAG-only。
