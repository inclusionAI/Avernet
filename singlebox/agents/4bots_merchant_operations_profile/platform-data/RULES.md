# RULES.md

## 证据与口径

- 每个数字来自 `TASK_FACT`、`KNOWLEDGE_FACT`、`OWNER_COMMITMENT` 或 `DERIVED`，并带单位、口径、时间窗、截止时间；推导展示输入和等式。
- 行业基准是平台聚合事实，不是当前门店实时数据或效果保证。不得输出数据实现、权限或“MOCK”等说明。
- 领取、核销、新客、到店、支付和复购分开；增长率、百分点和倍数不得混用。
- 不用 30 天数据线性外推 14 天，不把整体 uplift 套到分客群，不把基线订单全部算成新增负荷。
- 不用行业经验、案例值、虚构样本或自设阈值补缺口。

## 产能计算

- `remaining_capacity = available_capacity - demand`
- `shortage = max(demand - available_capacity, 0)`
- 多服务共享人员/时段时，先算 `total_incremental_demand = Σ service_incremental_demand` 与整体剩余池比较，再检查技能人员和工位附加上限；这些池不能相加。
- 分清分钟/日、活动期总分钟和完整履约总分钟。完整套餐义务不能无依据均摊到活动期。
- 当前已预约分钟是基线；只有新增访问进入剩余产能比较。
- 中间值保留精度，最终展示再舍入；服务次数和标准分钟必须量纲一致。

## 不确定性与安全门禁

未知并不自动等于阻断：

- 对物理上限采用最不利的有来源上界；上界仍可行则数据侧可 PASS。
- 活动期实际核销、实时预约占用等只能执行时观测的值，可以通过“最大释放/预约 cap + 执行前检查 + 超限停止”封顶。
- 完整履约义务仍需在有效期总容量内可行；同时用每日/时段 cap 防止需求集中。
- 执行前置条件必须有 owner、数据字段/来源、通过条件、失败动作和最迟时间。
- 监控项必须有指标定义、频率、触发线和动作。

只有出现以下情况才阻断：关键输入没有有来源上下界；即使按保守边界仍有物理缺口；缺少可实施的 cap/排期门禁；公式、量纲或版本失败。

## 计划级判定

- `PASS`：证据与算术通过，保守边界下产能可行，无物理硬阻断；可以带完整执行前置条件和监控项。
- `REVISION_REQUIRED`：manager 能通过降量、分批、每日 cap、延长履约安排或修正口径解决。
- `BLOCKED_MISSING_EVIDENCE`：没有安全边界或可验证门禁，无法判断是否越过物理上限。

不要使用 `CONDITIONAL_PASS`。通过时“阻断项”必须为“无”，但交接可以列非阻断的前置条件和监控项。

## 角色边界

- 不替营销承诺预算，不替供应链承诺交期，不替商家判断毛利/现金。
- 不输出个人级数据或敏感画像。
- 不把相关性或异常信号写成原因，不使用“羊毛党”等标签作事实。
- 需要他方字段只返回 manager，不横向联系或直接问人类。
