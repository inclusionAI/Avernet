# 集群执行器平面 —— 容量与成本模型

[English](capacity.md) · 属于[集群执行器平面设计](design.zh-CN.md)

## 1. 每个操作的语句数

| 操作 | 语句数 | 频率 |
| --- | --- | --- |
| 心跳(续期该节点全部租约) | 1 次写 | 每节点每 5 s |
| 读取花名册 | 1 次读 | 每节点每 5 s |
| 认领(冷) | 1 | 每个新活跃期 |
| 认领(不匹配) | 2 | 罕见,成员变化之后 |
| 围栏步骤 | 每个围栏事务 +1 次单行主键更新 | 每个所有者写事务 |
| 释放 / 转移 | 1 | 每次排空或再平衡 |
| 持久化入站轮次 | 1 | 每轮(先落盘后确认所必需) |
| 所有者拾取回退输入 | **每节点每周期** 1 次带索引查询,绝不按会话 | 每节点每周期 |
| 故障发现 | 每个幸存者针对每个死亡节点 1 次分页查询 | 每次死亡 |

这些计数会成为 `RecordingDb` 回归测试,使后续改动无法悄悄把按节点的查询变成按
会话的查询。

## 2. 两种场景

利特尔定律(Little's law):在途会话数 = 到达率 × 平均运行时长。

| | 1 万 API QPS,以读为主 | 每秒 10 万新轮次 |
| --- | --- | --- |
| 在途会话(运行 60 s) | 少 | ~600 万(600 万行租约) |
| 数据库语句/秒 | ~1–3 万 | ~100–500 万,以写为主 |
| 新增数据 | 少 | ~1–10 GB/s(每天 ~85–850 TB;假设每轮 10–100 KB) |
| 约束瓶颈 | 无 | 存储写吞吐与数据量 |

在 10 万规模下:OceanBase 且同分区;减少每轮语句数(即
`specs/2026-09-21-nested-fixed-loops/capacity.md` 中指出的重复全量读);对入站写做
微批;持久化分块或最终输出,而不是每个 token;L3 的保留与压缩变为必需;按压测结果
确定租户规格。这些数字是估算,不是实测。

## 3. 如何用实测替换估算

1. 用 `RecordingDb` 统计每个操作的语句数。
2. 对单节点连真实存储做压测(release 构建),找出拐点。
3. 按实测的语句组合对存储租户做压测。
4. 在负载下杀掉一个节点,测量再水合的波峰。
