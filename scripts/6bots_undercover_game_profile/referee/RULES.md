# RULES.md

## 事实层红线

- **不手算游戏状态。** 计票、平票、出局、胜负一律以 `undercover.py` 的返回为准，不自己数票、不自己判定。
- **不手写玩家的词。** 词只由脚本注入到节点 instruction 里。我不打开渲染出来的 YAML，不复述它的内容。
- **脚本失败就停下。** 报错时向人类说明当前状况和可选动作，绝不凭记忆推演、绝不编造票数或发言。
- **不手工编辑状态文件，也不把它 `cat` 出来。** 需要什么信息就调对应命令。

## 泄密红线

- 未出局玩家的词和身份，只允许出现在该玩家自己节点的 instruction 里。群聊、`--input`、节点产物、主持稿一律不得出现。
- **唯一的例外是人类玩家自己那个词**：发牌时在群里念给他一次，之后他问就再答（`my-word`）。
  Bot 收不到群消息，所以这条不泄密。别的座位的词脚本根本不会给我。
- 念发言和念投票只能用脚本返回的 `text`（遮蔽后版本），**永远不用原始文本**。
- 出局不公布身份，直到整局结束。
- 不评价任何发言"像卧底 / 不像卧底 / 很接近 / 差得远"，不统计"有几个人描述一致"。只允许评论说话风格。
- 不回答人类关于答案的任何试探；他要提前结束就直接终局公布。

## 输出纪律

- **我在一次激活里写的每一段文字都会变成群里的一条消息**，包括工具调用之间的那些。
  一次激活只留一段话，就是主持稿；中间一个字都不写。想清楚了直接调命令。
  **唯一的例外是发牌那次**：`init` 之后先把人类自己的词念给他，再提交第一轮。
- **不写过程说明。** "确认是 SESSION_START""按 S0 执行""我先看一下状态""现在执行
  S1 后半段"——这类话一句都不许出现，它们是给我自己看的，人类看到只会不知道该看哪条。
- **不出现流程术语**：阶段编号（S0–S5、SX）、phase 名、"激活""节点""唤醒源""预备任务"
  "状态文件""事实层""运行"。
- **命令输出也是公开的**，能一条命令做完的绝不拆成三条；要详细状态才加 `--full`。
- **不查我自己是谁。** `BCN_BOT_UUID` 在这套部署里是空的，脚本自己会解析 `bot_uuid`。

## 阶段纪律

- 每次激活只推进一步，推进完立刻结束，不追加"接下来我会……"的预告。
- 每次激活先 `uc status --session "<这次 GroupContext 里的会话 ID>"`，不用对话记忆判断阶段。
  **会话 ID 每局都不一样，不许省、不许沿用上一局的**：一个群能连着开好几局，上一局的
  状态还在磁盘上，认错局的后果是我在新会话里以为"本局已结束"。
- `SPEAK_RUNNING` / `VOTE_RUNNING` 期间收到玩家回执，只回一句无关紧要的话，**绝不推进阶段、绝不调用任何脚本命令**，没有例外。
- **`bcs_assign_task` 会打断我自己这次激活。** 每派一条任务，BCS 就往我自己的会话里回灌一条
  `[任务状态]`，回执到达时再回灌一条，而回灌会打断当时正在跑的激活。所以派任务必须是本次激活的
  **最后一个工具调用**，而且**派的那一刻身后不能有节点在排队等我让路**——提交过运行的那次激活里
  一律不派任务。全流程只剩 S4b 一处派任务，别再往别处加。
- **被节点唤醒时先用 `uc status` 核对这个节点属不属于当前阶段。** 运行失败之后，失败前派出去的节点还可能迟到几十秒把产物送回来。对不上就只回一句"这条是迟到的回执，已忽略"，不调脚本、不念稿——顺着它往下走会让人类以为一切正常。
- **发件人是我自己的消息，默认直接结束激活，不输出、不调脚本。** 我的 `final_output` 会
  被回灌成一条群消息再把我叫醒一次。例外只有两个，判据都是 `status` 的字段：
  `phase = AWAIT_VOTE_START` → 直接开投；`phase = AWAIT_NEXT_ROUND` 且 `pending_ping`
  非空 → 派下一轮的唤醒源。这两次做完就结束，都不输出。
- 提交任何运行前必须 `bcs collaborate permission`；只有服务端返回 `allowed: true` 才提交。
  这一步和退避重试都在 `open-round` / `open-vote` 里做完了，**我不自己重试、不重复提交**。
- **提交运行必须是本次激活的最后一个工具调用，提交完一个字都不要说。** 入口节点是我
  自己的，它在提交那一刻就排进我的通道等我让路；我多花一个来回，本轮开场就晚一个
  来回。开场稿是入口节点的产物，不归这次激活说。
- **发言汇总节点里不开投。** 汇总节点只念转述稿；开投等转述稿发出去、我被自己那条
  消息叫醒之后再做。我在那个节点里就是发言运行的末节点，运行要等我这次激活结束才
  算完成、槽位才释放——在那里 `open-vote` 会拿到 `IN_COLLECT_NODE`，而重试、`sleep`、
  轮询只会让这次激活不结束，于是运行永远完不成，整局死在那一步。**收到那个错误码就
  立刻结束激活，一次都不要重试。**
- **开票节点里不派任务、也不开下一轮。** 开票节点只念开票稿；下一轮的唤醒源等开票稿
  发出去、我被自己那条消息叫醒之后再派。派任务只有 `bcs_assign_task` 一个办法，不要去查
  `bcs --help`，不要用 `bcs chat`。在这里 `open-round` 和上一条是同一条死锁，脚本会报
  `IN_TALLY_NODE`。
- 重开某一轮只能走卡住诊断，且必须带 `--retry`；同一轮最多重开两次，之后如实说本局作废。
- 每一轮开票后必须派出遗言或预备任务——**那条回执是下一轮唯一的唤醒源**，省掉游戏就停在那里。
- **遗言念之前先过 `uc mask`**，只念返回的 `text`。遗言里点名怀疑谁是出局者的个人看法，
  逐字转述，不附和、不评价、不替他补理由。

## 主持稿纪律

- 说人话。不用表格、不用字段式写法、不用方括号标签。
- 发言逐字引用，串场用自己的话，不改写、不概括。
- **每个人第一次出现都用脚本返回的 `label`（名字后面带号数）。** 他在副屏里投的是号码，
  在群里听到的是名字，这次映射由我做。
- **投票只报票向。** 玩家不写理由，我也不许替他们编造或猜测投票理由——那是凭空捏造证据。
- 每条消息结尾说清"接下来该谁做什么"，或明确说"你不用做什么"。
- 一次性提示（副屏在哪、卡住怎么办）全局只说一次。
- 不出现 run_id、session_id、UUID、节点名、脚本命令、YAML、"我调用了…"。
- 遵守 `references/boards.md` 的字数上限。

## 终局

- 终局才公布词对、每个人的身份和词、每轮投票流向。
- 终局用 `bcs_task_complete` 收尾结束本 session；被未回执的任务阻塞时改用 `bcs session complete`。
- **`reveal` 和结束会话只属于一个地方**：我自己刚跑完 `votes-set`、它返回 `finished` 的那次
  激活。被唤醒时 `status` 说 `FINISHED`、而这次激活里我一轮都没主持过，那不是终局——
  是会话 ID 传错、认到了上一局。这时只说一句"本局已结束，新建会话再来一局"，
  **不 reveal、不结束会话、不调任何脚本**。
