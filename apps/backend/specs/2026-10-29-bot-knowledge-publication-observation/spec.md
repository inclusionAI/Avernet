# 服务 Bot 知识库开关的分版本尽力记录

## Summary
为服务 Bot 保留现有知识库开关，并提供草稿、预发、生产对应配置的后端查询能力。发布版本的配置记录是辅助展示信息，保存失败允许缺失，不影响 Bot 原有构建、发布或运行。

## Motivation
当前选择不能准确表达不同发布版本的知识库配置。用户希望区分各阶段的配置，但不接受为此扩大发布流程的事务、失败处理和运维负担；本功能替代尚未合入的强一致方案，不叠加两套实现。

## User Stories
- As a 服务 Bot 编辑者, I want 在草稿开启或关闭知识库并得到真实的保存结果, so that 我能准备下一版配置。
- As a 配置调用方, I want 查询预发或生产所对应版本记录的选择, so that 新草稿不会被误认为已发布配置。
- As a 服务 Bot 运维者, I want 辅助记录失败不改变原生发布结果, so that 不必为非关键展示数据排查发布故障。

## Acceptance Criteria
- [x] AC-01：草稿开关的权限、并发冲突、可编辑阶段限制和保存成功/失败反馈保持原有语义；个人 Bot 不受影响。
- [x] AC-02：发布版本构建时尝试记录当时的启用选择；后续修改草稿，不改写其他版本已记录的选择。
- [x] AC-03：预发与生产查询原生流程选定版本的记录；同一版本从预发到生产不要求再次保存知识库配置。
- [x] AC-04：记录存在不代表部署成功；构建中、部署中、失败版本不能因有记录被宣称为已生效版本。
- [x] AC-05：明确记录的空选择表示全部关闭；记录缺失、无效或读取失败不冒充全部关闭，也不回退读取最新草稿。
- [x] AC-06：辅助记录的读取、保存或解析失败不改变原生发布状态、任务结果或回滚行为；可通过关联版本的日志定位失败。
- [x] AC-07：查询保留当前 Bot 访问权限及租户、环境、空间隔离；不可因知道版本标识读取其他 Bot 的配置。
- [x] AC-08：原生回滚选中历史版本时可读取该版本已有记录；没有可信记录则返回未记录，不回填、不自动恢复草稿勾选。
- [x] AC-09：重试不要求辅助记录成功；同一发布版本重新构建时可更新最近记录，保存失败允许保留上次记录及采集时间，但不得宣称与本次构建或实际文件严格一致。
- [x] AC-10：原有知识库使用指引、文件交付及访问授权行为保持不变；记录不承诺与运行文件原子一致，不作为运行时控制依据。

## In Scope
- 当前草稿选择与发布版本最近成功记录的查询、区分及兼容性。
- 构建过程中的尽力记录、故障隔离、权限检查和针对性验证。
- 后端接口与接入说明；调用方沿用原生版本选择结果。

## Out of Scope
- 新增前端页面、运行时授权或检索消费逻辑。
- 修改原生发布状态机、共享发布事务、成功判定、文件同步或恢复流程。
- 生产选择的重复维护、历史回填、自动补偿、专用重试、对账和后台任务体系。
- 自动恢复草稿选择、数据迁移、部署、合并以及修改旧 PR。

## Open Questions
- 无阻塞性产品问题。本版将同一版本重建后保存失败定义为允许保留带时间的上次成功记录，不承诺逐次构建强一致；此取舍已在统一 review 后由用户确认。数据库等待与真实部署环境未验收边界已在 verification.md 明确，不宣称硬超时或线上验收。
