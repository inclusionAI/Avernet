# 治理：门禁、安全与发布

> English version: [08-governance.md](08-governance.md)

> 状态：DRAFT（讨论稿）。拟议决策：
> [DR-2](decisions/0002-promotion-is-platform-owned.zh-CN.md)。

让改进者自己给自己打分的自改进，就是规模化的自欺。文献在这一点上结论一致
（DGM 删除了自己的幻觉标记；自评分的 Hermes 循环过于宽松；由 LLM 编写的
skill 若没有评估引导的修订往往毫无增益；harness 进化带来的收益在与预算匹配
的基线对比时常常消失）。本文档列出无论运行哪种进化策略（Strategy）都能让平台
值得信赖的规则。

## 1. 权力分离

| 权力 | 持有者 | 永不由谁持有 |
| --- | --- | --- |
| 提议变更 | 进化策略（通过提交候选）、被改进 Bot（收件箱） | — |
| 选择在某个 Bot 上运行哪些进化策略、它们可以改什么，以及验证有多严格 | **所有者 / 租户管理员**（绑定） | 进化策略、Bot |
| 定义什么绝不能变差 | **平台 + 所有者**（回归集、安全集、封存集（holdout）；平台底线（platform floor）） | 进化策略、Bot |
| 执行评估 | **平台**（验证服务（Verification Service），使用验证器所属的执行器与评分器） | 进化策略 |
| 修改验证器（用例集、评分器、profile、协议、阈值） | **人类**，通过经评审的变更（[03-verification.zh-CN.md §7](03-verification.zh-CN.md#7-验证器完整性)） | 任何自动化循环，包括第 3 层 |
| 采纳新的改进机制（第 3 层） | 平台机制门禁 + 人工批准 | 元策略 |
| 决定晋升 | **平台门禁** + 按风险等级由所有者/评审者决定 | 进化策略、Bot |
| 修改锁定基因 / 策略 | 所有者、租户管理员 | 进化策略、Bot |

## 2. 门禁

候选（Candidate）只有在以下**全部**通过时才可晋升：

1. **静态底线** —— schema 合法；base 匹配；未触碰任何锁定基因或钉住项；
   未引入密钥/PII（与 pre-push hook 相同的扫描规则）；满足大小与重写阈值；
   除非对应基因已解锁，否则不得新增出站 URL 或 MCP server。
2. **回归底线** —— 在 Bot 的 `regression` 与 `safety` 用例集上，候选相对
   父版本的退化不超过容差（默认：`safety` 上新增失败用例为零，
   `regression` 上 ≤ 1 且需评审）。
3. **验证判定** —— 在绑定的验证配置下，`validation` 上的判定为 `accept`
   （[03-verification.zh-CN.md §4](03-verification.zh-CN.md#4-bot-验证协议第-2-层)）。
4. **封存集检查** —— 定期（而非每次迭代，以免通过选择过程泄露封存集）在
   `holdout` 上为已晋升的修订版打分；若分数下降，则开立事件并阻止该 Bot 后续
   的自动晋升。
5. **预算匹配基线**（对单个进化策略可选，对平台发布的进化策略强制）——
   候选必须在同等成本下胜过「父版本加额外采样」。
6. **风险等级审批**（§3）。

## 3. 风险等级

按补丁操作分配；一个补丁取其所有操作中的最高等级。

| 等级 | 示例 | 默认晋升方式 |
| --- | --- | --- |
| **T0** | 仅注解 | 自动 |
| **T1** | 记忆条目新增/退役；skill 描述微调；resource 内容更新 | 门禁通过且所有者策略允许时自动 |
| **T2** | 人设编辑（SOUL/AGENTS/RULES）；skill 新增/更新；允许列表内的 `engine_config`；任何带 `rewrite` 标记的编辑 | 人工评审（所有者或其代理人）；所有者可按进化策略将自动上限提高到 T2 |
| **T3** | MCP/CLI 工具变更、script、记忆 `replace` 模式、权限、`policy` 中的任何内容 | 默认锁定；解锁后始终需人工评审，绝不自动 |

## 4. 反奖励投机规则

- 评估器、评分器、用例集及其配置位于基因组**之外**，对进化策略和 Bot 只读。
- 进化策略永远看不到验证集的逐用例细节（仅提供汇总）、封存集、回归集或安全集
  用例（即 ClawEvolve 的评审防火墙，经过泛化并由 `StrategyContext` 强制执行，
  而非依靠 prompt）。
- 差异审计：提及或编辑类护栏文本（安全章节、拒绝策略、日志/上报指令）的补丁
  会被打标并提升到 T2 及以上。
- 在可行的情况下，评审模型应来自与进化策略所用模型不同的模型家族；T2 晋升需使用多个
  评分器。
- 按修订版跟踪成本与长度；仅靠花费更多而胜出的候选会被如实报告。
- 定期在新用例上重新审计已晋升的谱系。

## 5. 沙箱

- 进化策略和评估器只在**沙箱物化实例**上工作（通过 `eval_env` 创建的评测 Bot，
  或临时工作区）。不使用生产凭据，也无法访问线上表型。
- 每个进化策略声明它 `needs` 的目录能力及其运行时隔离（R13）；它的上下文不授予
  其他任何东西，并且除非另行声明并获批准，编排器只允许出站网络访问模型提供方。
- 经验是**不可信输入**（提示注入与记忆投毒的载体）。进化策略必须把片段
  （episode）文本当作数据处理；由其派生的补丁要经过密钥/PII/URL 扫描；
  被改进 Bot 提交到收件箱的内容受速率限制。

## 6. 发布与回滚

- **影子**（可选）：候选在镜像流量或重放的片段上运行，离线评分。对于服务型
  Bot，这对应现有的 verify 阶段。
- **金丝雀**（多实例 Bot）：部分实例使用 `canary` 引用；在线指标（任务成功
  率、用户反馈、错误率、成本）与 `active` 对比；按策略可选启用自动回滚规则。
- **晋升**：移动 `active`，设置 `previous`，通过 Manifest / 发布链应用；在
  apply 报告上记录 `revision_id`。
- **回退**：再次晋升一个更早的修订版（`avn genome promote
  --revision r41`）。这是一次普通的、留有审计的晋升：对服务型 Bot 而言，它通过
  现有的发布流程作为下一个版本发布。不涉及现有的服务型 Bot 回滚功能。
- **永不删除**：被拒绝和已退役的修订版会被归档。

## 7. 数据处理

- 经验库按租户设置保留期；摄入时对密钥脱敏；PII 策略可配置；只有在租户明确
  选择加入后才可导出用于训练。
- 默认禁止跨租户使用经验或进化策略学到的产物。
- 跨 Bot 的 skill 迁移（P6）须经过 Skill Center 治理（ADR 0010：Skill
  Center 负责分发，写入权仍归管理源所有），并针对每个使用方 Bot 重新评估。

## 8. 预算与熔断开关

- 每次运行：token、USD、墙钟时间、rollout 次数、迭代次数 —— 由编排器强制
  执行，并在运行上报告。
- 每个 Bot / 每个租户：日上限与月上限；每日最大晋升次数。
- 升级处理：连续 N 次迭代被拒绝 ⇒ 停止运行并通知所有者。
- 熔断开关：按进化策略（全局禁用该策略）、按 Bot（冻结进化，保留 `active`）、
  全局（暂停编排器）。

## 9. 审计

每个修订版、门禁决定、审批、晋升和回滚都是一条只追加事件，包含执行者、主体
类型、原因，以及指向证据和评估结果的链接。归档读模型就是审计 UI。
