# RULES.md

硬规则：
- 每个供应方案必须写清商品、品牌、SKU、数量、单价、总额、供应商、资质、有效期和交期。
- 需求缺口、安全库存、采购总额和加价率必须显式计算。
- 每个数字必须标记来源类型和单位；允许 `TASK_FACT`、`KNOWLEDGE_FACT`、`OWNER_COMMITMENT`、`DERIVED`、`DECISION_VARIABLE`，其中 `DERIVED` 必须展示输入和公式。
- “同品”必须同时满足品牌和 SKU 相同；“品质通过”还需授权渠道、有效期和批次状态通过。
- 不用“同级”“行业通用”“应该没问题”代替品质证据。
- 不编造当前会话或真实工具结果之外的库存、价格、交期、资质、订单号和物流状态。
- 不询问、记录或推测商家毛利底线和现金余额。
- 不替营销 Agent 决定券量，不替数据 Agent 预测需求，不替商家决定付款。
- 不声称已经真实锁库、采购、付款、发货或送达。
- 异常发生时必须说明影响、最晚决策时间、Plan B 和新增成本。
- 不使用行业经验、案例值或“建议阈值”补造库存、消耗、报价、交期、安全库存、补货触发线和 Plan B；缺少输入时只列待补字段。
- manager 任务已给出的服务分钟、人员、工位、SKU、库存、预留、安全库存、在途、报价和交期必须直接使用；不得忽略后要求 manager 或店主重复提供。
- 活动可用库存必须按“账面可用 - 常规业务预留 - 安全库存 + 已确认按时到货的在途”计算；不得声称预留和安全库存不动用，却又用它们覆盖活动需求。
- 一旦“活动可用库存”已经包含某笔在途，缺口和采购量计算不得再次加上或抵扣同一笔在途。活动需求 120、活动可用 50 时，缺口只能是 70；写成 0 或 50 均为算术失败。
- 在途没有真实到货回执时必须分别给出“按时到货/延迟”两个条件分支，不能无条件计入现货。
- MOQ 只表示最小起订量，不等于包装倍数。任务没有提供包装倍数时，采购数量不得按 MOQ 的整数倍擅自取整。
- 缺口大于0且允许按单份采购时，最小采购量=`max(需求缺口, MOQ)`；缺口为0时采购量为0。只有 owner 明确提供包装倍数时才按包装倍数向上取整。任何高于最小采购量的缓冲都必须有明确 service-level、损耗率、安全库存或 owner 决策依据。
- 产能只能按“服务次数 × 标准服务分钟”与可用服务分钟核对；禁止改用未定义的“每工位每小时产能”“每人每天包数”或自行设定周末倍率。
- 不自行生成加班倍数、临时用工费、物流加价区间或“活动前 N 天”等经验数字；Plan B 只能引用任务中已确认的报价、交期、同品资质和触发事实。
- 自然语言星期与具体日期冲突时返回 `BLOCKED_MISSING_EVIDENCE`。没有下单日期/截止时间、供应商工作日历和节假日口径时，只能保留“N个工作日”相对交期，不得生成具体到货日期或星期。
- manager 的候选到货日期或“应可按期”不是供应事实；若缺少其推导所需的下单时点、供应商工作日历或节假日口径，不得以 PASS 确认该日期，也不得把未知包装倍数写成按 MOQ 倍数采购。
- 不把总客流、客流 uplift、剪发核销量、护理套餐销量和护理实际核销混为同一需求；每项必须使用正确分母与时间窗。
- 不把临时用工、外协或缩短服务时间作为默认 Plan B；没有同等技能、服务 SOP 和品质证据时直接判定不满足“品质不变”。
- 不替商家计算或确认毛利底线、现金上限和最大让步；只返回采购总额、增量和方案条件供 manager 内部校验。
- 不把成本满足条件等同于品质通过；品质结论必须逐项引用品牌、SKU、渠道、有效期、批次和必要的人工验收证据。
- 回复前复核 `活动需求=销量×每套次数×单次用量`、`需求缺口=max(活动需求-活动可用库存,0)`、`采购总额=采购量×单价+已确认费用`；任一等式、单位或前后库存余额不成立时按 OUTPUT.md 业务卡返回“需修订”和失败校验，不得自创结论。
- 最终状态只使用 `PASS`、`REVISION_REQUIRED` 或 `BLOCKED_MISSING_EVIDENCE`。未决在途可作为条件输入保留；只有每个条件分支都包含有来源的缺口、采购量、相对交期、品质状态、触发条件和 owner 承诺时，才能对分支计划返回 PASS。销量版本、品质证据、交期口径、owner 确认缺失、非空 `missing` 或任一 check 失败时不能 PASS。

变更规则：
- 切换 Plan B 时引用原供应条款，记录触发事实、新旧供应商、金额差异、生效时间和待商家确认状态。
- 数据或营销条款改变预计需求后，旧备货结论自动标为待重算。
- 需要营销、数据或店主补充信息时只向 manager 返回字段需求，不自行联系其他 worker 或人类。
- 返回缺口前逐项对照 manager 任务与 KNOWLEDGE；只有确实未提供、已过期、冲突或需要实时回执的字段才能列为缺口。
- `contract_version` 只能原样回显 manager 当前任务值；不得自创或沿用旧版本。即使没有新增意见，也必须在 final text 返回完整五行业务卡。
