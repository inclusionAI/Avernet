# AI 使用策略报告（#2609，壹贰队）

本队只有一名成员。本任务的设计、实现、测试和文档都大量使用了 AI 编码代理。本文记录用了哪些工具、怎样分工、怎样核实 AI 的产出，以及 AI 实际犯过、后来被抓到的错误。

## 1. 工具与分工

| 角色 | 工具 | 负责 |
| --- | --- | --- |
| 成员（刘顺洋） | — | 认领与范围；对照 issue 原文和维护者答复拍板设计取舍；决定提交什么、怎么拆 PR；所有对外发布（issue 评论、push、PR）由本人操作 |
| 主代理 | Claude Code（Claude Opus） | 读源码定位信道；起草方案、RFC、威胁模型、复盘；panel 副屏改动；按评审意见修复；跑测试和 singlebox 实测；整合各分支 |
| 协作代理 | codex CLI（gpt-6-astra，reasoning effort xhigh） | BCS 服务端两个 commit（HumanInput 绑定人类、GC 只读入口）；referee 多人改造的首版；对方案和每轮修复做对抗式评审 |

两个代理互不信任对方的结论：codex 的实现由 Claude Code 对照源码复核、跑测试后才提交；Claude Code 的修复和文档交给 codex 复审。成员只采纳能落到源码行号、测试结果或实测记录上的结论。

## 2. 使用规则

1. **范围以 issue 原文为准。** 每次会话开始先用本地脚本抓取 issue 最新内容，有维护者新评论就先读。设计取舍回到原文和维护者答复核对，不以 AI 写的摘要为依据。
2. **权限最小化。** codex 评审一律在只读沙箱（`-s read-only`）里运行，需要跑测试时自己复制仓库到临时目录；只有实现任务才给工作区写权限，并限定可改目录（例如 referee 任务明确禁止改 panel、BCS crates、宿主前端）。BCS 改动放在独立 git worktree，与 profile/panel 分开。
3. **AI 不对外发布。** AI 只做本地 commit，不 push、不开 PR、不在 issue 评论，这些都由成员本人确认后操作。
4. **不把密钥交给 AI 输出。** 模型网关地址、密钥只放在被 `.gitignore` 忽略的 `singlebox/.env.local`，AI 读取时只检查变量是否存在，不回显值；仓库内的 pre-push 钩子另外扫描明文凭证。
5. **结论按证据强度标注。** RFC、威胁模型里每条断言注明证据类型：基线实测、集成实测、单元测试或源码阅读。没有实测支撑的不写"已修复""已隔离"，例如直接调接口读票，文档里只写成已知限制。
6. **每轮修复都要再评审。** 修复提交前交 codex 定向复审，复审给出可复现的反例就继续修，直到复审结论为"可以提交"。

## 3. 评审过程

| 轮次 | 对象 | 结论（摘要） |
| --- | --- | --- |
| 方案评审 | 隔离方案 v0.2 | 6/10。指出 nextgen 网关下缺 GC 路由、GC 返回 200 不等于取到本人词条、不能宣称完整服务端隔离 |
| 终审 | 首版 5 个 commit | 两处流程阻断（`{{bcs.run_id}}` 不展开、遗言依赖历史接口拿不到的任务回执）+ 偷看脚本只看第一页等 |

## 4. AI 犯过、后来被抓到的错误

| 错误 | 谁犯的 | 怎么发现的 | 处理 |
| --- | --- | --- | --- |
| 节点指令写 `--run-id '{{bcs.run_id}}'`，以为会被展开 | 实现首版 | codex 终审指出；第一局实战复现（collect 两次 `STALE_RUN`、整轮超时） | `--run-id` 改可选；多人局必须带齐 round/stage/attempt；T8 降为"部分处置"，开放问题 Q6 |
| 遗言改走历史接口，但该接口不返回任务回执 | 实现首版 | codex 终审 | 遗言回到原 `mask` 链路 |
| 偷看脚本只读第一页，命中也退出 0 | Claude Code | codex 终审 | 读全量历史、命中非零退出，之后 6 轮持续收紧解码与退出码 |
| 副屏取词字段拼错（`scope_level`）、不校验座位、失败后允许盲发言 | Claude Code | codex 终审 | 修复并加 panel 测试 |
| 文档把意图写成事实（"已处置""全部无词"） | Claude Code | codex 终审 | 按证据类型逐条改写 |
| 以为"关闭 thinking"能让慢模型变快 | Claude Code | 实测：关闭后同一请求仍把输出 token 全用于推理 | 3 人类局改为换模型重跑，不把超时归因于代码 |
| 离线重扫时把整段响应当一个字符串扫，第 3 局 111 条记录报"扫描不完整" | Claude Code | 扫描器失败即拒绝，拒绝给出无泄露结论 | 改成与在线测试一致：先解析 JSON 再扫字符串叶子；三份记录重扫均无不完整 |
| 用 `pkill -f` 结束代打脚本时把外层 shell 一起中断，显示的退出码 1 容易被误读为泄露 | Claude Code | 核对脚本自身输出（stderr 为空、收尾行正常） | 复盘如实写明；之后按进程号只对 Python 进程发信号 |

这些错误都没有进入对外提交。其中前两条只靠单元测试抓不到，是真实对局暴露出来的，所以验收以真实对局为准。

## 5. 没有交给 AI 的事

- 与维护者沟通和对设计方向的最终取舍（例如不引入 `sealed_output`、票面由前端在 `tally` 后展示）。
- 是否扩大改动范围：BCS 改动按 issue 要求先在 RFC 提出，等维护者确认后单独提 PR。

## 6. 对局中谁在操作"人类"席位

如实说明：
- 第 1 局（2 人类 + 3 Bot）：admin 席位的宿主界面和副屏由 Claude Code 通过浏览器自动化操作；bob 席位由 `tests/e2e/scripted_human.py` 代打。
- 第 2 局（3 人类 + 3 Bot）：admin 和 Bob 两块副屏都由 Claude Code 通过浏览器自动化操作，两者分属两套前端、两个认证身份；Carol 由脚本代打。
- 第 3 局（4 人类 + 3 Bot）：admin 和 Bob 同第 2 局；Carol、Dave 由脚本代打。

这些对局验证的是信道与鉴权：每个身份只能读到自己的私词，待办里只出现、也只能提交绑定给自己的节点。它们不证明其他信道已隔离：默认 Full 视图下，计票前的原始票面和主持人 `mask` 调用参数里的遗言原文对其他人类可读（已知限制 L1、T12），直接调接口读票同样是已知限制。对局验证的也不是玩家水平。每份复盘日志都写明各席位由谁操作。演示视频计划由真人分别操作两块副屏。

## 7. 局限

- AI 评审只能发现它构造得出反例的问题。偷看脚本的解码范围有明确边界（不处理 base64、URL 编码、压缩），文档已声明。
- 两个代理都可能对同一处源码产生相同的误读。关键结论（GC 人类间隔离、HumanInput 绑定、Participant 视图过滤）都用 singlebox 真实请求复核过，不只依赖源码阅读。
