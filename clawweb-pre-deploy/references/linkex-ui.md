# LinkEX 页面速查

## CI / 合并前 CI

目标表头：

- `PR 标题 / 状态`
- `分支`
- `Commit`
- `提交人/提交时间`
- `最新流水线状态`

终态：

- 可继续：PR `已合并` + 流水线`成功`
- 等待：`待合并`、`运行`、`排队`
- 停止：`失败`、`取消`、关闭

刷新很重要：打开较久的标签页可能显示旧的 PR 状态。

## 持续交付 / 构建交付物

入口按钮：`构建交付物`

弹窗文案：`选择集成分支后，将基于集成分支构建交付物`。默认分支应显示`master`。只有点击弹窗`确定`才开始构建。

## 构建流水线

目标表头：

- `运行状态`
- `序号`
- `分支/Commit`
- `触发方式/触发人`
- `触发时间/耗时`

从成功行记录：

- 流水线编号，如 `#699614634`
- master Commit，如 `5d0ff587`
- 提交说明中的 `PullRequest: 179`

## 交付物

目标表头：

- `交付物版本号`
- `分支/Commit`
- `交付物状态`
- `交付物来源`
- `构建人/构建时间`
- `操作`

不要用“最新行”代替版本校验。示例中旧交付物 `b43dd039 / PR 177` 和新交付物 `5d0ff587 / PR 179` 同时处于`待验证`，只有后者允许部署。

预发按钮可能出现嵌套 button，语义定位返回两个同名元素时，先限定目标 row，再使用可见的第一个按钮并立即检查确认弹窗。

## 验证流水线

预发确认文案：

- `确定要执行预发部署吗？`
- `执行此操作后，将触发「预发部署流水线」。`

触发后在`验证流水线`中按交付物版本/Commit 锁定新行，等待状态从`运行`变为`成功`。不要用其他人的更新流水线判断自己的部署结果。
