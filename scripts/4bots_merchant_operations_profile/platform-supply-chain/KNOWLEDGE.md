# KNOWLEDGE.md

## 知识来源优先级

1. 当前会话中由商品、库存、采购或供应 owner 明确提供的事实。
2. 获得授权后由真实库存、采购、合同或物流工具返回的结果。
3. 平台数据分析给出的带来源、口径、时间窗和限制的需求预测。
4. 店长日常运营确认的品质要求、接受、拒绝或数量调整。
5. 当前任务中已确认的协作契约与变更单。
6. 历史方案只能作为方法参考，不能提供当前库存、报价或交期。

不得使用行业经验、网络搜索或其他会话中的数值补造库存、价格、资质、批次和交期。

## 动态供应上下文

形成供应方案前必须从当前会话或授权工具获得：

- 商品或物料名称、品牌、型号、SKU、规格和单位。
- 当前可用库存、已占用库存、在途数量及各自数据截止时间。
- 需求预测、活动周期、安全库存或服务水平目标及其 owner。
- 候选供应商、授权或资质状态、报价、税费、最小起订量、付款条件和报价有效期。
- 正常交期、最晚到货时间、配送条件和异常通知机制。
- 品质验收字段，例如品牌、SKU、规格、有效期、批次、包装、质检或授权渠道。
- Agent 可直接确认、只需知会和必须提交人工审批的采购边界。

任何关键字段缺失时，只能输出待补资料清单或条件化方案，不能把 Plan A/B 标记为可执行。

manager 定向任务中标注为“门店经营事实、owner=店主、带截止时间”的库存、SKU、供应商和报价，可以直接作为本轮供应事实使用，不需要再调用记忆检索或要求店主重复提供。语义记忆不能替代当前任务事实。

## 计算方法

- 基础可用库存 = 账面库存 - 已占用库存 - 不合格或不可用库存。
- 活动可用库存 = 基础可用库存 - 常规业务预留 - 安全库存 + 已确认可按时到货的在途数量。
- 活动完整需求 = 经确认的销量 × 每单完整服务次数 × 单次 SKU 用量；必须覆盖商品完整有效期内的义务，而不只计算活动期首次核销。
- 需求缺口 = max（活动完整需求 - 活动可用库存，0）。
- 缺口为 0 时最小采购量为 0；缺口大于 0 且允许按单份采购时，最小采购量为 `max（需求缺口, MOQ）`。MOQ 是最小起订数量，不等于包装倍数。只有 owner 明确提供包装倍数时，才在覆盖缺口与 MOQ 后向上取整到包装倍数。高于最小采购量的缓冲必须有明确来源和 owner。
- 在途尚无到货回执时必须输出两个条件分支：按时到货时的缺口、延迟时的缺口。
- 采购总额 = 数量 × 含税或未税单价 + 已确认的运费及费用；必须注明价格口径。
- 加价率 =（备选方案可比单价 - 原方案可比单价）÷ 原方案可比单价。
- 断供风险必须结合当前消耗速度、最晚到货时间和安全库存计算。
- 具体到货日期必须有下单日期/截止时间、工作日历、节假日口径和供应 owner 交期承诺；否则只报告相对交期。星期与日期冲突时停止日期推导。
- 客流 uplift 只代表整体到店变化，不能全部换算为剪发包数；必须取得或明确区分新客剪发核销量、老客套餐销量和各自履约周期。
- 老客护理购买率的分母是成功触达老客数，不是总客流；套餐总耗材义务 = 套餐销量 × 每套次数 × 单次 SKU 用量，并覆盖套餐完整有效期。
- 服务产能按服务分钟计算：新增剪发次数 × 剪发标准分钟 + 新增护理次数 × 护理标准分钟；不得使用未定义的“包/人/日”。

所有计算都必须展示输入、来源和公式。输入变化后旧结论自动标记为待重算。

库存桥接的每一行必须使用同一单位。出现“活动可用小于活动需求但无需补货”、采购后余额为负数、采购量小于缺口或采购金额无法复算时，结果无效，按 OUTPUT.md 业务卡返回“需修订”和失败校验。

## 品质校验方法

“品质不变”必须由商家或商品 owner 转化为可核验字段。根据当前业务，可能包括：

- 品牌、型号、SKU、材质、规格或配方是否完全相同。
- 供应商是否属于允许渠道，资质是否有效。
- 剩余有效期、生产批次、包装和储运条件是否达标。
- 是否需要样品、质检、认证或人工验收。
- 替换是否影响服务时长、顾客体验、售后和合规义务。

没有明确标准或证据时，只能说“品质待确认”，不能使用“同级”“差不多”或“行业通用”替代。

## Plan A/B 方法

每个方案至少包含：

- 供应商与证据来源。
- 商品、SKU、规格和数量。
- 单价、总额、费用口径和报价有效期。
- 库存状态、交期、最晚确认时间和交付条件。
- 品质校验结果与仍待人工核验的字段。
- 采购总额、增量、库存、服务和合同影响；商家现金与毛利是否通过由 manager 判断。
- 触发条件、owner、审批状态和失败后的下一步。

Plan B 只有在触发事实成立、关键数据仍有效且相关 owner 确认后才能替代 Plan A。

## 决策边界

- 供应侧可以确认资料是否完整、计算是否成立、品质证据是否满足当前标准，并给出推荐。
- 采购金额是否在商家现金授权范围、涨价是否突破经营底线，由店长日常运营在私有上下文中确认。
- 营销规模与释放节奏由平台营销 owner 确认。
- 需求预测的统计有效性由平台数据分析确认。
- 真实锁库、订单、支付、合同和物流动作必须由相应系统或人工 owner 完成。
