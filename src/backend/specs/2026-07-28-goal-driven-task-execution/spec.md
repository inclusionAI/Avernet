## 1. 概述

### 1.1 背景

ocb 是多 bot AI 工作台,支持 bot 生命周期管理、多 bot 协作(BCS)、聊天会话。当前缺少一个把"用户提的真实需求"驱动成"目标 → 拆解 → 搜推执行方 → 执行 → 验收 → 交付"闭环的能力:**任务不靠人手编排 step,而是由系统围绕目标自动维护一张动态生长的执行图谱,按需拉单 bot / 协作群 / 上升 BBS 完成子任务,验收不过自动重规划,全程对用户透明**。

### 1.2 这是什么

一个**目标驱动、Bot 执行、loop 推进**的任务执行系统。系统持有任务的目标契约(目标/交付物/验收标准/约束)与执行状态图谱(DAG),由 loop 推进:拓扑序解锁子节点 → 搜推能搞定的执行方 → 派发 → 收回投 → 验收 → 全局终验 → 交付。执行方分三模态(单 bot / 协作群 / BBS),其中协作群再分三种协作模式(自由聊天 / 主从 / 自定义协作 yaml workflow)。TaskScheduler 做 deepresearch 动态编排(路由/拆解/重规划/派发);状态判断与验收由 owner bot 经 SKILL 自判后回投上报;状态唯一写口在 TaskService(校验状态机合法性)。

**副屏动态 workflow 可视化是该系统的一等能力**:需求端到端执行流程在副屏以动态 DAG 呈现,DAG 随 deepresearch 拆解/重规划动态生长与重构(区别于自定义协作群"执行流固化"的 workflow)。任务为一等公民,不同执行模态(单 bot / 协作群 / BBS)默认以节点形式在 workflow 中呈现;协作群节点支持下钻展开群内具体执行 DAG;同时向下兼容并 cover 现有自定义协作群 workflow 画布(自定义协作群即"workflow 已固化"的特例)。整体生命周期的执行状态都在副屏可视化,节点支持查看执行详情。

### 1.3 为什么是现在

- 多 bot 协作(BCS)、bot 生命周期、聊天会话等基建已就绪,在其上叠加目标驱动 loop 的条件成熟。
- 现有协作群 workflow 是"执行流固化"形态,无法承载"目标驱动、运行期动态拆解/重规划"的需求;需要一套以任务为一等公民、DAG 动态生长的执行系统补齐能力。
- 验收链路(owner bot vs 后端服务验收)需统一口径,避免状态双写。

本 spec 作为后续落地的正式 WHAT/WHY 基线。

## 2. 问题与目标

### 2.1 要解决的问题

1. **目标驱动而非步骤驱动**:用户只给目标,系统自己拆、自己派、自己验,不让人手填执行步骤。
2. **执行方动态组配**:子任务需要谁,系统按需搜推;单 bot 不够就拉群,群内协作方式随子任务而定(头脑风暴 / 主从派活 / 固化流程)。
3. **验收自动闭环**:每个子任务交付前由系统侧验收,不过就重规划,最终全局终验才交付。
4. **deepresearch 式兜底**:搜推不到能搞定的执行方 → 拆解子任务;全局终验仍不过 → 人工确权后上升 BBS 续做。
5. **可审计、可重放**:状态变更走事件,不绕过回投通道,避免状态双写双轨。

### 2.2 目标

| 目标 | 含义 |
|---|---|
| **G1 系统化规格基线** | 内外一致、去重、可对外评审的系统化 spec 集 |
| **G2 统一口径** | 服务/聚合/验收链路/编排归属等关键口径定于一版,plan 以下不歧义 |
| **G3 明边界** | 落点域、跨模块依赖、本期范围与后续待定分清 |
| **G4 可落地** | 四件套可直接驱动后续 tasks 落具体文档/代码骨架 |
| **G5 副屏可视化一等化** | 副屏动态 workflow(动态 DAG / 多模态节点 / 下钻 / 节点详情 / 全生命周期)从附注提升为一等需求维度;且向下 cover 现有自定义协作群 workflow 画布的全部信息 |

### 2.3 非目标

- 不在本期实现 BBS 的 BCN 广场机制(BBS 作为"任务级上升兜底"接入,承载方式另系分)。
- 不重写 ocb 现有 bot 生命周期 / 会话 / BCS 协作基建,只在其上叠加目标驱动 loop。
- 不做纯产品规格(交互稿与产品文档见语雀);本 spec 是技术系分的需求面。

| 角色 | 关注点 |

## 4. 需求列表

> FR = 功能需求,NFR = 非功能需求。技术实现(具体 service 名、Protocol 签名、数据结构、落点四层)见 `plan.md`。

### 4.1 任务建模(FR-TASK)

- **FR-TASK-01** 任务持有"5 要素渐进式契约":目标(objective + 验收标准)、交付物、约束、执行(可选,渐进式),创建时可不完整,执行中可补充。
- **FR-TASK-02** 任务状态机 7 态:草稿(DRAFTING)→ 计划冻结(DEFINED)→ 执行(EXECUTING)→ 验收(REVIEWING)→ 交付(DONE);含取消(CANCELLED)、失败(FAILED)终态。要素补全期留 DRAFTING;验收不过可返工回 EXECUTING。
- **FR-TASK-03** 任务目标可被结构化拆解为带依赖关系的子任务集合(图),拆解需覆盖全部验收标准且置信度达标,否则回退澄清。
- **FR-TASK-04** 执行图谱是动态生长的 DAG:运行期可加兄弟节点(拆解)、可同节点重路由(重规划),节点身份在重路由中保持不变。
- **FR-TASK-05** 任一节点用三种执行模态之一执行:单 bot / 协作群 / BBS;模态是节点标签,图谱逻辑对三模态同构。

### 4.2 执行方组配(FR-DISPATCH)

- **FR-DISPATCH-01** 系统能按子任务需求搜推执行方,并判定单点可完成 / 多点拼合可完成 / 当前不可完成。
- **FR-DISPATCH-02** 路由分流:用户指定优先;无指定时由搜推结果决定(单 bot / 已有群 / 临时拉群)。
- **FR-DISPATCH-03** 动态拉群时,系统据子任务需求与上下文在其协作群的三种协作模式间选择(自由聊天 / 主从协作 / 自定义协作)。
- **FR-DISPATCH-04** 当子任务执行流可固化为有序步骤且角色可静态绑定时,系统能将其自动编译为自定义协作模式所需的 workflow 定义并在建群时注入;注入后执行由协作群自闭环完成,本系统只收终态。
- **FR-DISPATCH-05** 协作模式选定置信度不足时降级到稳健默认,不阻断。
- **FR-DISPATCH-06** 搜推当前不可完成时,系统先尝试运行期拆解;原子不可拆或重拆超限则留待全局终验。

### 4.3 验收(FR-ACCEPT)

- **FR-ACCEPT-01** 子任务级验收由 owner bot 经 SKILL 完成(非后端服务自行判定):双轨(structured 断言 + effects 状态 delta),LLM 兜底,置信度不足打断用户。
- **FR-ACCEPT-02** 验收结果分通过 / 部分 / 不过;通过节点完成,部分触发同节点重路由,不过(执行报错)在有限次内同执行方重试后转重路由。
- **FR-ACCEPT-03** 全局终验:全部节点完成后由 owner bot 经判断完成 SKILL 对原目标逐验收标准复核,回投 `GOAL_VERIFIED`;过则交付,不过上升人工门(BBS)。
- **FR-ACCEPT-04** 验收证据与产出物引用落图谱节点;产出实体(代码/文档/PR)存于外部仓库,图谱只持引用。

### 4.4 重规划与兜底(FR-LOOP)

- **FR-LOOP-01** deepresearch 两类 loop:① 搜推不可完成 → 拆解补兄弟(loop 任务拆解);② 子任务验收不过 → 同节点带上下文重路由(loop 搜推执行)。两者均为有界重试,超限不再扩张。
- **FR-LOOP-02** 全局终验不过,经人工确权(隐私确认)后上升 BBS;BBS 在任务内部续做未完成子任务,有界执行,完成回填进度。
- **FR-LOOP-03** BBS 续做完成 → 交付(DONE);BBS 续做仍不过 → 任务失败终态(FAILED),不再回环 / 不再重试 / 不再上升。
- **FR-LOOP-04** loop 有终止性兜底:轮次上限 / 连续无进展强制终验,防止空转。

### 4.5 回投与状态一致(FR-EVENT)

- **FR-EVENT-01** 单 bot / 协作群 / BBS 的完成、进度、验收、终验事件统一经后端回投通道回流(run_mode 区分);执行方/owner-bot 不直接改任务状态,只回投。
- **FR-EVENT-02** TaskExecutionGraph(含顶层 root_phase)状态唯一改入口为 TaskService 状态组(校验状态机合法性后落态);TaskScheduler 编排不写态,只调 TaskService;owner-bot SKILL 判断/验收结果经回投 on_event 落态。
- **FR-EVENT-03** BBS 作为任务内部模态,也经回投通道(run_mode=BBS)上报节点验收与全局终验,与编排链路同出口。
- **FR-EVENT-04** 状态变更必经事件(可审计 / 可重放);并发更新有单写者抢占保证。

### 4.6 协作模式语义(FR-COLLAB)

- **FR-COLLAB-01** 自由聊天:开放探索无固定步骤序,owner bot 为拉群 driver,收敛产出后验收。
- **FR-COLLAB-02** 主从协作:有总指挥但步骤随上下文动态,owner bot 为 master;逐步派活、可逐步回投进度。
- **FR-COLLAB-03** 自定义协作:执行流可固化,owner bot 为 master;群按注入的 workflow 自闭环跑完,回投终态。
- **FR-COLLAB-04** 三种模式对应的回投粒度差异(终态 vs 逐步 + 终态)由系统按模式正确接收处理。

### 4.7 可观测与副屏可视化(FR-OBS)

> 副屏动态 workflow 是一等可视化能力:端到端执行流程以**动态生长的 DAG** 呈现(deepresearch 式拆解/重规划),区别于自定义协作群"执行流固化"的 workflow。任务为一等公民,不同执行模态默认以节点形式呈现,支持下钻与节点详情,并向下 cover 现有自定义协作群 workflow 画布的全部信息。

- **FR-OBS-01** 副屏动态 workflow:端到端执行流程以动态 DAG 呈现;DAG 随 deepresearch 拆解(加兄弟节点)与同节点重路由(换执行方)动态生长与重构,副屏实时反映,不依赖人工刷新。
- **FR-OBS-02** 任务为一等公民、模态节点同构:不同执行模态(单 bot / 协作群 / BBS)默认以 node 形式在 workflow 中呈现,图谱逻辑对三模态同构(与 FR-TASK-05 呼应);模态是节点标签,非不同画法。
- **FR-OBS-03** 下钻:协作群模态节点支持下钻,展开该群内部的具体执行 DAG(如自定义协作模式的 state_machine workflow sub-DAG);下钻呈现与现有自定义协作群 workflow 画布逻辑一致。
- **FR-OBS-04** 节点详情:workflow 中任意执行节点支持展示节点执行详情(产出物引用 / 验收结果与证据 / 进度 / 重路由上下文 / 失败原因等),交互粒度对齐现有自定义协作群 workflow(点节点看详情)。
- **FR-OBS-05** 向下兼容且信息 cover:任务状态图谱对自定义协作群 workflow 画布展示的信息**全覆盖**——节点状态(pending/ready/running/completed/failed/retry_scheduled/skipped 等)与子状态(awaiting_response/judging 等)、attempt 次数、产出 artifact 文本、验收/判定输出(judge_outputs)、带 outcome 与 guard 的边、run/根相位状态、final_output 等,都在任务图谱中有对应体现。自定义协作群视为"workflow 已固化"的特例,在同一画布中无缝展示,不丢失原有信息维度。
- **FR-OBS-06** 全生命周期可视化:从草稿 → 计划冻结 → 执行 → 验收 → 交付(及取消 / 失败)各根相位、各节点状态、重规划/重试/上升 BBS 等编排动作,都在副屏可见。
- **FR-OBS-07** 实时性:图谱快照 + 增量进度推送;状态变更经事件驱动投影(与 FR-EVENT-04 一致)。
- **FR-OBS-08** 关键节点(等待人工确权 / 上升 BBS / 交付)能触达用户(如钉钉卡片)。
- **FR-OBS-09** 全程事件可查,供排障与重放。
- **FR-OBS-10** 副屏展示位置:任务入口处(用户提需求的单 bot / 协作群入口)副屏展示**任务整体执行流程**(顶层动态 DAG);其它执行上下文(如进入某协作群页)副屏只展示**该群自己的执行子 DAG workflow**(现有自定义协作群画布),不展示任务顶层 DAG。两套画布分置不同页面,按用户当前所在上下文切换。
- **FR-OBS-11** 副屏触发时机:任务创建时自动触发副屏弹出(对齐自定义协作群 run 启动即弹出的模式);后续根相位推进与节点状态变化实时反映在已打开的副屏中。

### 4.8 非功能(NFR)

- **NFR-ARCH-01** 复用 ocb 现有跨模块契约(经 Port/Protocol 注入),不单点硬依赖具体下游实现。
- **NFR-ARCH-02** 边界 Port 在不同部署模式下可替换(professional 实现对接外部系统 / 本地/桩实现用于测试与单机),符合 ocb 微内核规矩。
- **NFR-ARCH-03** 状态写入单一化:TaskExecutionGraph 唯一改入口为 TaskService 状态组,无双轨写法。
- **NFR-EXT-01** 执行模态、协作模式可扩展:新增模态/模式不动图谱 schema,只加标签值与对应执行端口实现。
- **NFR-DI-01** 落点属 ocb 公开仓库边能力范围;非公开分支产物不混入(若引入需明确隔离)。
- **NFR-EV-01** 系统对下游模块的扩张需求(服务化建群、单 bot 程序化派活、可被回投等)在跨模块需求清单中列明。

## 6. 场景

> 用于验证需求闭包;逐步细化在 `plan.md` 与 implement 落地文档。

### 6.1 场景 A:单 bot happy path(最短可完成)

用户给一个单子任务可完成的目标(如修某 PR 命名对齐 PRD 段落)→ 拆分 → 搜推单 bot cover=100% → 派发 → 单 bot 自验收通过 → 回投 → 全局终验过 → 交付。

### 6.2 场景 B:三执行模态同案(单 bot / 协作群 / BBS)

写代码(单 bot)+ 代码 review(协作群)能过,但全量回归 + 发布跨多模块且涉广审核,搜推拆解后仍原子不可完成 → 全局终验不过 → 人工确权 → BBS 在任务内部续做 → 完成 → 交付(或仍不过 → 任务失败)。

### 6.3 场景 C:三协作模式同案(自由聊天 / 主从 / 自定义协作)

搭"代码评审 SOP bot":① 头脑风暴评审维度(自由聊天,driver 验收);② 按维度写 checklist + DDL 建表(可固化 → 自动编译 workflow yaml 注入自定义协作,群自闭环,master 验收);③ 跑一轮真实 PR 评审(有总指挥但步骤动态 → 主从协作,逐节点回投,master 验收)。三段自然覆盖三协作模式。

### 6.4 场景 D:验收不过 → 同节点重路由

某子任务验收不过,保留已做产物与未达验收项作上下文,同节点换执行方 / 补上下文重新派发(节点身份不变),有限次后通过。

### 6.5 场景 E:搜推不可完成 → 运行期拆解

某子任务搜推无执行方可完成(cover 不足),且非原子 → 拆为兄弟子任务、父节点委托(跳过),兄弟各自搜推执行;若拆后仍原子不可完成 → 留待全局终验(不直接 BBS)。

### 6.6 场景 F:副屏动态 workflow 端到端可视化

用户给出目标后,在副屏看到:
1. **任务创建即副屏弹出**(FR-OBS-11),任务入口页副屏展示任务整体执行流程(FR-OBS-10);
2. 根相位从 草稿 → 计划冻结 → 执行 → 验收 → 交付 全生命周期推进可见;
3. build 相位的 deepresearch DAG 动态生长:拆解出现新兄弟节点、验收不过触发同节点重路由(节点身份不变、换执行方)均在画布实时呈现;
4. 三模态节点同构可见:单 bot 节点、协作群节点、BBS 节点在同一 workflow 中以节点形式呈现,模态为标签;
5. 协作群节点可下钻:点开某"自定义协作"群节点,展开其内部 state_machine workflow sub-DAG(或跨页跳转到该协作群页,其副屏展示群 sub-DAG),节点状态/产出/验收/带 outcome 的边等信息与现有自定义协作群画布一致;
6. 任意节点可看详情:产出物引用、验收结果与证据、attempt/重试、重路由上下文、失败原因;
7. 全程信息维度 cover 自定义协作群 workflow:原有的节点状态/子状态/attempt/artifact/judge_outputs/边 outcome/run 状态/final_output 等,在任务图谱中均有对应体现,自定义协作群作为"workflow 固化特例"在同一画布无缝展示。

## 8. 关键决策(plan 详化)

| 决策 | 取向(详情见 plan) |
|---|---|
| 编排归属 | 单聚合 Task(spec+plan+execution_graph)+ TaskService 合一(定义/状态/查询/on_event)+ TaskScheduler deepresearch 动态编排(路由/拆解/重规划/派发,inline Port) |
| 状态写入 | TaskExecutionGraph(含顶层 root_phase)唯一写口 = TaskService 状态组(校验状态机合法性);TaskScheduler 编排不写态;owner-bot SKILL 判断/验收结果经回投 on_event 落态 |
| 验收主体 | 子任务验收由 owner bot 经 SKILL 完成,非后端服务自行判定;后端只收验收结果事件 |
| BBS 触发 | 仅全局终验不过 + 人工确权触发;非 per-node、非搜推不过直接触发 |
| 图谱范式无关 | 节点是范式无关执行单元,新增模态/模式只加标签 + 执行端口实现 |
| 协作模式选择 | 动态拉群时由系统据子任务上下文在三种协作模式间选择,不固定主从 |
| workflow 注入 | 可固化子任务运行期自动编译 workflow 定义注入协作群,注入后群自闭环,本系统只收终态 |
| 回投统一 | 单 bot / 协作群 / BBS 的判断/验收/进度/终验事件统一经后端回投通道(run_mode 区分);BBS 也经回投通道上报 |
| 副屏呈现 | 动态 workflow 画布为一等可视化:任务/模态节点同构、动态 DAG 生长与重构、支持下钻(协作群→内部 sub-DAG)与节点详情;向下 cover 现有自定义协作群 state_machine 画布的全部信息字段(自定义协作群=workflow 固化特例,同画布无缝展示) |
| 画布形态与扩展面 | 新建**独立动态 workflow 画布**(参考现有 `bcsPanel/StateMachineRunView` 实现扩展完善),非复用 state_machine 画布;**任务领域模型(定义/调度/执行图谱)+ API 为 cover 可视化需求的主扩展面**,画布为其消费者;信息字段映射(state_machine 画布信息 → 任务图谱字段)由 plan 基于代码分析(实现侧字段)给出对照表 |
| 副屏展示位置与触发 | 任务入口处副屏展示任务整体执行流程(顶层动态 DAG),协作群页等其它上下文副屏只展示该群自己的执行子 DAG workflow(两套画布分置不同页);**任务创建时自动触发副屏弹出**(对齐自定义协作群 run 启动即弹出的消息驱动模式) |

> 以上决策的 HOW(具体 service 名、Protocol、落点目录四层、双 Profile)见 `plan.md`。
