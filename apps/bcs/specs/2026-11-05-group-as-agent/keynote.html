Group
as an Agent

让一个协作群，成为可调用的 Agent

方案提议 · 2026.11

这份方案解决的是外部 Agent 如何调用一个已有 BCN 协作群，并持续对话。本期提供主从群与自定义协作群的 A2A，后续讨论自由聊天群。图中用主从群示意，同样的入口也支持自定义协作群。当前为待实施的方案。

核心模型

群可复用，会话连续，每轮结果独立

G
Group

对外的 Agent

成员与协作方式定义能力
一个群可服务多个会话

C
Context

BCN Session

承接同一调用方的连续对话
保留目标与轮次关联

T
Task

一轮群执行

记录进度、状态与最终产物
下一轮保留上一轮结果

调用方只需知道：向哪个群发消息、在哪个会话继续、查询哪一轮结果。

Group 本身就是 Agent，不需要额外注册占位 Bot。contextId 直接复用 Session.id，Task 绑定本轮 activation 或 Run。群内部可能有多个 Bot Run 或 StateMachine Run，内部标识通过关联记录管理，不混用外部 Task ID。旧结果在公布的保留期内可独立查询。

主从群 / ManagerWorker

显式完成、执行退出、产物提交

manager 调用 task.complete(summary)
BCN 固定完成边界，先返回 ack
等 manager 退出及整轮工作收尾
保存 Artifact 与 COMPLETED

完成信号必须指向本轮

精确关联 Session、activation 和 Task。

完全空闲却没有完成信号

建议 60 秒后提醒一次，
再给 120 秒宽限，仍未完成则失败。

最后一条聊天、Worker 完成或静默都不会自动判定成功。

完成调用先 ack，再等 manager 退出，避免等待自身造成死锁。提醒只在无活动工作、待回送、重试和未知停止工作时开始；心跳不重置计时。

自定义协作群 / StateMachine

同一会话里，每轮从入口启动新 Run

每轮自动带入

01最初的协作目标
02本轮要求
03上一轮结果与状态

需要更早的历史时，由流程显式读取。

流程入口
按本轮要求选择业务分支
读取指定 final_output 节点
task-1 / run-1下一轮task-2 / run-2

续聊使用新的正常执行。失败重跑与新一轮对话，各自保留原有语义。

既有自定义协作群执行结束后不能直接响应普通消息，方案在 A2A 应用层明确做 reactivate + start。成功结果使用流程指定的最终输出节点，消除按到达顺序挑最后一个 artifact 的歧义。本期不开放含 HumanInput 的流程；执行中意外进入时按期限失败收尾。

流程定义

“继续聊”做什么，由流程明确决定

本轮消息流程选择业务写入
预算改为 50 万重新比较供应商
生成新一轮建议		按分析流程执行
为什么推荐 A？读取上一轮结果并解释
必要时补读历史		解释分支只读
按方案提交订单校验业务条件后提交
使用业务单号去重		由业务规则约束

两层去重：messageId 识别同一消息的网络重试，业务单号识别重复的业务操作。

A2A 层负责把消息交给本轮流程。意图识别、分支选择和工具权限由流程实现。验收解释请求时，除了检查回答，还要断言写入能力调用次数为零。不同 messageId 可能表达同一业务意图，仍要依赖业务系统已有的去重合同。

调度取舍

同一 context 忙碌时，拒绝新一轮

收到什么本期处理
原 messageId 的相同请求读取原 Task，避免重复派发
新 messageId，不带 taskId409 / CONTEXT_BUSY
不创建 Task，不排队，不预留新 ID
向 working Task 追加消息UnsupportedOperationError
前轮结束且 context 已释放接受新 Task，保留旧结果

不同 context 可以并行。同 context 的 FIFO 排队列为下一期待定。

标准允许同 context 关联多个 Task，但不规定服务端必须串行或排队。本方案固定忙碌拒绝，并用持久化原子占用避免并发启动。

取消与恢复

停止结果未知：任务失败，会话暂时隔离

阶段Taskcontext
取消已受理，等待停止确认WORKING保持占用
全部停止且收尾完成CANCELED可接受下一轮
收尾超期，仍无法确认停止FAILED隔离，返回 CONTEXT_UNAVAILABLE
后台确认旧执行停止原 Task 保持 FAILED解除隔离，可创建新 Task

执行建议 30 分钟，收尾建议 60 秒；重启不重置期限。

隔离阻止同一会话启动新工作，原 Task 仍能查询。后台有界核实与告警，无法自动恢复时进入人工处置。不能因为锁过期就放开旧执行。

验收重点

场景预期
同 messageId 并发、两个新消息争用 context同消息只执行一次；新消息最多一条受理
task.complete 与 manager 退出、取消竞争先 ack 后收尾；只提交一个终局
Artifact 写入失败、提交后响应丢失不暴露部分成功；重试读取已提交结果

SSE 先公开过程、再最终产物、再终态；终态后不追加迟到事件。

使用真实持久化边界验证，特别覆盖写失败、重启和事件重复消费。未知执行不能再次派发，结果清理后旧 messageId 仍不能再执行。
