OpenSpec + Superpowers 变更提案

将 ClawWeb 任务护航 / TcLog 模块及其后端 API 拆分为独立开源版本 Evolvetrace

1. 变更概述

变更名称

evolvetrace-open-source-split

目标路径：/Users/fudapeng/project/ClawFlow/OCB/Avernet/src/evolverun/evolvetrace

来源仓库：clawweb（/Users/fudapeng/project/ClawFlow/clawweb）

变更性质

代码迁移 架构解耦 开源准备

风险等级：高（涉及前后端解耦、API 边界重划、权限系统简化）

预期版本：evolvetrace v0.1.0

1.1 目标

  1. 从 clawweb 中抽取任务护航与TcLog两个前端模块，作为独立的开源前端应用 Evolvetrace UI。
  2. 将对应的外部 API（/api/runs/*、/api/workflows/*、/api/tclog/*、/api/sandbox-query 等）与内部 API（/api/internal/*，供 ClawMind 写入运行数据）同步迁移。
  3. 移除 clawweb 专属的蚂蚁内网依赖（antbuservice、Dima、语雀、审批、Bench 等），保留通用能力。
  4. 权限系统从简：由蚂蚁员工号 + admin 名单模型，切换为简单的基于 HTTP Header/Cookie 的 ownerId 识别，仅保留“是否管理员”开关，不再维护 bot 协作者、工作流 ACL 等复杂权限。

1.2 非目标

  • 不迁移数据大盘、智能接入、审批、Dima、Dev-Workflow、Insight Center、Repair、Flow Control、Bench 等模块。
  • 不保留 antbuservice 单点登录；开源版本使用简化的 local-auth / 可配置 Header 登录。
  • 不做数据库 schema 重构，保持与 clawweb 现有 flow_runs、node_executions、ac_otel_log_trace、aw_langfuse_traces 等表兼容。

3.3 后端迁移策略

3.3.1 路由裁剪

新的 server/index.ts 仅挂载以下路由：

app.use("/api/auth", createAuthRouter());
app.use("/api/runs", createRunsRouter(flowRunRepo, nodeExecRepo, eventRepo, metricsRepo, null, null, workflowSpecRepo, executionStepLogRepo));
app.use("/api/workflows", createWorkflowsRouter(workflowSpecRepo, facadeRepo, null, notificationConfigRepo, wfdhRepo, httpCallbackConfigRepo));
app.use("/api/tclog", createTCLogRouter(db, flowRunRepo, null));
app.use("/api/sandbox-query", createSandboxQueryRouter({ sandboxQueryService }));
app.use("/api/internal", signatureMiddleware(sigConfig), createInternalRouter(internalRepos));

注释：权限 repo botPermRepo 传 null，开源版不再进行 bot 工作流 ACL 校验；admin 逻辑保留在 adminAuthMiddleware 中。

3.3.2 权限系统简化

原 clawweb 模型开源 evolvetrace 模型
蚂蚁 staff_id cookie + antbuservice可配置 Header X-Evolvetrace-User-Id 或 Cookie evolvetrace_user_id
isAdmin / isLogAdmin / isBenchAdmin仅 isAdmin，由 ADMIN_USER_IDS 环境变量决定
bot 协作者表 ac_bot_collaborator不维护；仅 owner 可见自己的 bot 与 trace
bot-工作流 ACL 白名单保留 repository 但不启用（传 null）
管理员可跨 owner 查询保留：管理员可查任意 ownerId 数据

3.3.3 内部 API 签名鉴权

保留 server/middleware/signature.ts 与 resolveSignatureConfig，内部 API 仍通过公私钥签名验证 ClawMind/Engine 身份。配置项改为：

EVOLVETRACE_INTERNAL_PUBLIC_KEY_B64=...
EVOLVETRACE_INTERNAL_SIGNATURE_TTL_SECONDS=300

3.4 数据库兼容性

开源版本直接复用 clawweb 的 DB schema，不做迁移。关键表清单：

  • flow_runs、node_executions、flow_events
  • workflow_specs、workflow_deploy_history、facade_bindings
  • ac_otel_log_trace、aw_langfuse_traces、ac_otel_log_observation、ac_otel_log_biz_ref
  • ac_bots、ac_entity_device_binding（TcLog bot 列表、Sandbox Query 依赖）
  • metrics、alerts、scheduled_triggers、webhook_triggers、webhook_events

4. 任务清单（按 Superpowers 工作流）

本提案对应 OpenSpec 阶段二输出。后续实施按 Superpowers 工作流拆分为 7 个并行/串行任务：

#任务类型依赖验收标准
1初始化 evolvetrace 仓库骨架（package.json、Vite、TS、基础路由）并行—npm install 成功，npm run dev 启动空白页
2迁移公共 UI 组件与工具函数并行1StatusBadge/EmptyState/ErrorState/HealthScoreCard/SuccessTrendCard 无编译错误
3迁移任务护航前端模块（WorkflowWorkspace + 子组件 + Editor 复用）并行1, 2/workflows/workspace 可渲染，可切换 Tab
4迁移 TcLog 前端模块（TCLog.tsx + hooks + types）并行1, 2/tclog 页面可渲染三种查询模式
5迁移外部后端 API（runs / workflows / tclog / sandbox-query / 简化 auth）并行1server/index.ts 可启动，对应路由返回 200/503（DB 未配时）
6迁移内部 API 及签名鉴权并行1, 5/api/internal/health 通过签名返回 {status:"ok", signer:"verified"}
7集成测试与权限简化验证串行3, 4, 5, 6前端页面可查询本地 server；admin 与普通用户权限差异生效

5. 实施计划（Superpowers）

阶段三实施方式：任务 1-6 相互独立，建议采用 /superpowers:subagent-driven-development 并行执行；任务 7 串行集成。
  1. Writing Plans：基于本提案生成 docs/superpowers/plans/2026-08-20-evolvetrace-plan.md，明确每个子任务的输入、输出、边界。
  2. Subagent 并行开发：为每个任务启动独立 subagent，分别负责前端组件、后端路由、内部 API、骨架初始化。
  3. 代码审查：使用 /superpowers:requesting-code-review 审查增量代码，重点检查：
    • 是否误把蚂蚁内网依赖带入开源目录；
    • 权限中间件是否正确降级；
    • 内部 API 签名中间件是否仍生效。
  4. 增量单测：使用 /superpowers:test-driven-development，为 tclog 路由、runs 路由、内部 runs 路由补测试，目标变更行覆盖率 ≥ 90%。
  5. 验证交付：npm run build、npm run build:server、npm test 全绿，输出 TEST_REPORT.md。

6. 风险与应对

风险影响应对措施
EditorTab 复用 Editor 页面，依赖复杂高先复制 src/pages/Editor 及其依赖到 evolvetrace，再裁剪非工作流编辑功能
TCLog 依赖语雀/日志分析等外部能力中明确不迁移 TeamClawSupport；TCLog 自身不依赖语雀
权限降级后影响原 admin 查询逻辑中保留 req.isAdmin，移除 req.isLogAdmin，TCLog 路由中用 isAdmin 统一判断
内部 API 签名配置缺失导致 engine 无法写入高文档中明确 EVOLVETRACE_INTERNAL_PUBLIC_KEY_B64 必填，提供生成脚本
Repository 层复制遗漏导致运行时异常中通过编译检查与集成测试覆盖，缺失 repository 优先让路由返回 503 而非崩溃

7. 开源合规与后续演进
