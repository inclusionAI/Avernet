# TC Session Resource Withdrawal

## Summary
用户删除一次 Bot 单聊文件上传后，TC 保留该资源的已删除状态，并可靠通知 ECB，使这次上传对应的业务文件引用失效。该操作不是聊天消息撤回，也不是共享知识内容的物理删除；其他有效引用继续可用。

- Status：Implementation authorized，2026-09-28；用户授权连续推进至 PR-ready，单聊范围已确认；对端契约及真实联调为上线前置条件，TC 投递默认暂停。
- Owner：Backend（TC 资源删除与可靠通知）；ECB 负责映射、引用失效和访问控制。
- Participants：Frontend-nextgen 提供 Bot 单聊用户入口；ECB 为仓库外依赖；群聊及 BCS 协作文件链路明确不在本期范围内。

## Motivation
当前删除只改变 TC 资源状态，没有同步知识体系的删除通知，可能使已删除上传对应的知识引用继续有效。通知丢失、重复或与上传通知乱序，都不能导致该引用重新有效。

## User Stories
- 作为 Bot 单聊用户，我希望删除某次上传后，知识体系不再通过这次上传的引用提供内容，同时不影响他人有权访问的相同内容。
- 作为运维人员，我希望下游故障或服务重启后仍可恢复通知，并能区分“已被下游接收”和“引用已失效”。

## Acceptance Criteria
- [x] AC1：Bot 单聊资源的合法删除沿用现有删除响应，仅作用于这一次上传；不存在或无权删除时保持现有错误行为，不产生删除通知。
- [x] AC2：成功删除与可靠保存待通知事实一起生效；任一本地写入失败均返回失败并整体回滚，不出现“删除成功但通知事实丢失”。
- [x] AC3：Bot 单聊的正式及仍受支持的旧版删除入口行为一致；单聊上传资源在上传或构建未完成时被删除，也必须通知。
- [ ] AC4：重复、并发删除及重试始终对应同一逻辑事件；允许重复投递，但不得重复产生业务效果或重置已接收状态。
- [x] AC5：ECB 不可用、超时或暂时失败不阻塞或回滚已提交的 TC 删除；待通知事实持久保留，服务重启及多实例运行后能够继续处理。
- [x] AC6：鉴权失败、契约错误或无效回执不能记为成功；保留可查询的失败原因并告警，修复后支持受控重放，避免高频无限重试。
- [ ] AC7：只有收到匹配事件的持久接收确认，才能记录“ECB 已接收”；该状态不等于“引用已失效”，映射尚未建立时也不得静默丢弃删除意图。
- [ ] AC8：删除后到达的完成回调不能恢复 TC 资源；删除早于上传入库或上传通知迟到时，ECB 仍须最终维持引用失效。
- [ ] AC9：两个上传引用相同内容时，删除 A 只使 A 的引用失效；B 及共享产物不受影响。知识文件列表、摘要和检索不得继续通过 A 的失效引用提供内容。
- [ ] AC10：跨系统处理限定在可信租户/集成范围，不得凭任意资源标识跨范围操作；保留必要关联信息用于追溯。
- [x] AC11：事件积压、最老未完成事件时间及失败状态可观测；暂停或回滚不能清空未完成通知；生产配置缺失必须显式失败，不能假报投递成功。
- [ ] AC12：TC 侧自动化验证覆盖上述本地行为；真实 ECB 联调验证乱序和共享引用隔离。仅通过 fake 验证不能宣称端到端完成。
- [x] AC13：群聊现有文件操作行为保持不变，不因本期改动产生群聊删除通知。

## In Scope
- 仅覆盖 Backend 管理的 Bot 单聊上传资源删除，以及单聊正式/旧版入口的一致性；该场景边界已由用户于 2026-09-28 确认。
- 删除通知的可靠保存、异步投递、去重、恢复、受控重放、可观测性与删除终态保护。
- 必要的跨系统契约、配置、迁移及运维说明；ECB 接收和引用失效能力属于交付依赖，不在 TC 内重复实现。

## Out of Scope
- 共享 source、segment、fact、向量、图谱、原始内容对象的删除或 GC。
- TC 管理 ECB 业务文件标识、计算共享内容引用数或直连 ECB 数据库。
- 改变 Engine 本地文件物理删除、重构上传流程、顺带提升上传通知的可靠性。
- 默认补发上线前全部历史删除记录；增加尚未证实存在需求的回调接口。
- 群聊文件删除及其 BCS 协作文件体系：不修改群聊入口、接口或删除行为，不增加群聊到知识体系的删除通知。

## Contracts and Evidence
- 对用户的删除响应保持兼容；需与 ECB 新增并冻结“按上传资源撤销引用”的服务契约。接口及回执目前仅为 handoff 草案，尚未获得对端确认。
- 现有模块边界、相关协议入口和静态代码证据见 [research.md](research.md)；目前无直接适用的已接受 ADR，不将 Skill 撤回规则套用于会话文件。
- TC 自动化证据见 [validation.md](validation.md)。AC4/7/8/9/10/12 的 TC 部分已覆盖；跨系统业务效果、可信集成鉴权和真实 UI/ECB 验证仍未完成，因此保留未勾选，不能宣称端到端完成。AC11 已提供日志/统计，实际告警阈值与路由属于上线配置。

## Open Questions
- **Q2 / ECB Contract**：由谁与 ECB 冻结接口、契约版本、可信租户范围、幂等及持久接收回执，并确认删除先到和迟到上传不会恢复引用？对端就绪情况尚未验证。
- **Q3 / Operations**：正常条件下从删除到引用失效的验收时限、积压告警阈值及故障处理责任人是什么？需双方明确，不在草案中虚构时效承诺。
