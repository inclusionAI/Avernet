# 数据与安全规则

## 硬规则

- 每个数字只能来自当前会话明确输入、真实工具结果或 `KNOWLEDGE.md` 的已登记行业
  历史数据；标记来源类型、单位、时间窗和截止时间。
- 允许的来源类型为 `TASK_FACT`、`KNOWLEDGE_FACT`、`OWNER_COMMITMENT`、`DERIVED`
  与 `DECISION_VARIABLE`。未标记来源的情景值不得代入。
- 百分比、增长率、倍数和耗尽时间必须显式复算；中间值保留原始精度，最后一步才
  舍入。
- 不使用个人观察、行业通常、虚构样本、经验区间或保守假设补充缺失业务数据。
- manager/owner 已确认的最大核销量是当前版本的待履约契约上限，不是销量预测；产能
  与耗材必须按该上限的最坏履约义务校验，不得用无来源转化率、行业经验或“保守估计”
  自行下调。若任务另有带来源的预测量，预测与契约上限必须分字段展示，不能互相覆盖。
- 不把相关性、地区差异、异常信号或群体标签写成确定原因；异常只触发调查或小范围
  可逆调整建议。
- 不替营销承诺预算，不替供应链承诺交期，不替商家确认成本、毛利、现金、授权或审批。
- 最终状态只用 `PASS`、`REVISION_REQUIRED`、`BLOCKED_MISSING_EVIDENCE`；存在非空
  缺口、观察窗不一致、产能定义冲突或失败校验时不得返回 `PASS`。

## 产能和观察窗门禁

- 需求与可用产能必须同一时间窗和单位。正的 `available - demand` 是剩余，不得写成
  缺口；需求不超过可用产能时缺口必须为零。
- 多服务共享资源先计算总增量需求；任何整体池、技能池或工位池超过上限都必须为
  `REVISION_REQUIRED`。
- 不完整观察窗不能与完整历史基线做无提示比较；当前已预约分钟属于日常基线，不能
  将全部核销都当新增负荷。
- 活动执行周期、剪发券有效期和护理套餐有效期是三个独立时间窗；任务同时给出时必须
  分别使用，禁止用任一券有效期替换活动天数。

## 隐私与业务安全

- 不请求、输出或反推手机号、设备标识、精确轨迹、支付明细、健康信息、个人消费记录
  或敏感属性。
- 不伪造数据源、查询记录、置信度、统计显著性、投放、券、指标或外部系统回执。
- Agent 分析不能替代真实业务中的隐私评估、合规审批或专业统计审查。
