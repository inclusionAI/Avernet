# TC 每库空间 Bot 自动授权开关配置

## Summary
在知识库详情“已授权 Bot”页签提供每库独立的开关，由 TC 保存和回显，覆盖个人空间与团队空间。作用对象沿用空间内 Bot 的范围，但本期仅配置，不执行自动授权，也不改变实际访问权限。

## Motivation
将完整自动授权需求拆成可独立交付的最小配置功能，先提供受权限保护的前后端入口。页面明确提示“本期仅保存配置，暂不执行自动授权”，避免用户将保存成功理解为已获得访问权限。

## User Stories
- As a 知识库创建者, I want 在仍有管理权限时保存每库开关, so that 后续能力可使用明确的配置。
- As a 知识库使用者, I want 看见真实保存状态及仅配置说明, so that 不误以为开关已经改变访问权限。

## Acceptance Criteria
- [ ] AC01：个人/团队空间的新旧库缺少配置时均为 OFF；修改仅影响目标库，不串库、空间或环境，不批量补写旧库。
- [ ] AC02：有权操作者保存 ON/OFF 后，接口和页面刷新正确回显；保存失败明确提示；读取异常不伪装成 OFF。
- [ ] AC03：仅创建者且当前有管理权限可修改；非创建者管理者、失权创建者和其他无权用户直接调用也被拒绝，通用配置入口不得绕过。
- [ ] AC04：待删除等不可操作状态拒绝修改，沿用现有生命周期规则。
- [ ] AC05：“已授权 Bot”页签包含开关、操作能力、错误反馈及“本期仅保存配置，暂不执行自动授权”提示，覆盖个人/团队空间。
- [ ] AC06：TC 是开关唯一维护方；ECB 不增加字段、副本或开关接口，只复用已有元数据和权限校验能力。
- [ ] AC07：切换不改变实际 Bot 授权、人工取消、人员权限、启用、MCP、发布选择或实际访问；不创建授权任务、不枚举成员、不监听生命周期。
- [ ] AC08：原有逐 Bot 人工授权/取消继续可用；不新增 ECB 开关汇总活动或数量接口；验收记录区分实测与未验证项。

## In Scope
- TC 每库开关的专用读写入口、持久化、隔离、服务端权限与状态校验。
- 工作台开关、保存与错误反馈、刷新回显及仅配置说明。
- 复用现有知识库元数据/权限和企业适配，验证前后端组合行为。

## Out of Scope
- 自动授权/撤权、逐 Bot 关系、名单枚举、新建/迁移/删除/Owner 转交监听、任务与批量进度。
- ECB 开关存储、归属投影、继承授权、授权执行或读路径改造。
- 汇总活动/数量、通知、审批、删除流程或语雀导入改造。
- 生产 DDL、数据初始化、发布和部署。

## Open Questions
无阻塞业务问题；本需求只保存配置的边界已确认。工程侧核对创建者身份来源、通用写保护及现有存储并发能力，不能以扩大 ECB 功能代替核验。
