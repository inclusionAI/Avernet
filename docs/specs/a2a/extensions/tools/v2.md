# BCS A2A tool observation extension v2

URI: `https://github.com/inclusionAI/Avernet/blob/dev/docs/specs/a2a/extensions/tools/v2.md`

This extension observes tool execution between A2A Agents and BCS or A2A
clients; it never grants approval. Declare the URI in AgentCard
`capabilities.extensions` and negotiate through `A2A-Extensions` before
emitting these records. Unsupported clients can still receive ordinary Artifact
answers when this observation extension is optional.

Carry one record in a structured `DataPart` of `statusUpdate.status.message`
(or `task.status.message`). Mark the `Message.extensions` array with this URI
instead of occupying a `Message.metadata` key. Preserve the actual Task state;
do not set a new Task state just to publish tool progress.

Required fields in `Part.data`: nonempty `toolCallId`, nonempty `name`, and
`phase` (`start` or `result`).

Optional fields in `Part.data` (omit when absent; do not fabricate missing
values):
- `args`: JSON object on `start` records.
- `isError`: boolean on `result` records. Tool failure does not imply Task
  failure.
- `result`: JSON object on `result` records with `content` (an ordered array of
  typed result parts; each text result part has `type: "text"` and string
  `text`, including empty text).

Optional source metadata (such as `serverId`) belongs in `Part.metadata`, not
in `Part.data`. `toolCallId` is stable within a Task. BCS associates it with
the authenticated remote Task and local Bot/Session/Run; remote IDs and
metadata never grant routing authority.

Duplicate equal records for the same `(toolCallId, phase)` are no-ops;
conflicting records of one phase or a changed `name` for one `toolCallId` are
errors. A `result`-only recovered record does not fabricate an observed
`start`.

Tool approval uses Structured Input and is never encoded as a successful start
or automatically accepted here. Internal run IDs, routing directives,
credentials, and database fields must not be embedded. Breaking field or
semantic changes require a new URI version.
