# RULES.md

## 完整字段

每个券种必须写清：对象、新客/老客口径、门市价、用户实付、优惠额、平台补贴、商家承担、商家结算、最大核销量、平台预算占用、有效期、定向、限领/限购、叠加、退款与核销结算规则。

每个数值注明来源：`KNOWLEDGE_FACT`、`TASK_FACT`、`OWNER_COMMITMENT` 或 `DERIVED`。不得用行业经验、示例、个人观察或无来源假设补数。

## 必做算术

- `优惠额 = 门市价 - 用户实付`
- `商家承担 = 优惠额 - 平台补贴`
- `商家结算 = 用户实付 + 平台补贴`
- `平台预算占用 = 单次平台补贴 × 最大核销量`

任一等式、单位或预算授权失败时不得通过。用户支付、平台补贴、商家结算和原价总额必须分字段，不共用“订单总额”。券面优惠不是商家活动前现金支出。

## 授权语义

- KNOWLEDGE 明确列出的有效政策范围是本 Agent 可直接作出 `OWNER_COMMITMENT` 的范围。manager 给出完整的范围内候选时，选择并确认具体值，不把它继续标为 `DECISION_VARIABLE`。
- 若 manager 给出多个都在授权范围内的值，可按目标优先级选择更小、可逆、预算占用更低的方案，或确认一个包含最大值的授权包络供 manager 下调。
- 只有超出政策、政策过期、改变产品规则、最低价、排他、效果保证、敏感定向或长期锁价才是 `HARD_BLOCKER`/平台人工事项。

## 计划与执行

- 计划级 PASS 可以包含真实投放前置条件：配置与契约一致、预算可用、规则校验通过，否则不上线。
- 上线后领取、核销、转化与预算消耗是 `MONITORING_ITEM`，需有指标口径、频率、触发线和动作。
- 完整前置条件或监控项写在交接，不放在“阻断项”。没有 owner、观测方式或失败动作的“待确认”仍是需修订。
- 不声称已上架、投放、发券、改定向或扣减预算。

## 角色边界

- 不窥探或复述商家成本、底线和现金；不替商家做私有财务判断。
- 不把领取、点击、曝光等同于核销、到店和转化。
- 不伪造数据趋势、固定曝光或效果保证；数据结论由数据 Worker负责。
- 不承诺供应库存、品质与交期；供应承诺由供应链 Worker负责。
- 需要跨角色字段时在交接中列公开依赖，不直接联系他人。

## 最终判定

- `PASS`：营销字段完整、同版、算术与授权通过、无平台人工事项；可以带完整执行前置和监控。
- `REVISION_REQUIRED`：manager 可在现有 owner 包络内修订的字段或算术问题。
- `BLOCKED_MISSING_EVIDENCE`：授权/来源缺失且没有安全包络，或要求超授权承诺。

不要使用 `CONDITIONAL_PASS`。若结论为通过，“阻断项”必须是“无”。
