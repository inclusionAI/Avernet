# ClawInsight 验收分析

## 运行职责

同一版本的项目程序负责获取队列、读取证据、匹配根因、计数和回写。
本技能解释证据和验收标准，不让模型直接修改改进项状态或执行环境。
验收任务使用自己的配置、任务标识、产物及状态目录；不覆盖治理任务或其他人的配置。
任务何时运行由外部调度决定，不使用个人技能仓库作为运行依赖。

对已批准并发布的正式验收任务，程序完成有效结果回写后结束，不暂停等待对话确认。
证据不足保留观察，不为了让任务“有结果”而关闭项目。
这不代表交互式只读复核自动获得写入权限。

## 对象和边界

- 标准队列：IN_PROGRESS且handledAt存在；观察从修复处理时间开始。
- 开放队列：ACTIVE或无handledAt的IN_PROGRESS；使用明确的修改观察边界，不能拿创建时间代替修复时间。
- 运行中的修复任务尚未结束时，不能宣布修复成功。
- 只统计边界之后实际检查的相关Session；来源、设备、Agent、操作和根因须能对应。
- 文件mtime只用于召回；最终判断使用Session时间与消息/工具结果。
- 离线数据滞后时，用同一来源的当前只读日志覆盖缺口；无法完整覆盖则保持证据不足。

## 判断原则

- STILL_PRESENT：原问题仍在最新相关执行中复现，能指出实际Session和时间，不关闭。
- DISAPPEARED：观察期满足且读取完整；同一操作较晚的成功执行可以证明恢复，或者完整观察期内没有再出现问题（包括停用错误定时任务后没有新Session）。
- INSUFFICIENT_DATA：数据读取失败、权限错误、未满服务端观察期、证据冲突、执行未结束或修复任务仍在运行。

结构化根因签名不是验收准入条件，不要求历史改进项补齐机器字段。
已有机器字段仅辅助定位同一操作；没有时检查完整Owner+Bot范围，不按错误分类猜测。
在整个范围均无错误且观察覆盖完整时，可以按无复现通过；如仍有错误但无法确认是否属于原问题，
保留并说明具体不确定性，不能把其他任务的成功当作修复，也不能虚报原问题复现。
没有精确对应到原问题的Session时，newSessionCount保持0；实际检查过的范围和数量另行记录。
读取失败不等于没有复现，配置变化或模型自述不等于日志证实修复。
当前服务端仍要求标准至少2天、开放至少7天，即使已看到成功证据也不绕过该限制。

标准和开放验收的观察期、状态约束及回写字段见
[verification-contract.md](references/verification-contract.md)。

## 输出与副作用

输出对程序验收计划的证据解释：原问题、实际检查范围、相关Session、复现或成功依据、缺口。
不能新增未经程序读取的Session、数量、修复时间、版本或对象ID。
程序生成的结构化请求和服务端回执是执行结果，报告文本不能替代它们。

当前程序将INSUFFICIENT_DATA记录在本次产物中，不每天回写刷新修改时间，
避免开放项目的观察时钟被反复重置。确定的复现/消失才进入正式回写通路。

已有问题重新出现不自动修改修复方式，不强制关闭、不重开已关闭项，不启动新修复。
NAS只读取目标数据，模型不获得Shell、文件写入、挂载或重挂载能力。

## 大证据包与运行输出

完整证据保留在本次运行产物中。模型解释可以按已核对的相关 Task 分批输入，必须保留证据标识、
范围、原始证据摘要和未展示部分的说明；部分输入不能被表述为完整历史，也不能改变程序的验收结论。
若程序已有确定的 INSUFFICIENT_DATA 门禁原因，直接输出该原因，不为改写一句解释重复调用模型。
控制台打印每次完成的模型可见回复、批次进度和校验失败事件；不输出隐藏推理、凭据或完整原始会话。
