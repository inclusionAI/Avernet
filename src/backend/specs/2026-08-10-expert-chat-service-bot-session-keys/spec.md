# ExpertChat service-bot session key contract

Date: 2026-08-10
Status: active contract for ExpertChat relay-managed service-bot chat sessions

## Scope

This document owns the session-key wire formats generated by backend
`ExpertChatService` when a service bot uses a relay-managed chat lifecycle.
For these engines, the backend does **not** call Adapter `/api/sessions`
create/check/delete. It persists a local session key and lets the runtime relay
create or resume the actual chat session lazily when the first chat request is
sent.

The strategy hook that implements this contract is
`EngineProvisioningStrategy.build_local_chat_session_key()`. The hook is used
only when `uses_adapter_chat_session_lifecycle()` returns `False`.

## Versioned formats

| Engine strategy | Version | Format | Owner / parser | Notes |
| --- | --- | --- | --- | --- |
| `aicoding` | `aicoding-service-bot-v1` | `user:{user_id}:session:{uuid}:agent:{bot_id}` | `teamclaw-aicoding-relay` | Service-bot sessions need both the caller user and service bot id. The relay owns the lazy session lifecycle. |
| `claude_code` | `claude-code-normalcc-legacy-v1` | `session:{uuid}:user:{user_id}` | Claude Code relay/runtime path | Preserved for normalCC compatibility. The backend does not append `agent:{bot_id}` for this engine. |
| default adapter lifecycle engines (`openclaw`, `teclaw`, `hermes`, fallback) | adapter-owned | Adapter returns the session id from `/api/sessions` | Engine Adapter `/api/sessions` | Backend does not mint a relay-local key for these engines. |

## Routing and namespace compatibility

The `aicoding-service-bot-v1` format has the same token order as one legacy
Claude Code parser form (`user:<u>:session:<s>:agent:<a>`), but it is not a
Claude Code session-key assignment:

- `ExpertChatService` resolves the active chat engine from bot metadata and
  dispatches local key creation through the registered engine provisioning
  strategy.
- `aicoding` service-bot sessions are sent to the aicoding relay path and are
  consumed by `teamclaw-aicoding-relay`.
- `claude_code` service-bot sessions keep the `session:{uuid}:user:{user_id}`
  format and are not minted with the aicoding service-bot format.
- Therefore the string-shape overlap is a namespace coincidence; it does not
  reassign the Claude Code adapter contract, provided routing continues to use
  the resolved engine strategy and path.

## Propagation and compatibility

Affected producers:

- `src/backend/src/agentclaw/community/core/expert_chat/services/expert_chat_service.py`
- `src/backend/src/agentclaw/community/core/bot_management/engines/provisioning.py`
- `src/backend/src/agentclaw/community/core/bot_management/engines/aicoding/strategy.py`
- `src/backend/src/agentclaw/community/core/bot_management/engines/default.py`

Affected consumers / implementations:

- `teamclaw-aicoding-relay` must accept `aicoding-service-bot-v1`
  (`user:{user_id}:session:{uuid}:agent:{bot_id}`) for aicoding service-bot chat
  sessions.
- Claude Code relay/runtime remains on `claude-code-normalcc-legacy-v1`
  (`session:{uuid}:user:{user_id}`) for this backend path.
- Adapter-lifecycle engines continue to receive create/check/delete calls and
  own their returned session ids.

Compatibility rules:

1. Already-open sessions minted before this change with
   `session:{uuid}:user:{user_id}` are not migrated in place.
2. If such an old local key is reused, the backend keeps sending the stored key;
   no parser rewrite is attempted in `ExpertChatService`.
3. New aicoding service-bot sessions use `aicoding-service-bot-v1` so the relay
   can recover both `user_id` and `bot_id` from the key.
4. Missing relay support for `aicoding-service-bot-v1` is a deployment ordering
   error and must be resolved before enabling this backend change on a release
   branch.

## Guardrails

- `ExpertChatService` must not compare against concrete engine strings for
  session lifecycle or key formatting. Engine variability belongs in
  `EngineProvisioningStrategy` implementations.
- Each concrete strategy must implement both lifecycle hooks; adding a new
  concrete engine strategy requires declaring whether it uses adapter-managed or
  relay-managed chat sessions.
- Format changes require updating this spec and naming the affected relay or
  adapter consumer.
