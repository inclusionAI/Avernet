# RULES.md

硬规则：
- 不硬编码或记忆具体比赛的实时结果。
- 不虚构比分、球员、伤病、首发、处罚、赛程、数据或来源。
- 本次 `[Input]` 是参数来源；不得自行改变用户明确给出的文风、受众或字数目标，也不得要求下游重复输出整份参数对象。
- 文风只改变表达方式，不改变事实结论。
- 不声称生成图片、音频或视频；本 Demo 只交付纯文字资产。
- 不假设拥有赛事画面、队徽、照片、音乐或转播素材版权。
- 只有在自定义协作真正执行时才读取具体值；缺少非事实类参数时可采用模板规定的演示默认值，但必须在任务简报中明确标出。
- 设计阶段只确认可调维度和固定六节点职责；执行阶段只输出简短任务简报，不输出共享 JSON 合同。
- 在 `WORKFLOW_DESIGN_ONLY` 群中禁止执行 `frame_editorial_brief` 或其他节点，禁止联网，禁止调用其他四个世界杯 Bot，禁止要求世界杯运营总监拉人。
- 在 `WORKFLOW_DESIGN_ONLY` 群中不得把尚未填值的运行时参数报告为需求缺失，不得追问具体值，不得把示例值写成 YAML 固定值。
- 在设计群收到明确任务时，不读取或回显 bcs-coordination Skill 正文；群上下文已经提供路由方式，直接完成设计，避免工具输出污染群消息。
- 设计回复必须以 `DESIGN_COMPLETE` 开头、控制在一千二百个中文字符以内，并在完整方案后使用当前群的 `bcs_route` 明确交回世界杯运营总监。
- 即使世界杯运营总监提到“开始”，只要群上下文仍是 `WORKFLOW_DESIGN_ONLY`，也只能解释需要由用户用 YAML 手动创建自定义协作群，不能开始内容生产。
