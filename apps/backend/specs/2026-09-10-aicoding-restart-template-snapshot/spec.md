# AICoding 重启模板快照契约

- 修订：2026-09-10，revision 2。
- 关联：PR #2117。
- 范围：既有 `POST /api/bots/{bot_id}/restart` 的 `extra_configs` 扩展，以及
  `AicodingProvisioningStrategy.apply_restart_extra_configs`。
- 本文取代 2026-08-20 授权知情同意方案中关于模板来源、版本判定、保存与失败处理的旧描述；
  不宣称该历史方案中所有前端弹窗或交互已实现。

## Problem

旧策略只接收版本严格增加的快照，且只调用 `update_template`：

- 已存在模板的同版本发布策略更新会被跳过。
- 无模板版本或无模板记录的历史 Coding Bot 不能通过该入口保存迁移配置。

本修复明确改变这两项输入语义，不是仅重命名或未接入生产路径的新增代码。
版本与发布状态选择移交前端，后端只保存所收到的完整快照。

## 请求与责任边界

请求结构示例（`template_config` 仅展示部分字段，实际必须传完整合并结果）：

```json
{
  "extra_configs": {
    "confirmed_template_update": true,
    "template_config": {
      "template_key": "personalCoding",
      "template_uid": "example-template",
      "template_version_id": 101,
      "envs": { "DOMAIN_POLICY": "" }
    }
  }
}
```

- `template_config` 与 `confirmed_template_update` 在 `extra_configs` 中同级，后者不是
  模板业务字段。请求不新增顶层确认字段，不新增接口或数据库列。
- 既有路由鉴权、所有权和生命周期校验不变；前端选择模板不是新的鉴权边界。
- 只允许 `aicoding` / `claude_code` 策略消费此配置。非目标引擎不调用模板服务。
- 策略只接受非空字典；缺失、null、空字典、数组或字符串不写模板。
- 发布状态、模板版本、新旧配置组合由前端负责。后端不拉模板市场、不重做组合、不比较版本。
- **这不是 PATCH 接口。** `template_config` 是前端基于 Bot 当前配置合并后的完整快照；
  只提交 `envs.DOMAIN_POLICY` 会覆盖掉其他已存字段，调用方不得这样使用。

## 前端调用方义务

| 情况 | 组合规则 |
| --- | --- |
| 无有效版本的历史 `personalCoding` / `applicationCoding` | 选对应正式发布模板，保留旧业务配置，补模板身份与能力；缺失/null 配置按空对象处理 |
| 有版本的新 Bot 或已迁移 Bot | 仅正式发布且版本 ID 严格增加时整份升级；顶层浅合并，envs 按键合并，新模板优先 |
| 独立字段 `envs.DOMAIN_POLICY` | 可见的白名单发布 `pre_published` / 正式发布 `prod_released` 有键即采纳，包括空值；不比较版本，缺键保留，不采纳草稿 |

独立字段规则允许增加其他路径；同步单个字段时也必须把其合入当前完整快照后再提交，
不得顺带替换模板版本、镜像或其他无关字段。首次迁移会携带确认标记，以复用授权/技能刷新。
模板查询失败可沿用当前配置，但不能把查询失败解释成空模板并覆盖已有配置。

以上是配套前端的义务，不是本后端 PR 对任意 API 客户端的运行时保证。
后端只收到确认标记而没有完整配置时，不会自动生成或获取新模板配置。

## 策略保存行为

- 移除原有 `incoming_version > stored_version` 门槛；同版本、较低版本和无版本的非空快照
  均可进入保存。版本仅用于已有刷新标记及日志，不作为写入准入条件。
- 调用原有 `TemplateService.create_or_update_template`，无记录创建；有记录则更新，
  包括已有记录的 `ext` 缺失/null/空字典。继续复用原有 token 加密及密文防重复加密逻辑。
- 整份 `extra_configs` 不入库。传入快照保存到 `ac_templates.ext`；确认参数不原样保存，
  策略按既有机制在快照中写 `_aicoding_restart`，供异步授权/技能同步及后续重试使用。
- 授权刷新沿用既有确认参数或持久标记触发机制，成功后清除标记，失败保留。
  保存快照与异步授权刷新不是一个原子事务，不承诺一次请求内两者同时成功。
- 不修改 `BotService`、`TemplateService`、通用 provisioning 接口或 HTTP router；
  不直接使用模板服务的私有仓储，不新增公共严格保存方法。

## 失败与重启顺序

1. 模板服务抛出的异常由策略向既有调用方传播。
2. 若模板服务返回空保存结果，策略抛 `RuntimeError`，避免打印保存成功日志。
3. **既有 `BotService.restart_bot` 会捕获该扩展异常，打印告警并继续按已存配置重启。**
   这不是新的 fail-closed 机制，也不代表保存错误会作为接口错误返回给前端。
4. 因此可能重启成功但未使用新配置；重启本身仍可能因其他原因失败。下一次有快照的
   请求可再次尝试保存，失败后不能推断数据库一定未发生写入。
5. 保存成功日志含 Bot ID、版本与刷新标记；扩展失败日志含 Bot ID、异常及堆栈。

保持原有钩子在重启锁前执行的位置和公共存在性查询的异常处理，不增强其并发语义。
这是复用既有保存入口，**不是原子 UPSERT**，也不保证重复重启请求在写配置前被锁抑制。

## 传播、兼容与风险

| 消费方或能力 | 变化与兼容边界 |
| --- | --- |
| 配套前端 | 负责模板可见性、版本选择、完整合并结果；须配套发布并验证实际请求 |
| 旧调用方不传 template_config | 策略不写模板，原重启行为不变 |
| 旧调用方传递完整更高版本快照 | 继续保存；不再享有“旧版本请求必被后端拒绝”的保证 |
| 其他直接 API 调用方 | 也受新快照语义影响；不能假设服务端提供 PATCH 或版本单调保护 |
| 默认引擎策略与公共主链路 | 无源代码修改；鉴权、设备选择、锁、异常回退保持原实现 |
| 模板读取、设备启动与授权刷新 | 读取最终已存快照；新增记录可被既有读取路径消费；授权同步仍异步 |
| 数据库与 token | 表结构不变、加密机制不变；新增首次创建路径，无原子并发创建保证 |

**并发风险：**删除版本门槛后，延迟到达的旧完整快照可能覆盖已保存的新快照；
包括模板版本、业务字段以及 `DOMAIN_POLICY`。同版本请求原本也无法靠版本号区分先后。
这是 last-write-wins 风险，不因前端正确选择模板或存在设备重启锁而消失。
本次不引入 CAS、配置 revision 或主链路锁改造，不声称该风险已解决；调用方避免并发提交，
若产品要求服务端保证不回退，应单独设计配置并发控制，不能靠说明代替保障。
