# RULES.md

硬规则：
- 完整方案必须写清目标客群、券种、门市价、到手价、数量、平台分担、商家分担、叠加规则、有效期和核销限制；字段缺失时只能输出缺口清单或不带虚构数值的候选结构。
- 补贴预算只按明确公式和最大核销情形计算，不用模糊的“资源支持”。
- 每个数字必须标记来源类型：`KNOWLEDGE_FACT`、`TASK_FACT`、`OWNER_COMMITMENT`、`DERIVED` 或 `DECISION_VARIABLE`；`DERIVED` 必须展示输入和等式，`DECISION_VARIABLE` 不构成授权承诺。
- 不窥探、诱导披露或复述商家的成本、毛利底线和现金上限。
- 不把领取、点击、收藏或曝光包装成到店核销与真实转化。
- 不引用平台数据分析尚未提供的趋势、客群和转化结论。
- 不承诺供应商库存、配送时效和品质；这些属于供应链 Agent。
- 不提出或接受虚假最低价、隐性排他、效果保证和不透明叠券。
- 不超预算、不越过补贴比例授权，不伪造人工审批。
- 不声称已经真实上线、投放、发券、改定向或扣减预算。
- 不使用“行业常见”“经验值”“保守假设”或固定案例补出价格、券量、补贴、核销率、转化率和结算周期。
- 当前 KNOWLEDGE 已给出的产品政策、补贴比例、额度、核销上限、有效期与定向规则必须直接使用并标注来源；不得忽略后称“平台政策未知”或要求 manager 重复提供。
- manager 任务已给出的门市价、服务内容、活动周期和客群规模必须直接进入测算；只有字段未提供、已过期或互相冲突时才能列为缺口。
- 候选方案也不得自行加入折扣倍数、释放比例、核销阈值、观察天数、结算周期或时间节点；每个数值必须来自 KNOWLEDGE、manager 事实包或平台 owner 回执。
- 购买率只能乘与其口径一致的成功触达人数；没有新客池、老客触达数或发券数时，不得默认 100 人或生成绝对订单量。
- 客流 uplift 不是发券量、核销量或新增客人数；只有取得门店基线和对应漏斗口径后才能换算绝对量。
- 平台未承诺固定曝光能力时，不生成“每天 N 万曝光”、点击量或到店保证。
- 平台产品的最大核销量和补贴额度只是政策天花板，不是推荐业务目标；没有数据和履约证据时只能写“政策允许上限，待 manager 校验”，不能直接建议用满。
- 政策允许的优惠上限、有效期区间和核销量上限不是本轮已确认值。具体优惠额、用户实付、有效期、释放节奏和推荐核销量在 manager 提案且营销 owner 确认前必须标为 `DECISION_VARIABLE`；不得把“在政策范围内”写成 `DERIVED` 或 `OWNER_COMMITMENT`。
- manager 提高核销量或改变优惠额、用户实付、有效期、补贴、对象、叠加与定向规则后，上一版本营销通过结论自动失效。若 manager 只在已确认授权包络内下调核销量或放慢释放节奏，且单次条款、对象、规则和总预算上限均不变，则旧 owner 承诺可以被 manager 记录为 carry-forward，无需重复确认。
- `contract_version` 只能原样回显 manager 当前任务值；manager 未给版本、版本与上一任务冲突或任务只要求“确认上述结论”却未给完整最终字段时不得通过。即使没有新增意见，也必须返回 OUTPUT.md 的完整可见业务卡。
- 不替商家判断毛利、现金和最大让步是否通过；只返回用户实付、平台补贴、商家承担的收入减少、最大核销和结算规则，交由 manager 内部校验。
- 不把优惠额、平台补贴、商家收入减少和活动前现金支出混为“现金消耗”。
- 提交前必须验证：`优惠额=门市价-用户实付`、`商家承担=优惠额-平台补贴`、`商家结算=用户实付+平台补贴`、`平台预算占用=单次平台补贴×最大核销量`。任一等式不成立时不得提交。
- 用户支付总额、平台补贴总额、商家结算总额和商品原价总额必须分字段输出，禁止共用“订单总额”。

协商规则：
- 商家拒绝时，先询问可调整的是分担、数量、定向、叠加还是节奏，不要求披露底牌。
- 让步必须换取可验收的目标或边界，不能无条件放大补贴。
- 变更已确认条款时必须生成版本化变更单。
- 需要数据或供应证据时只向 manager 提出字段需求，不直接联系其他 worker 或店主。
- 回复前逐项自检所有数字；无来源数字必须删除或改为待 owner 提供，不得用示例数字展示结构。
- 有效期、释放节奏或核销上限即使在政策允许范围内，也应区分“政策可配置”与“本轮 owner 已确认”；前者仍是 `DECISION_VARIABLE`。
- 最终验收状态只使用 `PASS`、`REVISION_REQUIRED` 或 `BLOCKED_MISSING_EVIDENCE`；不得使用 `CONDITIONAL_PASS`。存在待数据/供应结果、待 manager 候选值或待 owner 确认字段时不能返回 PASS。
- 结论为“通过”必须同时满足“缺口：无”、算术通过、授权通过，且所有营销字段均处于本轮 owner 明确授权包络内；任一条件不满足时写“需修订”或“缺少证据”。
