# 任务副屏跨产品复用

## Summary

用户在新旧产品中都能查看和操作同一任务副屏，不必为了任务切换产品。任务副屏及其恢复、切换和导航规则只有一份实现，避免后续两套功能独立演进。

## Motivation

用户仍习惯使用旧产品，但当前完整任务副屏依赖新产品。用户已确认参照自定义协作群副屏的复用方式，并由任务模块持有共享能力；还要求保留卡片调起和进入会话主动恢复两种体验，包括卡片不在当前历史分页时的恢复。

## User Stories

- 作为旧产品用户，我希望直接查看任务进展、节点和产物，并跳到相关会话，无需进入新产品。
- 作为回到历史会话的用户，我希望任务卡片不在当前页时仍能恢复副屏，且不影响聊天消息加载。
- 作为维护者，我希望修改一次任务规则和副屏功能即可覆盖两个产品。

## Acceptance Criteria

- [ ] AC01：当两个产品打开同一任务时，用户能看到一致的总览、执行图、节点详情、轨迹和产物；可用操作保持现有语义。
- [ ] AC02：当会话卡片调起副屏时，任务正确打开；重复触发同一任务不生成重复页签或重复轮询。
- [ ] AC03：当进入会话且任务声明不在当前消息分页时，恢复流程仍能发现并打开任务；查找不要求用户翻页，不重新执行历史卡片代码，也不将查找结果灌入聊天消息列表。
- [ ] AC04：当用户已经选择一个任务时，晚到的自动恢复和历史消息不得切换当前任务；显式打开优先于自动恢复。
- [ ] AC05：当一个会话关联多个任务时，切换范围保持该会话关联口径，默认恢复至多打开一个任务，各任务的选中和下钻状态互不串场。
- [ ] AC06：当用户选中节点、下钻、返回总览或返回原会话时，两个产品都保持现有语义；应跳转时打开正确会话并尝试定位消息，不应跳转时不产生导航。
- [ ] AC07：当任务驱动跨会话导航时，副屏实例和当前任务状态保留；普通会话切换、关闭或退出登录后，旧恢复和旧导航不得继续生效。
- [ ] AC08：当用户预览或下载产物时，已有支持的文件来源和展示类型继续可用；查看人与任务归属人不混用，无权限、失效和不存在均有明确反馈。
- [ ] AC09：当资源加载失败、接口版本不兼容或恢复查找暂未完成时，界面给出可诊断的状态及重试或继续入口，不静默伪装为“没有任务”。
- [ ] AC10：当发布或回滚副屏版本时，两种产品可使用同一批准版本；不要求维护第二份副屏实现，不允许会话消息指定任意远程代码地址。
- [ ] AC11：当用户操作副屏后继续发消息时，既有交互上下文仍被正确带入，不仅停留在前端日志中。
- [ ] AC12：本次改动不改变任务创建、澄清、执行、上报、派发和验收的既有协议及状态推进。
- [ ] AC13：正式构建的两个产品仅经同一已认证的 `GET /api/v1/collaboration/tasks/manifest` 获取副屏资源；登录用户通过同路径 `POST` 创建或完整替换当前服务端环境的配置，不要求运营权限；刷新页面即可使用新版本，无需重建宿主。不增加 OpenAPI 镜像接口。本地开发直接读取本机构建的 UMD/CSS，不请求 manifest。

## In Scope

共享副屏、声明识别、任务数据派生、恢复和任务切换编排；新旧产品接入；版本化资产构建与交付准备；单一任务资源清单与既有系统配置写入接入；回归与接入验证。

## Out of Scope

重做任务创建或澄清体验；迁移整个任务管理页面；改变任务执行协议；建设通用微前端平台；未经授权的生产发布。

## Open Questions

- **已解决（2026-11-11）**：用户明确旧产品界面以 `open-claw` 仓库为权威源，适配层在那里修改；此前引用的 OCB checkout 仅作历史调研上下文。统一 ownership memory 已更新。
- **评审决策**：批准先复用已有会话关联查询，未命中再走历史声明分页查找，最终保留任务列表兜底；所有结果经一个控制器提交，禁止三条流程竞争打开。
- **评审决策**：历史查找单批最多读取 20 页、每页不超过 50 条；达到预算显示“尚未查完”并可继续，不将其当作查无结果。该数值是待批准的保护预算，不是已经存在的产品规则。
