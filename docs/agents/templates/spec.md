# Change specification template

## Record

Record the problem, scope, acceptance criteria, decisions, baseline, tasks, validation and delivery status. Link the resulting durable knowledge and unresolved gaps.

## Do not record

Do not rewrite previous evidence, equate checked tasks with deployment, or copy the whole spec into permanent documentation. Existing adopted contracts remain authoritative until replaced.

## Ownership and verification

Name the owning module and link the applicable contract, source, tests and version. Mark unresolved claims and verification gaps.
